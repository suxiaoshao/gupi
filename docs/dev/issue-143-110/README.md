## #110 D1：临时装饰是有效来源的投影

### 在真实对话上下文中评审

样张展示完整主窗口：会话侧栏、左侧对话与现有引用附件/评论 Popup、右侧当前会话的 Git 工作区标签、差异正文与文件来源列表。点击输入框上方既有引用，在左侧编辑评论，同时观察右侧当前单侧源行高亮；保存/取消/Escape 后清除。模拟同路径从未暂存改动换到暂存区，会改变右侧来源而保留左侧快照和评论，用于明确 owner 失效的可见结果。

这里只新增装饰行为，窗口分区和评论入口沿用现状；不把引用移入输入正文，不新增回跳或批注入口。正文内引用属于 #104/#109。Git 示例说明来源身份，轮次 Diff 仍须通过相同契约接入。

### 公开能力与现有缺口

锁定的 `gpui-component 0.9.0` 提供 [`Diff::decorations`](https://github.com/longbridge/gpui-kit/blob/v0.9.0/crates/component/src/diff/mod.rs) 和 [`DiffDecoration`](https://github.com/longbridge/gpui-kit/blob/v0.9.0/crates/component/src/diff/decoration.rs)，接收 `DiffLineRange(path, side, start, end)`，行号为 1-based、闭区间。装饰仅改变行背景，不修改选择、复制和布局；选择背景优先于装饰。使用 Kit 默认半透明 warning 背景，与当前引用高亮语义一致，不新增主题选项。

当前 `quote/highlight.rs::Source` 只有 Message/File；`quote/toolbar.rs::Target::Diff::source` 和 `quote.rs::diff_body` 的菜单入口都没有 Diff source，键盘 `workspace_quote` 也只返回 Selection。`messages/diff.rs::DiffBlock` 保留真实 DiffState，`update` 会在数据改变时调用 `set_files`，工作区 Git 则会创建新的 Comparison block。需要补齐应用的来源记录与投影，不能用 `set_selected_lines` 假装高亮。

### 来源契约

临时来源至少同时绑定：

- 会话 key/binding 与真实来源 owner：区别工作区 Git 的 staged/unstaged/untracked、轮次改动及同路径的不同 operation；owner 存活期内保持身份，释放后失效。
- 对应 DiffState 的弱身份，以及 **权威数据 revision**。目前公开 DiffState 没有供应用使用的统一数据 revision，不可把 `cx.notify` 次数当版本；由拥有数据的 `DiffBlock`/来源 owner 在实际替换文件数据时推进版本，并在替换/释放时失效。等值来源复用不因焦点、模式、换行、展开、选择等展示更新推进版本。
- 从当前 `selected_lines()` 捕获的准确 Diff path、单侧 `DiffSide`、归一化行范围。装饰 path 必须是 Diff 数据模型的 key，不能把附件显示路径或绝对路径直接替换进去。

引用的文本与这些临时字段在同一次捕获中取得，继承已有 `quote_allowed` 和会话 binding 校验。只接受 `side == end_side`；不从 `selected_text` 搜索或推算行号。来源信息只存在于 `Attachments.sources` 等会话展示状态中，不写进 `QuoteAttachment`、`DraftFile`、历史或 Pi 请求。

### 统一入口与渲染

1. 指针选区工具条、Diff 右键菜单与键盘引用共用一次 selection/source 捕获，避免其中一个入口只能保存文本却无法高亮。复用已有 `diff_selection` 的单侧检查，同时返回同源的临时记录。
2. 接入现有 `Attachments::open / Editing / discard / paint_source` 生命周期。编辑某条评论时只有一个 active source；原有 Message/File 高亮行为保持。
3. `DiffBlock` 的正式 renderer 在每次构造 `Diff` 时，拿到匹配 owner + DiffState + revision 的当前 active range，调用 `.decorations(...)`；无匹配则传空集合。所有已支持引用的 Diff 展示入口都使用同一投影，包括工作区完整阅读器与有界操作 diff。用小型 Gupi 私有来源记录维护数据身份属于应用职责，不向 Kit 塞领域信息。
4. 装饰变化只请求该来源的正常重绘，不调用 `set_files`、`set_selected_lines` 或滚动定位 API。不要在 `render` 中重建 DiffState，不干扰现有选区恢复路径。

### 生命周期与失效

| 事件 | 高亮与评论 |
| --- | --- |
| 编辑现有引用评论 | 来源有效且当前可见时，显示该单侧行范围；评论框使用现有 Popup/InputGroup/Textarea |
| 保存、取消、Escape、移除引用或其他现有编辑结束路径 | 清空装饰；评论保存/弃稿按既有入口执行 |
| 同源切换统一/分栏、折叠、软换行 | 范围仍是来源行坐标；不重新选区、展开或滚动。Kit 只画当前渲染的相关行 |
| 来源视图暂时不可见 | 不画高亮、不自动切页；同一个仍有效的 live owner 再可见且仍在编辑时才可继续投影 |
| 内容变化、旧 owner 释放、同路径换来源、会话 binding 失效 | 永久丢弃该临时 source，清除高亮；保留引用文本快照及评论编辑内容，不错误迁移到新数据 |
| 重启或草稿恢复 | 没有临时 source，仍可编辑引用评论，但不恢复高亮 |

“重新显示仍存活的来源”不产生回跳功能，也不重新寻找已释放来源。失效不新增通知或用户设置。网页“模拟数据更新/来源切换”的说明只服务评审，不进入产品。

## Kit 不支持的部分

`DiffDecoration` 能绘制跨侧范围，不代表当前来源捕获能提供可靠的跨侧引用。#107/#108 所需的字符/跨侧来源范围、统一可见几何及 viewport anchors 仍不能假设已具备。本设计不调用私有布局、不猜字符位置、不复制 Kit 选择模型，也不把 D1 扩展成 #111 的 gutter marker 方案。

新增测试要防止以下可见产品失败：

| 测试入口 | 防止的失败与应观察的结果 |

| 正式 SettingsView → 包 → 浏览，注入分页 registry 数据 | 实际滚轮滚到长结果底部后搜索框和分页仍处于视口，最后一项可见；分页按钮可点击并显示新页，非手工复刻布局的 harness |

| 两标签分别选择包，窄窗返回再恢复宽窗 | 选择、列表位置、浏览页码与分栏状态不丢；详情正文滚动不挤走操作条；普通设置页仍可整页滚动 |
| 两标签的正式移除按钮 → 取消/Escape/确认 | 入口和确认均为危险变体；取消不移除，确认才执行已有 remove；成功后已安装失效选择清除、浏览改为安装态；切 scope 后旧确认不得误删新目标 |
| 正式项目/继承/delta 资源入口与“打开所属包” | 选择正确来源身份，继承/delta 的移除/启停限制不丢，入口打开新详情而非写无效展开状态 |
| 正式 Git/轮次 Diff 单侧选行 → 工具条/菜单/键盘引用 → 编辑评论 | 仅相应 path、side、行范围出现装饰；同名路径的其他来源不亮；复制所得文本和选区在高亮前后不变 |
| 上述评论编辑中保存/取消/删除引用 | 画面高亮消失；引用评论结果符合既有操作 |
| 编辑中通过真实来源更新入口替换 diff、换同路径 owner 或切会话 | 旧高亮清除且不投影到新数据，引用快照与未提交评论不丢；纯模式/软换行变化不误判成数据失效 |

测试检查正式组件的可见几何、渲染结果与用户命令输出，不仅断言私有 `Option`/revision 数值，不在测试里重写 decoration 的范围逻辑。纯行背景还需原生画面观察；网页验收不能替代 GPUI 绘制、选区和剪贴板验证。
