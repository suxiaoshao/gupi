# 查看本轮 agent 的文件改动（[Gupi #33](https://github.com/suxiaoshao/gupi/issues/33)）

状态：计划已确认，待实现。

## 目标与范围

在每次回复下方汇总这一轮里 agent 通过编辑工具改过的文件，并用 GPUI Kit 的只读差异组件查看改动。

分两个提交交付：

1. **依赖升级**：GPUI Kit 升级到 0.7.3 及配套依赖，处理破坏性变更，评估能否用官方组件替换自写实现。
2. **改动查看**：本轮已更改文件入口、审阅面板，以及工具详情改用差异组件。

不做：整轮合并后的净差异、bash 等非编辑工具造成的改动、工作目录快照或文件系统重建、回滚和提交操作。

## 依据

- Pi（`2688aba7d`）不提供文件基线或整轮净改动，也没有快照或检查点接口。`edit` 工具结果的 `details.patch` 是标准补丁（`details.diff` 仅供展示）；`write` 工具结果没有 `details`，只有参数中的路径和新内容，无法得知原内容或是否新建。Gupi 事后也无法补回 `write` 的基线。`edit` 与 `write` 都在写盘完成后才检查取消，取消或出错的结果仍可能对应一次实际写入。
- 扩展通过 `ctx.executeTool` 发起的嵌套调用不会作为独立工具调用出现在会话中，父调用结果只保留有限的状态与参数记录，不含补丁（`core/extensions/types.ts`、`nested-tool-calls.ts`）。
- 参考产品：
  - Zed 的原生 agent 由各编辑工具写入变更日志，文件首次被 agent 修改时记录基线，用户的中途编辑并入基线；改动按整个对话累计，直到用户保留或撤销。每次工具调用另有内联差异。外部 agent 在工具调用中自带原文与新文。
  - ChatGPT 桌面应用（Codex）：解包其前端可见，每个文件改动条目（`fileChange`）自带补丁，整轮差异由 Codex 后台推送（`turn/diff/updated`），前端只按轮保存显示；随附的 Codex 程序中也有该通知。后台如何计算未在本地核对。
  - 两者的整轮净差异都由上游提供基线；Pi 没有对应契约，Gupi 只能如实呈现每次操作。
- Gupi 保存工具参数与结果，持久化结果替换实时输出，当前会话与历史会话使用同一投影（`crates/gupi-conversation-ui/src/home/messages/activity.rs`）。但配对只在单个 Run 内进行：工具调用与其结果之间若插入用户消息，两者落在不同 Run，结果一侧成为缺少参数的孤立条目；工具详情按 ID 查找时取第一个匹配，可能选中不完整的一半（`.../messages/details.rs`）。工具详情已优先显示 `edit` 的 `details.patch`，回退到旧的 `details.diff`，并显示 `write` 的内容（`.../messages/tool_details.rs`）。
- 界面中的一组回复（Run）按用户消息、压缩和分支摘要切分；中途插话会产生多段，它不是 Pi 的稳定轮次标识（`.../home/messages.rs`）。
- GPUI Kit 0.7.3 的只读差异组件：`DiffFile::parse(patch)` 解析补丁，`DiffState` 由所有者持有，渲染时构建 `Diff`，需要有界视口；`DiffFile::unchanged(path, content)` 可中性展示整份内容。组件负责渲染、选择与虚拟化，不合并多次补丁；同一 `DiffState` 内按文件路径标识，重复路径以第一个为准，选择、导航和复制都会落到第一个文件上。

### 变更与需要的修改

- GPUI Kit 0.7.2 的发布提交（`c6193700`）只挑选兼容改动，明确排除 main 上的破坏性改动（`ResizeHandle` 签名、`Folder` 标签变体、测试 trait 要求、Easing 和 WebView 迁移）；0.7.3（`67265a36`）只在 0.7.2 上更新 GPUI 运行时到 0.3.9，声明无公开接口变化。仓库中的 `release-notes.md` 停留在 0.7.0，以发布提交说明为准。
- GPUI 运行时对应 Zed `279fe07` → `93d7456`：新增显示器追踪与刷新率接口，修复长 `uniform_list` 布局和 macOS 27 模糊背景。`paint_surface` 参数改为 `CFRetained<CVPixelBuffer>`，Gupi 没有调用方或自定义平台实现，无需迁移。
- 按源码核对，Gupi 不需要迁移 Rust 调用，只改各 manifest 的版本声明、`Cargo.lock` 和五个共享服务的 revision。
- 其他依赖为修复与兼容扩展：Tokio 弃用的 `AsyncFd` 构造函数 Gupi 未使用；`toml` 调整了编码表键的序列化，由现有设置与配置往返测试覆盖；`tray-icon` 只改 Linux（Gupi 托盘只在 macOS / Windows 启用）；`tauri-bundler` 扩展了 NSIS 降级检查，属于发行验证范围。
- 可见变化：文本视图的默认排版调整（段落间距 1rem → 0.75rem，标题随正文字号缩放），Markdown 回复的观感会略有不同。

### 官方组件替换评估

| 自写实现 | 结论 | 理由 |
| --- | --- | --- |
| 工具详情中的补丁代码块 | 替换（第二个提交） | 改用官方差异组件，与审阅面板共用 |
| `gpui-lucide` | 不替换 | 官方 `SvgIcon` 只在本地未合并分支上，0.7.3 与上游 main 都没有；官方 `IconName` 也不覆盖完整图标目录 |
| `gpui-tokio` | 不替换 | GPUI Kit 没有 Tokio 桥接；Zed 的 `gpui_tokio` 依赖其自身运行时 crate |
| 复制按钮（`CopyAction`） | 不替换 | Gupi 会回读剪贴板确认并报告失败，官方 `Clipboard` 直接标记成功 |
| Markdown 适配、输入框封装、设置表单与布局 | 不替换 | 已组合官方组件，其余是应用自身的流式身份、查找投影和表单所有权 |
| 面板布局与拖拽调整 | 不替换 | 新的可调整面板接口只在 main 上，现有实现已使用官方 `resize_handle` |
| 历史画布的提示计时器 | 不替换 | 官方提示需要稳定的命中区域，虚拟画布没有，不能直接替换 |
| `window-ext`、截图显示器快照 | 不替换 | 新的显示器事件可用于失效通知，但不提供 xcap 标识、模式像素和覆盖层生命周期 |

## 二、改动查看

### 范围与入口

- 以界面中一次可见回复为一轮；遇到中途插话或压缩不跨段合并。
- 先在整个当前会话分支内按工具调用 ID 配对调用与结果，再把操作归到调用所在的 Run；结果落在后续 Run 时不重复计入，也不因中间插入了用户消息而视为缺少参数。工具详情使用同一配对。
- 只统计顶层 `edit` / `write`。扩展嵌套调用没有补丁记录，本次不纳入。
- 列表含义是“本轮记录到的编辑操作”，不是磁盘改动的完整清单，文案不暗示整体或当前文件差异。
- 回复下方显示“已编辑文件 · N”，位于折叠的过程区之外。点击打开审阅面板：左侧为文件列表，右侧按时间顺序列出该文件在本轮的每次 `edit` / `write`。

### 内容

- 每个文件一项，按工具调用 ID 去重，操作按时间排列。文件按路径的字面规范化归组：去掉 `./`，位于会话目录下的绝对路径转为相对路径，其余保持原样，不访问磁盘；无法规范到同一形式的别名分开列出。路径以参数为准，缺少参数的 `edit` 从补丁头取路径；缺少参数的 `write` 无法识别文件，不列出。多次 `edit` 各自保留补丁，不拼接成一份（中间基线不同，拼接会误导）。
- `edit`：用差异组件显示 `details.patch`，并显示该次补丁的 `+a −b`。文件级别不汇总行数，文件行显示操作次数。
- `write`：显示为“写入内容”，用中性方式展示整份内容，没有增删统计；不标为“新建”，也不画成全部新增。
- 只有参数而失败、取消或未完成的调用不列出，但这不代表磁盘未改动；它们仍可在现有工具详情中查看。结果带有补丁的失败调用列出并标明错误状态。
- 旧格式或无法解析的补丁回退为纯文本。

### 工具详情

现有工具详情对话框中的 `edit` 补丁改用同一个差异视图，与审阅面板共用；对话中的工具标记保持紧凑。

### 交互

- 入口与面板支持键盘操作，Escape 关闭并把焦点还给入口；文案本地化。
- 回复仍在进行时，面板随新操作更新，已有操作的滚动和选择保持不变。切换会话或分支时关闭面板，重新打开按当前数据重建；迟到的结果不会写入其他会话的面板。

### 归属

改动列表是 `gupi-conversation-ui` 中由会话级工具配对派生的投影，不新增持久化。补丁在数据变化或打开面板时解析，不在渲染中解析（当前 `RunContent::project` 在渲染时调用，改动列表不沿用这一做法）。每次操作一个 `DiffState`，按会话、Run 与工具调用 ID 保留，放在有界视口中；不伪造路径来绕开组件的路径标识。

## 验证

- 依赖升级提交：`cargo fmt --all -- --check`；`gupi` 及受影响 crate 的 `cargo check`、`cargo test`、`cargo clippy --all-targets -- -D warnings`（`--locked`），包括 `xtask`、`gupi-updates` 的 Objective-C 构建，以及需要 `bundled` 特性的 `gupi-update-helper`（普通全目标检查不会启用该特性）；确认 `Cargo.lock` 中只有一套 GPUI 运行时；推送后由 CI 取得 Windows / Linux 结果。原生试用：Markdown 排版、文本选择/复制/查找、输入框自动增高与右键菜单焦点、设置页焦点环、托盘、截图多屏与临时窗口。Windows 安装包降级行为属于发行验证，不在本次本地验证范围。
- 改动查看提交的自动测试：
  - 调用与结果之间插入用户消息时，`edit` 与 `write` 在实时、持久化、重新加载后都归到调用所在 Run 且不重复；调用确实缺失（压缩）时的孤立结果。
  - 同一文件多次操作时，选中和复制第二次 `edit` 的内容正确。
  - 路径归组：相对与绝对别名、Windows 盘符路径、含空格路径；可解析的孤立 `edit` 与孤立 `write`；补丁解析失败回退为纯文本。
  - 取消/出错且无补丁的调用不列出；成功的 `write` 中性展示。
- 原生试用：真实会话中的入口、审阅面板（进行中更新、键盘与 Escape）、工具详情，以及历史会话。
