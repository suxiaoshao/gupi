## 状态与生命周期

1. 设置视图拥有页面内搜索、详情选择和滚动；同一页面刷新不重新创建输入实体。视图关闭后，目录查询不应反向保活窗口。
2. 目录查询由资源能力提供异步只读服务，加载状态绑定查询/分页或包身份；迟到响应不得替换当前选择。避免每个 render 启动请求。
3. 本地资源 owner 继续拥有安装、更新和移除。浏览页和已安装页投影同一操作状态，防止从不同入口重复提交。
4. 延续保存后的 Pi 命令检查、配置/资源操作互斥及操作后回读。搜索失败不禁用仍然可用的本地管理功能。
5. 快捷键值仍来自已提交配置；录制稿由编辑视图持有。取消、失焦、切页和写入失败的行为需按[快捷键方案](shortcuts.md)明确，不能让界面草稿伪装成已保存值。

### 有界页面主体所需的上游改动

最小改动在 `gpui-component` 的 `setting/page.rs`（与锁定的 0.7.1 及本地 `suxiaoshao/gpui-kit` 当前源码一致）：

- `SettingPage` 新增 `content: Option<Rc<dyn Fn(&mut Window, &mut App) -> AnyElement>>` 与构建方法 `content(F)`。
- 设置了 `content` 的页面在标题区下方渲染 `div().p_4().flex_1().min_h_0().w_full().child(content(window, cx))`，不再渲染组列表；页面的组仍提供搜索关键字与侧栏入口，因此搜索过滤无需改动。
- 约 30 行，不改变现有页面行为。

应用侧随之只需：包页面调用 `.content(...)` 渲染 `render_page(Kind::Extension, Section::Packages)`，并把挂载方式改为 `Mount::Bounded`。

## 包操作状态

- 按钮和点击入口共用可用性判断：本地资源目录可用、资源 owner 与配置空闲、当前 Pi 探测就绪，才能执行包操作。无缓存的扫描失败不影响在线浏览，但禁止安装，并在详情显示本地信息不可用、刷新指引及扫描错误。
- 删除视图中的 `pending_package`。资源 owner 的 mutation 运行态同时持有 `Change` 和实际任务；按钮 loading 从运行态匹配来源与动作，结束或取消后自然消失，移除不会让更新按钮转圈。
- 本地扫描继续使用 `gpui-operation::refresh`；mutation 使用仅含 Idle/Running 的任务状态，避免锁定版 operation 不暴露运行任务请求信息而引入镜像状态。完成事件携带实际 Change，视图只为包操作记录每包历史结果，结果历史不参与 loading 判断。
- 验证（macOS、Nix）：47 项 Gupi 测试、13 项资源测试通过；新增覆盖无目录拒绝执行、包与动作匹配、停止后清除 loading。对应两包全 targets/features 的 Clippy、格式和九种语言键一致性检查通过。未新增真实 Pi 安装或原生窗口人工试用。
