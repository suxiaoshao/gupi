# 首批实施方案

状态：已实现，等待协调者验证。用户已确认按协调者推荐的首批范围、按页保存与手动重连方式实施，并要求 Gupi 提供明确的“信任项目…”操作，由设计师开发。本文是当前实施依据；研究清单和早期备选不扩大本期范围。

## 交付范围

在现有设置页面内增加 Gupi / Pi 分区切换。Gupi 偏好保持现有行为；Pi 区域使用连接、对话、网络、包、Skills、模板六个入口。

- 连接：保留可执行文件路径、状态、检查及独立保存，数据仍属 Gupi。
- 对话：默认模型和思考；自动压缩及两个 token 参数；插话和排队消息模式；图片缩放和禁止发送图片。
- 网络：Pi HTTP 代理（仅全局）；Agent 自动重试、次数、初始延迟、最大延迟。
- 资源：复用全局包、Skills、模板编辑器，明确显示全局，不实现项目资源编辑。
- 项目：从对应会话或项目入口携带实际 cwd，支持项目覆盖和明确的信任操作。

首批不增加按模型覆盖、模型范围、思考预算、缓存预热、安装遥测、Shell、传输方式、超时、Provider 重试、工具选择、会话目录或终端选项的图形控件。保留已有字段，仍可打开配置文件编辑。

## 保存与继承

- 对话、网络按页保存；布尔字段使用不暗示立即生效的控件。输入和恢复继承先进入页面草稿，Enter 不触发意外的整页保存。
- 恢复继承删除当前作用域的目标叶字段。显式设置成与继承值相同也保留覆盖；用字段菜单中的“设为项目值”表达，不要求切换两次。
- 模型选项同时写入 provider 和 id；读取已有部分覆盖时不自动补齐，删除此选择时删除当前作用域这两个字段。
- 切换页、分区、作用域或离开设置时，有未保存草稿则提供保存、放弃、取消。失败保留草稿，取消保留当前页面。
- 保存进行中禁用重读与放弃；离开请求等待当前保存结束，成功后重新检查剩余草稿，失败则留在当前页面并保留草稿。
- 保存前在锁内重读文件，只修改本页变更叶字段；保留未知字段、其他页面字段及其他来源的改动。
- 同一目标叶字段自读取以来发生外部改变或删除时，拒绝静默覆盖，显示冲突并保留草稿。用户可重新读取后再编辑；不加入强制覆盖按钮。
- 文件不存在时首次保存正常创建，不额外确认；解析错误或无法读取不视为空文件。

## 信任契约

上游 `ProjectTrustStore` 使用 `<agent-dir>/trust.json`，对象键为规范化绝对目录，值为布尔或 null。查找沿当前目录向父目录寻找最近的显式布尔决定。全局 `defaultProjectTrust` 是没有记录时的回退，扩展的 `project_trust` 回答还可优先于记录。

- “信任项目…”只在用户显式操作后，确认当前项目完整路径和实际含义：Pi 可加载项目配置和资源、安装项目包、执行项目扩展。确认按钮为“信任项目”，取消不写入。
- 仅写当前规范化 cwd 的 `true`，不信任父目录、不改变全局默认策略、不顺带修改其他目录的决定。
- 未信任项目可编辑并保存原始配置，但显示尚未被 Pi 采用的状态，并提供信任入口。保存配置不自动信任项目。
- 信任存储读取失败或未知时，不显示“已生效”。磁盘信任记录只能证明存储策略，不等于已运行进程的实时信任状态；扩展覆盖或进程缓存无法确认时如实保留未知，不捏造有效值。
- 信任成功不自动重启已有 Pi；原有会话仍通过手动重新连接采用新的启动上下文。信任确认只修改文件，不立即执行项目扩展。

## 技术边界

### 写入协调

Pi 的 `proper-lockfile` 使用原子创建目录：`settings.json.lock` 和 `trust.json.lock`，而不是 POSIX 文件锁；默认 stale 时间 10 秒、刷新约 5 秒。现有 Gupi `write_atomic` 只保证替换，不提供与 Pi 的互斥。

新增写入路径必须在兼容的目录锁内完成重读、冲突比较和写入，锁失败保留草稿。不得擅自删除其他进程的锁；锁生命周期需覆盖提交，超过 stale 窗口应刷新并检测锁所有权，不能让 Pi 抢走后仍写入。崩溃遗留锁宁可报错重试，不新增自动强删行为。Gupi 现有写同一个 settings.json 的资源路径也要复用这一写入协调，避免应用内部互相覆盖。具体 helper 放在已有合适能力模块，不另造一份 Pi 配置存储。

### 模型查询与版本

本机 `pi --version` 已确认是 1.1.0，研究源码也是 1.1.0。新配置/信任编辑能力首批按 Pi 1.1.0 契约实现；低版本或无法确认版本时保留现有连接与资源能力，新能力明确不可用，不改写不确定格式，不擅自升级用户 Pi。更高版本仍需按能力/格式失败正常报错，不承诺永久兼容。

可以复用既有独立查询实例的生命周期模式，但不得借用用户的活动会话获取模型能力。查询应使用目标作用域、`--no-session`，不发送 prompt，不替用户授予项目信任。未信任项目不得加载其扩展。模型能力未知时保留已存值，不自动写回。

该研究快照的 `set_model` 和 `set_thinking_level` 默认不持久化默认配置；若通过查询实例选择模型后查询等级，必须针对实际支持版本验证这个无副作用契约。不能把旧版本的会话 setter 行为假定相同。全局查询不能意外采用应用 cwd 的项目配置。

### 生效规则

| 字段 | 保存后的承诺 | 已有会话 |
| --- | --- | --- |
| 默认模型、默认思考等级 | 写入启动默认配置 | 保留当前模型和历史记录；Gupi 重连显式传当前模型/思考，不能承诺重连会替换它们 |
| 队列模式 | 写入对应作用域配置 | 新建 Pi 实例启动时读取；设置页不调用会写全局值的即时 setter |
| 压缩和 Agent 重试参数 | 写入对应作用域配置 | 运行时读取进程内 SettingsManager；磁盘修改不会自动刷新，通过用户手动重连重新读取 |
| 图片缩放、禁止发送图片 | 写入对应作用域配置 | Pi 使用进程内设置处理图片；手动重连后读取，保留 Gupi 附件入口现有职责 |
| HTTP 代理 | 写入全局配置 | 启动流程读取，手动重连；不声称改变 Gupi 自身网络请求 |
| 项目信任记录 | 写入当前项目的明确授权 | 不修改正在运行的实例；后续启动仍遵循 Pi 的扩展和信任解析规则 |

页面不添加自动重启或隐式 RPC 同步。沿用已有手动重连入口，文案只说明必要差异，不增加解释面板。

### 目录锁

- 锁身份是锁目录的 dev/inode（Windows 为创建时间）加上 Gupi 最后设置的 mtime。
- 临时文件写入并 fsync 后，在替换前续期并核对所有权。
- 距上次续期已达 10 秒（Pi 的 stale 窗口）或身份不符时放弃写入，草稿保留。
- 释放时只删除仍属于自己的锁；不删除他人的锁。

### 模型查询与思考等级

- 模型列表由专用 `--no-session` 实例的 `get_available_models` 提供，读到后关闭；不调用 `set_model`。
- 思考等级按 Pi 1.1.0 `getSupportedThinkingLevels` 从 `reasoning` 与 `thinkingLevelMap` 计算。
- 2026-10-10 以本机 Pi 1.1.0 和临时 agent-dir 核对：模型列表含 `thinkingLevelMap`（包括 `off: null` 等形态）；查询前后临时 `settings.json` 未变。

### 与原方案的差异

Pi 区域内的侧栏切页由 `Settings` 组件内部处理，应用无法拦截。因此草稿跨页保留，不在切页时询问；切换作用域、切回 Gupi 区域、离开设置时会询问。

### 包页面滚动

- **原因（源码）**：包页面主体原先挂在 `container_query(...).size_full()` 中。`gpui-pre` 0.3.8 的 `container_query` 不由内容决定自身尺寸，而 `Settings` 0.7.1 以 `MinContent` 高度测量页面列表项，因此该项高度接近 0。列表没有可滚动的范围，但包行仍然绘制出来。
- **修复**：主体改为按内容高度布局的普通容器，宽度在布局后测量并保存，仅在宽度变化时重绘；首帧按 640px 估计。没有固定高度，也没有窗口整体滚动。
- **滚动归属**：仍由 `Settings` 页面主体负责（`packages::Mount::Content`）。搜索栏、工具栏与列表一起滚动；仅列表自身滚动仍需上游提供有界槽位，见 issue-3 实施记录。
- 未在 `HEAD` 上做运行时对照。
