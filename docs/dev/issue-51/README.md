# MCP 登录与连接检查（Gupi #51）

状态：方案待评审。

依据：Pi v1.2.0（本地 `/Users/sushao/Documents/code/pi`），路径相对 `packages/coding-agent/src/`。`mcp.json` 的文件编辑（服务增删改、启停、`exposure` / `toolExposure`、项目覆盖）已由 [#48 + #51 文件编辑](../issue-48-51/README.md) 完成。研究记录见 [MCP 配置盘点](../issue-2/mcp-configuration.md)。本文只覆盖 [Gupi #51](https://github.com/suxiaoshao/gupi/issues/51) 的剩余部分。

## 目标与范围

在 **Pi → MCP** 页：

- 对使用 OAuth 的服务登录、登出；
- 用户点击时检查所有服务的连接状态；
- 说明如何让运行中的会话加载更改。

**用户已确认的决定**：

- 登录和登出放在设置页，调用 Pi 官方命令 `pi mcp login` / `pi mcp logout`，不在会话内通过 RPC 执行 `/mcp login`。
- 连接检查只在用户点击时运行，结果标为“上次检查”，不作为实时状态。检查会实际连接所有启用的服务，用户已接受这一点。
- 运行中的会话通过已有的会话菜单 **重新连接** 加载更改；保存时不自动重启会话。
- MCP 凭据只存在 Pi 的全局 `mcp-auth.json`，由 Pi 读写。Gupi 不读取、不解析、不复制该文件，也不新增存储。
- 不发起上游请求，不使用私有桥接或模拟终端按键。

**不在本期**：

- 实时连接状态面板；
- 对运行中的会话即时启停服务或更改暴露；
- 只读展示已存凭据的元数据；
- 清理已删除服务遗留的凭据；
- 第三方扩展替代内置 MCP 时的识别。

供应商 OAuth 登录仍不在 Gupi 中实现，因为 Pi 没有对应的非终端入口（`pi auth` 只有 `check`、`print-api-key`、`print-bearer-token`）。

## 设计

### 1. 调用方式与生命周期

复用认证检查的命令解析与环境约定（`crates/gupi-resources/src/pi_auth/check.rs`）：通过 `pi_rpc::probe::resolve_command_with_env` 解析 Pi，使用当前运行时环境快照（真实的 agent dir、HOME 与环境不变），不经过 shell，Windows 设置 `CREATE_NO_WINDOW`。

- **输出**：stdout 与 stderr 并发读取或丢弃 stderr，按操作设置上限（list 含全部工具名，上限需高于认证检查的 16 KiB），超限视为失败。输出不写日志、不原样显示，不交给调用方。
- **结束与清理**：取消、超时、离开页面或关闭设置窗口时，停止并回收 Gupi 启动的 Pi 进程，以及由它启动的 MCP 服务子进程（`list` 会启动 stdio 服务和配置中的辅助命令）。优先沿用现有运行时的进程生命周期做法；不终止无关进程。读取任务随操作一起结束。
- **工作目录**：项目作用域使用项目文件夹；全局作用域使用不含 `.pi/mcp.json` 的空临时目录，并在整个操作期间保留。全局检查在项目之外运行，使用相对路径的服务结果可能与会话中不同，界面说明这一点。
- **期限**：登录传 `--timeout 300` 作为授权阶段时限，Gupi 外层总期限更长（推荐 420 秒）以包含连接与重连；登出使用短期限（推荐 30 秒）；检查使用 60 秒总期限，超时显示“检查超时，结果不完整”，不显示为全部失败。
- **互斥与作用域**：同一时间只运行一个登录、登出或检查。操作进行中冻结保存、编辑和作用域切换，或在切换时取消；结果带操作代次，过期结果不得落到其他作用域。

### 2. 作用域与可用性

- 页面有未保存修改时，登录、登出与检查都不可用，提示“请先保存或放弃更改”。Pi 读取的是磁盘文件。
- 登录与登出只对 Pi 实际会解析到的定义提供：项目作用域且项目未受信任时，项目行不提供（说明 Pi 会忽略未受信任项目的配置），不自动信任项目。项目覆盖行按已保存的全局定义合并判断，只在项目受信任时成立。
- OAuth 可用性按已保存的有效定义判断：HTTP、无 `auth.provider`、无任何大小写的 `Authorization` 头。检查结果为“需要登录”本身不产生登录入口。
- 界面标明这是 Pi 内置 MCP 的检查与登录；安装了替代内置 MCP 的扩展时，结果不代表该扩展管理的会话。

### 3. 登录与登出

- **入口**：MCP 服务行菜单。
- **登录**：对话框说明“如需登录，Pi 会打开浏览器，请在浏览器中完成”，提供 **取消**；并给出固定的后备说明：未出现浏览器时，取消后在终端运行 `pi mcp login <名称>`。不显示捕获的 URL 或输出。结束后显示通用结果：完成（退出码 0 表示命令完成或已可访问，不表示新存了凭据）、失败（说明凭据可能已保存但连接失败，建议检查连接）、超时或已取消。
- **登出**：确认对话框“登出 MCP 服务 "<名称>"？”，使用 Danger 提交。说明：“删除本机保存的凭据；不会吊销服务端授权，也不会立即断开已运行的会话。重新连接这些会话以刷新连接。”

### 4. 检查连接

- **入口**：MCP 页标题区的 **检查连接** 按钮，作用于当前作用域；运行时显示进度，可取消。
- **解析**：只取白名单字段并校验类型：`name`、`scope`（`global` / `project`）、`enabled`、`state`（全部已列状态的枚举）、工具数量、是否有资源；`errors` 只取是否非空；`note` 只取是否存在。不显示或记录 `transport`（含完整 URL 或命令参数）、`error` 与 `errors` 原文、stderr。JSON 无法解析或类型不符时整体报告“检查失败”。
- **展示**：以独立的“上次检查 <时间>”结果区按作用域与名称列出全部被检查的服务（包含项目页本身不列出的继承全局服务），状态标签为：已连接（工具数）、需要登录、连接失败、未连接（`connecting` / `disconnected` / `closed`）、已停用。只有作用域与名称都匹配时，结果才附到对应的配置行；未出现在结果中的行显示“未检查”，不显示为已连接。`errors` 非空时显示通用的“配置有错误”摘要。`note` 存在时显示固定提示“项目未受信任，Pi 只使用全局配置”。说明文字提示：使用 `auth.provider` 的服务在检查中可能显示需要登录，但会话中可用。
- **失效**：开始登录、登出、保存、重新读取或切换作用域时清除旧结果；检查失败、超时或取消时不保留看似新结果的旧数据。

### 5. 让运行中的会话加载更改

页面说明：“要让已运行的会话完整加载保存的 MCP 配置，请在会话菜单中选择 **重新连接**；新会话自动加载。”复用 `crates/gupi-conversation/src/conversation/reconnect.rs` 的现有流程，不新增重连机制，也不从设置页批量重启会话。不声称外部登录后一定需要重连，或登出后会话一定继续使用旧令牌。

### 6. 文案与本地化

新增文案覆盖九种语言，沿用 [设置文案](../settings-polish/README.md) 的用词：对话框标题写明对象和动作，确认按钮使用动词，检查结果使用“上次检查”。

## 实施顺序

1. `gupi-resources`：`pi mcp login/logout/list --json` 子进程封装、结果枚举与 list 白名单解析，含超时和取消。
2. MCP 页：检查连接按钮与行状态标签。
3. 行菜单登录、登出对话框与操作互斥。
4. 保存、登录、登出后的重新连接提示。
5. 九种语言文案。

## 验证

- 单元测试：list JSON 白名单解析（退出码 1 时的有效 JSON、仅 `errors` 非空、缺字段、类型不符、全部状态、`note`、作用域匹配）；OAuth 可用性与作用域判断（HTTP、`auth.provider`、`Authorization` 大小写、项目覆盖、项目未受信任）；登录与登出退出码映射。不把 Pi 输出原文暴露给调用方。
- 子进程：用临时假 Pi 覆盖成功、失败、超时、取消与输出超限；假 Pi 再启动一个子进程，确认取消和超时后两者都被回收；作用域对应的工作目录正确。
- 界面回归：未保存时入口不可用；未受信任项目行无登录入口；操作互斥且过期结果不落到其他作用域；结果失效规则；未检查行不显示为已连接；登出确认文案。
- 原生：worker 用 `cargo run -p xtask --locked -- gallery ui` 的隔离环境和假 Pi，检查 MCP 页的检查连接、状态标签、登录对话框（含取消）、登出确认与重连提示，浅色与深色各一次。不连接真实 MCP 服务，不发起真实 OAuth，不读取真实 `~/.pi`。
- 检查命令：`cargo fmt --all -- --check`、`cargo clippy --workspace --all-targets --all-features --locked -- -D warnings`、`cargo test --workspace --locked`（隔离 `HOME` 与 Pi 目录）。
