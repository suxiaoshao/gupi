# 截图选区覆盖范围、遮罩、十字光标与多屏冻结（[Gupi #60](https://github.com/suxiaoshao/gupi/issues/60)）

状态：已实现。自动检查与原生试用的实际范围见文末。截图整体设计见 [Gupi #18](../issue-18/README.md)，本文只记录本次改动。

## 目标与范围

一次性交付，不分阶段，包含以下两部分：

1. **选区窗口与外观**：选区窗口完整覆盖目标显示器（含 macOS 菜单栏与 Dock），冻结画面按显示器像素对齐；遮罩改为与主题无关的压暗；选区边框更醒目并显示宽 × 高；选区窗口出现后立即显示十字光标。
2. **多屏冻结**：按下快捷键时冻结所有显示器，每块显示器一个选区窗口，在哪块显示器按下鼠标就截取该屏。

不改：先冻结再选区的时序、单显示器内的矩形选区（不跨屏拼接）、Escape/右键/离开取消、输出与发送流程。不加提示文字、放大镜、标注、原生全屏或实时画面选区。

## 原实现依据

- 选区窗口为 GPUI `WindowKind::PopUp`。`gpui-pre-macos` 即使没有标题栏也为窗口设置 `NSTitledWindowMask | NSFullSizeContentViewWindowMask`，PopUp 另加非激活面板位，类为 `GPUIPanel`（`canBecomeKeyWindow` 为 YES）。带标题样式的窗口被 AppKit 限制在菜单栏下方，窗口顶边下移一个菜单栏高度，冻结画面随之下移，底部超出屏幕。层级 `PopUpMenu`（101）已高于菜单栏与 Dock。
- GPUI 自身只在简易全屏切换时改样式，并注明改样式会让窗口失去键盘窗口与第一响应者，随后用 `makeKeyAndOrderFront` 与 `makeFirstResponder(native_view)` 恢复（`window.rs` 约 649–655 行）。GPUI 视图是 `contentView` 的子视图，即原始窗口句柄中的 `ns_view`。
- Windows 的 PopUp 窗口已以 `WS_EX_TOOLWINDOW | WS_EX_TOPMOST` 创建，本来就是置顶窗口；能否完整盖住任务栏需原生确认。
- 遮罩颜色为 `cx.theme().background.opacity(0.6)`，浅色主题下发白。
- 光标：遮罩根元素已设 `CursorStyle::Crosshair`，但 GPUI 只在窗口悬停时更新光标（`Window::reset_cursor_style`）。macOS 把样式记录在窗口私有状态中，经光标矩形（`reset_cursor_rects`，初值为箭头）生效；Windows 在 `WM_SETCURSOR` 中使用私有的 `current_cursor`。macOS 的“悬停”即窗口为键盘窗口，`reset_cursor_style` 只在绘制结束时调用；选区窗口在隐藏状态下完成首次绘制，成为键盘窗口后没有重绘，记录的样式停在箭头，直到鼠标移动触发重绘。Windows 窗口出现在静止的鼠标下方时尚未悬停，光标保持箭头。
- macOS 的 `App::active_window` 读取 `NSApplication.mainWindow` 而不是 `keyWindow`，非激活面板持有键盘时它可能返回主窗口。
- 冻结只捕获鼠标所在显示器（`platform_ext::app::current_mouse_display_id` + `xcap`），保存原始 RGBA 与 BGRA 预览两份完整像素。`RenderImage::as_bytes` 可读取预览像素。显示器检查只比较 GPUI 标识与逻辑边界，缩放比例或分辨率变化而逻辑边界不变时检测不到。

## 一、选区窗口与外观

### 打开与覆盖整块显示器

选区窗口改为先隐藏创建（`show: false`），配置完成后再显示，避免先出现在错误位置：

1. `open_window` 返回后，在任何窗口/App 更新之外（与 #58 的原生调用边界一致）通过 `NativeWindowHandle` 执行新的 macOS 操作：样式改为无边框（保留非激活面板位），按整块显示器的 `frame`（不是 `visibleFrame`）设置窗口位置。无边框窗口不受菜单栏限制。
2. 显示：`makeKeyAndOrderFront`，再把 GPUI 视图恢复为第一响应者。不激活应用：非激活面板无需激活即可接收键盘输入，而异步完成的应用激活会把光标重置为箭头。句柄额外保留 GPUI 视图以完成这一步。
3. Windows：沿用 #58 的位置设置后显示。不改窗口层级。

窗口尺寸等于显示器逻辑尺寸，冻结画面按显示器的缩放比例与像素一一对应，不额外缩放；裁剪映射沿用按视口比例计算。

### 遮罩与选区样式

- 遮罩改为固定的黑色半透明（约 45% 不透明），不读主题颜色。
- 选区边框改为白色细线外加一圈深色描边，在亮暗画面上都可辨认。
- 拖拽时在选区外侧（优先下方，空间不足时上方/内侧）显示 `宽 × 高`，单位为最终图像的物理像素，与 `crop_rect` 一致。文字、底色等界面尺寸不随应用字号缩放（与现有选区几何约定一致）。

### 十字光标

以选区窗口自有的原生光标覆盖实现，不读写 GPUI 私有状态，生命周期与本次请求一致（选区窗口在请求结束时关闭，不复用）：

- macOS：沿用 GPUI 的光标矩形。选区窗口成为键盘窗口时请求一次重绘，绘制结束时 GPUI 把十字样式写入并刷新光标矩形，鼠标静止也立即生效。曾尝试停用光标矩形并直接设置十字光标，实测光标始终不变，已放弃。
- Windows：对选区窗口子类化（`SetWindowSubclass`），在客户区的 `WM_SETCURSOR` 中始终设置十字光标并返回已处理，其他情况交给原处理；收到 `WM_NCDESTROY` 时移除子类化。显示后立即 `SetCursor(IDC_CROSS)`。这样鼠标静止和后续移动都显示十字，不依赖 GPUI 的光标缓存（它只在有无光标切换时调用 `SetCursor`）。
- 这些操作放在 `window-ext`，经 #58 的生命周期检查，在与其他原生调用相同的边界下执行。

## 二、多屏冻结

### 显示器快照

- 一次枚举 GPUI 显示器与 `xcap` 显示器，按完整标识建立对应关系（macOS 为 `CGDirectDisplayID`；Windows 的 `xcap` 标识为 `u32`，需校验与完整 `HMONITOR` 的对应无歧义，否则按 `DisplayChanged` 结束）。
- 快照为以显示器标识为键的集合，记录 GPUI 逻辑边界、缩放比例、显示模式像素尺寸与旋转。`xcap` 的 `width`/`height` 在 macOS 是逻辑尺寸、在 Windows 是显示模式像素，含义不同，不直接当作像素尺寸：macOS 由显示模式的像素宽高（`xcap` 缩放比例所用的同一来源）得到，Windows 取显示模式像素。比较按键进行，枚举顺序变化不算变化。
- 裁剪与尺寸标签只使用实际捕获图像的尺寸，不使用快照中的数值。
- 捕获完成后、打开窗口前与提交时各检查一次，任何差异或对应失败都以 `DisplayChanged` 结束。

### 冻结与内存

- 先冻结所有显示器，再打开任何选区窗口，保证选区窗口不出现在其他屏的冻结帧中。各显示器在后台并行捕获；任一捕获失败则整个请求以该错误结束，不打开部分屏幕。
- 每屏只保留 GPUI 需要的一份 BGRA 预览（`Arc` 共享，不复制像素），提交时只把选区部分转换回 RGBA 再编码。这减少的是长期保留的 CPU 像素缓冲，不代表捕获过程的峰值内存。

### 选区窗口与请求阶段

- 每块显示器一个选区窗口，均按上文方式隐藏创建、配置后显示；只有鼠标所在显示器的窗口成为键盘窗口，其余窗口只排到前面而不激活（macOS `orderFront` 系列，Windows `SW_SHOWNOACTIVATE`）。
- 请求分为 **打开中 → 选区中 → 结束中**。打开中：所有窗口句柄登记完成、最终焦点确立前，不处理失活取消；任一窗口打开或配置失败，关闭全部已登记窗口并结束请求。结束中：提交后先进入此阶段再关闭窗口，其他窗口的失活或关闭不会取消正在编码的请求。
- 选区从按下鼠标的窗口开始（包括切换键盘窗口的首次点击），拖出该屏时钳制在该屏内，提交只裁剪该屏的冻结帧。

### 取消规则

- Escape、右键在任一选区窗口生效。
- “离开即取消”改为“本次请求的选区窗口都不是活动窗口”：某个选区窗口失去激活时，安排一次检查，在激活切换完成后（不仅是本次 App 更新结束后）逐个查询本次请求窗口的激活状态，不使用 `App::active_window`，不在某个窗口的更新中嵌套更新其他窗口。检查带代次与阶段保护，多次失活合并为一次。点到另一块屏的选区窗口不会取消。

## 实施

1. 选区窗口与外观：`window-ext`（macOS 无边框整屏与第一响应者恢复、选区窗口光标覆盖与恢复，Windows 子类化处理 `WM_SETCURSOR`）→ `gupi-screen-capture`（隐藏创建、配置后显示、遮罩/边框/尺寸标签、结束时恢复光标）。
2. 多屏冻结：`gupi-screen-capture`（显示器快照与对应、全部显示器冻结、单份 BGRA、请求阶段与窗口集合、取消规则）；`window-ext`（不激活显示）。同步更新 [#18 设计](../issue-18/README.md)中“冻结鼠标所在显示器”的描述。

## 验证

- 自动测试：
  - 选区窗口与外观：尺寸标签的像素值与 `crop_rect` 一致；现有选区与裁剪测试保持通过。
  - 多屏冻结（经由正式的请求所有权与动作）：部分窗口打开或配置失败时关闭全部已登记窗口；冻结进行中取消后迟到结果被忽略；提交后关闭窗口不取消编码中的请求；激活在选区窗口之间转移及初始化期间不取消请求；带 `first_mouse` 的真实按下 → 拖动 → 松开事件完成选区；快照在缩放比例或显示模式像素尺寸变化时判定为变化、枚举重排时不判定（含逻辑尺寸、模式像素尺寸与实际捕获尺寸各不相同的 Retina 夹具）；BGRA 裁剪经 PNG 解码后像素正确（R/B 互不相同、含透明度、非零行偏移）。
- 检查：`cargo fmt --all -- --check`；`gupi-screen-capture`、`window-ext`、`gupi` 的 `cargo check`/`test`/`clippy --all-targets -- -D warnings`（`--locked`）；Windows 编译由原生 CI 或 Windows 机器验证。
- macOS 原生（协调者使用 Computer Use；全局快捷键无法由工具触发时由用户试用）：选区窗口覆盖菜单栏与 Dock、画面不偏移、可框选这两处；出现后不点击直接按 Escape 能取消；遮罩压暗；出现即为十字光标（鼠标静止），移动后仍为十字，结束后恢复；尺寸标签；跨屏点击选区与各种取消。
- Windows（用户）：选区窗口是否盖住任务栏；鼠标静止时和移动后分别检查十字光标；多屏与混合缩放。

## 实现与实际验证

- `window-ext` 保留 macOS 的 GPUI 视图句柄，提供隐藏覆盖层配置、恢复第一响应者、不激活显示，以及 Windows 的十字光标安装与恢复。macOS 选区窗口成为键盘窗口时重绘以应用 GPUI 的十字样式；Windows 使用仅属于覆盖层的 `WM_SETCURSOR` 子类回调，在 `WM_NCDESTROY` 中移除。不激活定位仅用于覆盖层，原有窗口定位调用保持原行为。
- 截图请求拥有全部覆盖层，区分打开、选区和结束阶段。失活检查通过下一轮调度中的 16 ms 定时器合并；逐个读取请求窗口的激活状态。提交先进入结束阶段，再清理全部窗口；清理完成前请求保持忙碌，避免重复触发捕获旧覆盖层。结果在窗口移除和光标恢复后交回。
- 全部显示器并行冻结后才创建覆盖层；每屏只保留一份共享 BGRA 缓冲。裁剪只转换所选区域为 RGBA。快照记录完整身份、逻辑边界、缩放、模式像素尺寸和旋转；macOS 模式像素尺寸来自 Core Graphics。遮罩、黑白边框和物理像素尺寸标签按已确认设计实现。
- 句柄获取有一处实现调整：xcap 的 Windows `Monitor` 包含不可跨线程发送的原生句柄，后台任务因此只传完整显示器 ID，各捕获线程内重新枚举并检查该 ID 唯一匹配，完成后按完整快照复核。快照仍一次枚举建立对应；没有添加不安全的 `Send` 实现，也不凭尺寸猜测目标。
- 自动检查通过：`cargo fmt --all -- --check`；对 `gupi-screen-capture`、`window-ext`、`gupi` 的 `cargo check --locked`、`cargo test --locked` 和 `cargo clippy --all-targets --locked -- -D warnings`。测试分别为截图包 10 项、window-ext 5 项、Gupi 89 项，全部通过；`cargo build -p gupi --locked` 通过。
- 截图测试覆盖 BGRA 通道、透明度与非零行偏移的 PNG 输出，Retina 模式与捕获尺寸区分，快照缩放/模式/旋转变化及枚举重排，标识歧义，尺寸标签边界，部分窗口失败后的全部清理，取消后的迟到捕获结果，编码期间关闭窗口，初始化和激活转移，以及真实 `first_mouse` 按下、拖动、松开到 PNG 输出。GPUI 事件测试只替换测试平台无法提供的原生显示器元数据，使用正式请求、绑定和编码路径。
- macOS Computer Use：当前构建在独立 `gupi-ui-gallery` 环境正常启动；设置页确认截图任务启用、来源为截图，截图与临时窗口快捷键已加载。工具发送两个全局快捷键后均未观察到响应，无法完成覆盖层试用。菜单栏/Dock 覆盖与对齐、即时 Escape、静止与移动十字光标、尺寸标签、跨屏选区及取消均未取得原生验证结论，留给用户试用；不能用自动测试替代这些结论。
- Windows 配置代码已实现，本次 macOS 检查不证明 Windows 编译或运行。任务栏覆盖、光标、多屏和混合缩放仍需 Windows 验证。

功能范围没有偏离已确认计划；捕获线程内重新获取原生句柄的原因见上文。原生覆盖层验证因工具无法观察到全局快捷键响应而未完成。
