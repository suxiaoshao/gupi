# Git 与 Diff 阅读器

状态：Zed 参照重设计已实现，实际验证范围与限制见文末。对应 [Gupi #86](https://github.com/suxiaoshao/gupi/issues/86)。

## 决策

扩展现有右侧工作区 Changes 视图，复用文件导航与 GPUI Kit `Diff`，让用户读清修改、定位文件并在外部编辑器继续工作。增加实际 Git 工作区来源，与 Pi 每轮工具记录共用阅读器，始终标明来源。

全程只读。不提供 stage/unstage/revert、commit/push/PR、评论、worktree 管理或终端；不经 Pi `bash` 获取 Git 数据，不写 Pi 会话。遵循 [职责边界](../../gui-boundary.md) 与 GPUI Kit Coding/Design Guides，不升级依赖或另写 diff 绘制器。

### 布局与来源

右侧工作区内是“分组文件导航 + 差异正文”，用一条细分隔线分区，不套卡片。导航头和正文头同高、同基线，工具栏不换行堆成多层。仓库由当前会话 cwd 决定；分支沿用窗口标题栏，不在正文重复。

```text
┌ Git ─────────────────────────────────────────────────────────┐
│ 文件  +18 −6       ↻ ⋯ │ ▾ src/main.rs · 未暂存 ↑ ↓ ↗ ≡ ⋯ │
│ 搜索文件…              ├─────────────────────────────────────┤
│ ▾ 已暂存  1            │ index → 工作树                        │
│   M main.rs  src  +5 −2 │   18 │ 原文                           │
│ ▾ 未暂存  3            │ − 19 │ 旧内容                         │
│   M main.rs  src  +8 −4 │ + 19 │ 新内容                         │
│   D old.rs   src  −…   │       … 展开上下文 …                  │
│   U notes.md     +5    │                                      │
└────────────────────────┴─────────────────────────────────────┘
```

- 固定提供“已暂存”和“未暂存”两个组；未跟踪文件放在未暂存组，用 `U`／“未跟踪”可访问名称明确区分，不另设第三个切换按钮。冲突存在时单独置顶“冲突”，只显示状态，不提供解决操作。空组保留组头及真实零计数，仓库全空时显示一个空态。
- 已暂存比较 HEAD→index，未暂存比较 index→工作树，未跟踪比较空→工作树；未跟踪不冒充 index 中已有文件。无提交仓库沿用读取层空基线语义。组内文件身份仍为 `(来源, 原始路径)`；同一路径两处出现时读取不同版本，不合并统计或正文。
- 文件行保持单行、统一紧凑高度：状态标记、文件名、弱化父目录、右对齐增删数。完整路径/重命名前后路径放 tooltip 和正文头；长路径省略，不增高行。状态同时有图形或字母与可访问名称，不只靠颜色。不可用统计留空，不伪造零。
- 搜索跨组过滤；上一/下一文件在当前可见结果中移动，边界禁用。保留已有 palette/token 等其他界面不动。目录树、排序/分组偏好切换不是本次必要项。
- **与 Zed 的明确差别**：Zed Project Diff 是多文件 multibuffer；本次仍按需阅读一个选中文件，复用现有 navigator 和 Kit Diff，避免把重设计扩大成虚拟编辑器工程。借用其分区、密度、文件头和稳定更新方式，不声称已实现连续多文件阅读。
- 窄区沿用现有导航折叠/返回机制，正文保留“文件列表”入口；正文宽度不足时统一视图，变宽恢复并排偏好。窄宽原因放阅读选项（sliders）按钮的 tooltip 和可访问名称，不放进菜单项文案或常驻工具栏。

### 正文头与操作

正文只有一个固定高度文件头：左侧本文件折叠箭头、路径与来源；右侧依次为上一/下一文件、外部打开、阅读选项（sliders）、文件操作（⋯）、文件列表开关。每个图标按钮均有 tooltip 和可访问名称。比较方向用 Diff 左右版本标签（统一模式用紧凑标签），不再增加重复页面标题、说明段。打开动作仅指当前磁盘文件；缺失时禁用，tooltip 解释，不常驻“打开的是当前文件”一整行。

阅读选项菜单使用 Kit 原生 label/separator/check：在“视图”下列出互斥的“统一／并排”，只勾选实际生效项；在“显示”下列出“字内差异／自动换行／全部未变更行”。窄宽时并排项为普通禁用项，保留偏好并在变宽后恢复；Kit 0.8 不提供禁用菜单项 tooltip，因此原因明确属于 sliders 触发按钮的 tooltip 与可访问名称，不宣称菜单项本身有原因提示。文件操作菜单单独提供“复制文件路径／复制 patch／复制文件全文”，分隔后是“在外部编辑器打开”；不可用项可见但禁用。选区复制沿用 Kit。字内差异默认开启。文件头保留本文件折叠入口；删除单文件阅读界面里的“折叠全部/展开全部”和跨未加载文件的隐式折叠意图。上下文 disclosure 仍就地可见，与文件折叠分开。

二进制、仅改名、删除、空文本、冲突、特殊文件和超限各显示真实内容状态；错误在当前正文区域提供重试，不用空 patch 冒充成功。Pi 记录缺少全文时禁用全文动作，不拿当前磁盘补历史。外部打开和复制保留既有只读边界。

### 第一版“跳动”的原因与当前刷新约束

以下是重设计前 `7762ef4` 的源码结论，不是当前实现，也不声称完成了原生逐帧测量：

1. **确定的周期性几何变化**：`workspace/git_changes.rs::sync_worktree` 每 5 秒调用刷新；`refresh_worktree` 设置 `refreshing=true` 并通知；`render_git_main` 在 `refreshing && !loading` 时向纵向正文插入“刷新中”行（当前约 622 行），完成后移除。即使结果完全不变，正文也会下移再上移。失败信息同样是动态增删行。
2. **无变化也重做更新**：每次清单成功都清掉 `body_task`/`body_error`、递增 `body_generation`、重新构造 rows 并投影选择。已有相同 `Change` 的缓存会保留，故不能说“每次必重建 DiffState”；但未完成的正文请求会被无条件取消再启动。
3. **版本变化时正文消失再出现**：缓存按完整 `Change` 相等保留；当前选中文件变化后缓存移除，旧 DiffBlock 被加载态替换，随后新建阅读模型。内容高度和阅读状态因此可能跳变；这与第 1 条无变化也发生的跳动分开。
4. **排除误判**：Kit 0.8 `list/list.rs::set_selected_index` 明确不滚动，Gupi delegate 也跳过同一选择。因此不能仅凭每次调用它断言列表被滚回顶部。来源行/工具栏 `flex_wrap` 会在窄宽变化时增高，属于另一条布局问题。

改为“后台取新快照 → 比较语义版本 → 原位应用变化”：

- 首次没有真实数据才显示加载态；日常刷新保留清单、正文及固定头高，只在刷新按钮槽位表示进行中。失败保留旧快照并在同槽位标记“未更新”，详情在菜单/tooltip，不能删除内容或挤动正文。
- 无变化不重建 rows、不重设选择、不取消正文任务、不替换 DiffState。改变其他文件只更新对应行；选中文件未变时保留其实体、滚动、选区和折叠。
- 当前文件变更时保留明确标为“正在更新”的旧版本，准备好新正文再原位替换；patch 未变则保留原 DiffBlock。Kit 0.8 不公开 diff 当前视口锚点，故版本实际变化时不保证恢复任意滚动位置；不自动跳到旧选区、不伪造跨版本选区。未变正文精确保留实体、滚动和选择。删除选中项才选邻近实际条目；主动导航才要求滚动到项。
- 一个 Git 标签同时持有分组清单及源限定选择，不再以按钮切换 source 清空缓存。三种读取结果须属于同一仓库/刷新代次，部分失败标在对应组，不能把失败当零项；正文仍延迟读、按版本有界缓存。打开、恢复可见、手动刷新和可见时低频检查继续共用合并任务，隐藏停止。

## 工作区标签拖拽

标签始终留在栏内，维持抓取时尺寸，实时换位；不采用拖拽预览加松手插入的交互。`Tabs` 继续拥有领域 order/active，单个 `strip::Interaction` 保存按下抓取偏移、手势、槽位测量与表现状态，不另建 Entity，不持久化排序或回滚已完成的换位。

- 排序只看未平移的外层 slot wrapper 与冻结宽度／间距：右移的右前沿越过下一项中线、左移的左前沿越过前一项中线后换位，带 1px 小滞回；同次事件可以跨多项。动画位置不参与排序。
- 按下时记住当前可见位置的抓取偏移，`on_drag` 启动时立即消费当前移动坐标。窗口 Capture 处理后续移动与最终松手坐标，统一幂等结束，独立于子元素 Bubble 和 pane resize 路由。Escape、失活、会话切换及标签集合变化同样结束手势，保留实时顺序。
- 普通滚动或可见栏几何变化会安全结束当前手势，不复用旧快照；支持从非零滚动位置开始。可见栏宽小于标签宽时不继续拖动，不扩大栏的夹紧范围。活动标签矩形夹紧在可见栏中，松手后向名义槽位回位。
- 邻居与回位表现使用 Kit `spring` 和主题 `spring_move`，key 包含会话、标签和每次手势的唯一身份；重拖从独立记录的可见姿态开始，名义几何不受上一次 spring 影响。settle 后释放冻结表现状态。
- 浮起层显式继承祖先与可见栏交集的 mask，同时用于 prepaint 命中及 paint，不能只依赖 deferred 的绘制裁剪；邻居、标题栏空白区和其它控件不应被不可见标签截获。

### 投影、折叠与选择

- 复用当前虚拟 `ListState`，投影为 `Group / Directory / File` 三类固定高度行；不再引入第二套 Kit `TreeState`。只从已有 Entry 的原始路径组件构造目录，不扫描磁盘；已删除文件仍能生成其目录。目录身份为 `(组, 原始相对目录)`，叶子沿用 `(来源, 原始路径)`；显示文本不参与身份。各级目录先、文件后，分别按路径稳定排序，不合并单子目录链。
- 每个 Git 标签保留关闭目录集合，默认全部展开；普通刷新、列表／树切换保留该集合，已消失目录剪枝，仓库或 cwd 改变清空。目录与分组只控制投影，不拥有正文。点击或 Enter 切换展开；上下键走可见行，左右键展开／收起或到父节点。目录与分组提供名称、计数、展开状态，文件保留状态名称与既有可访问角色。
- 目录计数为当前搜索匹配的全部后代叶子条目数，不受折叠影响，不跨来源去重。常驻只显示计数；增删合计放 tooltip，且仅在全部后代统计可用时作为完整合计展示，混合未知时说明统计不完整，不把缺失值当零。叶子继续显示自己的增删数。
- 正文选择独立于导航焦点：折叠当前文件祖先不清正文、不取消读取。前后文件只走当前搜索及展开后可见叶子，跳过目录／分组且不循环；当前正文因折叠隐藏时，以完整树顺序中的位置找最近可见前后叶子，不因可见索引缺失就把两按钮都禁用。
- 切换列表／树保留来源限定的文件身份、正文实体、滚动与选区；主动进入树视图时为当前文件展开祖先一次，显示其位置。后台刷新不主动展开或滚动，不变清单不重建投影。

### 搜索与持久化

搜索保持现有完整路径／旧路径匹配：先过滤文件，再构造匹配文件的祖先树。搜索期间临时展开匹配祖先，不修改普通折叠集合；清空搜索恢复原集合。选中资格从匹配的源条目计算，不能从折叠后的可见行反推。搜索、折叠和视图切换均不触发额外 Git 或文件系统读取。

只将视图枚举持久化到现有 `state.toml` 的 `LayoutState`，默认 List；启动沿用同步加载，在首次显示前读取真实偏好。全局 LayoutState 是视图偏好的唯一来源，各窗口只持有投影及目录折叠状态，不另存默认值后异步覆盖。更新现有 capture/save 路径保留该字段，沿用既有保存机制；不新增配置文件、独立写任务，也不持久化过滤词、折叠集合或选择。

## 所有权与数据流

### 读取层：`gupi-resources::git`

复用 #85 的 `discover`、规范化 `Repository` 和私有系统 Git 进程执行边界，增加语义化的“读取改动清单”和“读取指定来源/文件内容”接口。接口返回路径、状态、可用统计与正文结果，不引用 GPUI、`DiffState` 或 Pi 会话。按需拆为 `git/changes.rs`，不公开任意命令执行器。

- Git 通过参数数组、指定 cwd、后台任务执行；沿用取消、超时、stdin 关闭、子进程回收及环境隔离。status 使用稳定的 porcelain/NUL 格式；name-status/numstat 采用 NUL 路径协议，正确处理 rename 双路径、空格、Unicode 和换行，不能按空白分割路径。文件路径参数使用 literal pathspec，避免 `[`、`*`、前导 `-` 改变查询含义。
- 差异读取明确禁用 external diff 与 textconv（`--no-ext-diff --no-textconv`），禁用颜色/pager；不运行用户 diff driver，不刷新或写 index，不读取 ignore 之外的未跟踪全集。未暂存/已暂存分别读取正确的左右版本，已暂存右侧绝不能用当前磁盘内容代替。
- 清单先于正文；大清单、numstat 和正文读取都有明确的容量/时间边界。超过边界返回“部分清单/过大/不可用”状态，UI 显示限制；不能将有限结果宣称全部，也不能先把无界输出收进内存再判断大小。具体容量按代表仓库和 Kit 实测确定，并作为读取策略集中定义。
- 未跟踪文件按需读取，遵守相同大小/编码判断；符号链接按链接对象展示，不跟随链接读取仓库外目标；删除不尝试读取缺失的工作树文件。保留路径身份与展示文本的区别。
- 工作树不是事务快照：清单和正文携带读取代次，正文读取时核对选定条目的源标识/版本；文件变化或消失时作废该条目并刷新，不将不同版本的 metadata、统计和正文拼成一份确定快照。对读取期间再次变化给出可重试状态，不无限追赶修改。

### UI 层：Git 与 Pi Changes 标签

`来源 → 真实文件清单 → 选定文件的真实正文 → 阅读模型 → Kit DiffState`。

Changes 标签拥有来源、查询任务/代次、清单、选中文件、过滤词和阅读偏好。仓库描述由工作区来源持有，按当前 cwd 调用 resources 发现；不依赖标题栏缓存 HEAD，也不为 diff 重复实现 Git 子进程。关闭标签/窗口、切换目标后取消任务，旧结果必须核对标签、来源、路径和代次后才可回写。

Pi 轮次适配器继续消费 `EditedFiles`/`ToolIndex`，保留当前历史路径的 in-scope 判断及无法合成净改动时的逐操作回退。工作区适配器消费 Git 返回值；两者转换成阅读器所需的文件描述/正文类型，不给 `EditedFile` 塞入伪造的 Pi operation ID。来源相关信息留在适配器，共用导航、布局和 DiffBlock。

首次打开没有伪造文件、统计、空 patch 或默认版本：清单成功前是加载态；文件正文成功前是该文件的加载态；仅成功的空清单显示“没有改动”。Git 后台刷新按上节保留旧快照；选择另一个来源/路径时只使用其对应缓存或首次加载态，不能借用别项正文。切换 cwd 必须重新加载。

打开工作区标签、用户刷新、窗口恢复活动时读取；仅可见工作区来源做合并的低频刷新，隐藏/关闭停止。可以用现有 Pi 状态变化触发刷新，但 Git 才是工作区事实来源。正文按源版本缓存并限制保留量；不变正文保留组件实体、滚动和选区，变化后按上节准备并替换，不能先清空当前正文。列表与工具栏从同一已应用的结果计算，不依靠额外重绘修正选择或启用状态。

### Kit Diff 接入

已核对锁定的 Kit 0.8：`DiffState::set_mode`、`set_inline_unit`、`set_context_lines`、`expand_unchanged`/`collapse_unchanged`、`set_file_collapsed`，以及 `Diff::soft_wrap`、文件头组合接口可复用。现有 `DiffBlock::render_reader` 隐藏组件文件头，需要由工作区文件头提供折叠/展开入口并调用状态接口，不能只改一个布尔值而不影响正文。

Kit 只能展开已提供的源行。Git 单文件正文可按需取得受限的完整上下文，再由 Kit 折叠；若使用局部 patch，扩展读取成功前保持加载状态，不能把不存在的上下文画成空行。Pi 记录仅含局部 patch 时标明“记录仅包含这些上下文”，不读取当前磁盘补成过去版本。全文不可用时禁用对应的全文展开/复制操作，保留真实片段和已有回退。

### 读取与保留策略

- 每个 Git 子进程最多 5 秒；stdout 最多 2 MiB、stderr 最多 64 KiB，读取时即限制并在超限/取消时回收子进程。清单最多 5,000 项；超限显示不可用，不将截断结果交给解析器或宣称完整。
- 单侧文本最多 1 MiB、50,000 行、单行 16 KiB；Pi 工作区正文也使用这套文本限制。Git patch 另受 stdout 上限约束。二进制、特殊文件、冲突和超限正文显示状态；外部打开根据真实工作树文件是否可用独立决定。
- Git 标签最多保留 8 个文件正文；Pi 标签最多保留 16 个文件阅读模型，只为当前文件构造正文，逐操作回退每页 3 项。重设计中跨来源选择仍保留有界缓存；未变源版本保留 DiffState。
- 并排模式最小正文宽度为 48rem，以实际 pane allocator 的 `main_width` 判断；窄时采用统一、扩大后恢复并排偏好。重设计改为本文件折叠，不保留跨未加载文件的全局折叠意图。
- Pi 记录没有完整版本时禁用全文上下文/全文复制；无法合成文件净 patch 时不把任意一条操作当作文件级 patch 复制，保留原有逐操作展示与操作自身的复制入口。外部打开仅打开当前磁盘文件，不补齐历史版本。
