# #47 项目资源路径与启停

状态：Done。

依据：Pi v1.2.0（本地 `/Users/sushao/Documents/code/pi`，标签 `v1.2.0`），路径相对 `packages/coding-agent/src/`。

## 目标

让用户在 Gupi 里直接编辑决定 Pi 加载哪些资源的 `settings.json` 内容：

1. 顶层 `extensions`、`skills`、`prompts`、`themes` 四个字符串数组，全局和项目作用域都可编辑。
2. 项目作用域下的资源启停开关。

**原则**：与 #49/#50 相同，Gupi 按 JSON 文件原样编辑。条目原样保存，不认识的表达式原样保留，不推断 Pi 实际加载了什么。

## Pi 规则

| 规则 | 依据 |
| --- | --- |
| 四个数组**不做全局与项目合并**：项目数组只作用于项目资源，全局数组只作用于全局资源 | `core/package-manager.ts` `resolve` 约 926–975 行 |
| 普通路径相对 `.pi/`（或 agent-dir）解析，是资源来源；`*`、`?` 只过滤已由普通路径收集到的文件，不单独展开；`!glob` 排除；`+路径` / `-路径` 精确匹配已收集的路径，强制启用或停用 | `splitPatterns` 约 311 行、`applyPatterns` 约 751 行、`resolveLocalEntries` 约 2396 行 |
| 内置扩展条目（如 `-builtin:mcp`）也写在 `extensions` 数组里；项目条目按顺序取最后一条匹配，全局按 `!`、`+`、`-` 的固定优先级 | `resolve` 约 977–990 行、`applyAutoloadDisabledPatterns` 约 799 行 |
| 普通自动加载的包，对象条目里某类型数组缺省表示全部加载，`[]` 表示全部停用 | `collectPackageResources` 约 2220 行、`applyPackageFilter` 约 2293 行 |
| 项目未信任时 Pi 不加载项目设置。Gupi 仍可写文件，沿用 D1 的“未加载（项目未信任）”标记 | 现有 D1 规则 |

## 范围

### 1. 资源路径数组：按文件原样编辑

- **位置**：Pi 设置“工具与环境”页新增分组“资源路径”，四个字段各一行。
- **控件**：有序列表，与 `defaultTools` 的条目标签相同：
  - 可以原样追加一条字符串、删除、上移、下移；
  - 顺序有意义：同名资源按先后决定，项目内置扩展条目也按顺序生效。
- **只看当前作用域的文件**，不复用 Pi 配置页的继承和默认值解析：
  - 项目页只显示项目文件里的数组，不显示全局数组；
  - “没写这个键”“空数组 `[]`”“有内容”三者区分显示；
  - 清空即写 `[]`；行菜单“移除此键”删除键。两者都不叫“继承”或“默认”。
- **保存**：
  - 重复条目和顺序原样保留；不解析、不校验、不预览匹配结果；
  - 不对条目套用 `defaultTools` 的 `+`/`-` 修饰规则；
  - 文件里的值不是字符串数组（例如含非字符串）时，该字段只读并提示“格式不支持”，不改写。
- **冲突单位**：每个数组是一个叶，整组比较，不做元素级合并。

### 2. 项目作用域的资源启停开关

已有全局开关的写法不变（`pi_resources::set_enabled`：去掉同一路径的旧 `+`/`-` 条目，再追加一条）。项目作用域只对两类行提供开关：

| 行 | 写入位置 |
| --- | --- |
| 本项目资源（`.pi/` 下自动发现，或项目数组列出） | 项目 `settings.json` 的对应数组 |
| 项目包内的资源 | 项目包条目（字符串先改为对象，与全局写法相同） |

- 开关写入**项目 controller 与项目 `settings.json`**。现有 `ResourcesView.change` 总是走全局 controller，`ResourceController.change` 拒绝项目 Toggle（`src/features/settings/resources.rs:833-836`、`crates/gupi-resources/src/resources.rs:194-205`），需要改。资源从哪个目录扫描出来，与写到哪个文件分开判断。
- 开关状态沿用现有扫描结果，不新增推断。
- 目标数组或包条目字段的形状不支持时，拒绝写入并提示，不改写。
  - 原因：现有 `strings()` 会丢弃非字符串条目，不能用它来改写。
- 继承的全局资源（独立资源和包内资源）、已有的 `autoload: false` 条目保持只读，与现状一致。

### 3. 两处写同一数组时的一致性

资源页开关和“资源路径”列表会写同一个数组：

- **开关写入后**：Pi 配置页重新读取。
  - 该数组没有未保存的修改：正常更新为磁盘上的新值。
  - 该数组有未保存的修改：**保留它原来的基准**，不重算。这样保存时现有的按叶检查会报“文件已被修改”冲突，不会悄悄覆盖开关写入的内容。
  - 不能直接调用现有的 `reload`：它会把基准推进到磁盘值，冲突就检测不到了（`pi_config.rs:360-405`）。
- **列表保存后**：刷新同一作用域的资源目录。
  - 现有 `follow_scope`/`sync_scope` 只在切换作用域时刷新（`resources.rs:552-566`）。

### 不做

- 内置扩展专用开关：在 `extensions` 列表里直接写 `+builtin:<name>` / `-builtin:<name>` 即可；
- 继承的全局包在项目中的开关（新建 `autoload: false` 条目）、移除已有项目过滤；
- 包过滤数组的原样编辑器；
- 扩展、主题代码编辑；
- 文件选择器、存在性检查、glob 预览；
- 保存后让运行中的会话重新加载：与现有全局开关一致；
- 祖先目录 `.agents/skills`、AGENTS 文件、trust.json 管理。

## 所有权与实施顺序

1. `gupi-resources`：
   - `set_enabled` 可指定项目根；
   - 写入前检查目标字段形状，不支持时返回错误。
2. `src/features/settings/resources`：
   - 项目作用域按上表显示开关，写入项目 controller；
   - 写入后刷新项目目录。
3. `src/features/settings/pi_config`：
   - 四个数组字段和“资源路径”分组；
   - 字段走当前作用域的原样模式；
   - 有未保存修改时保留基准的重读规则。
4. 两个方向的刷新接线。
5. 九种语言文案。

## 验证

**单元测试**：

- 项目资源开关写入项目数组；项目包资源写入项目包条目；
- 继承资源的开关不改动全局文件；
- 形状不支持时拒绝，文件不变；
- 四个数组区分“缺键”“`[]`”“有值”；重复项、顺序、`!`/`+`/`-` 及 `builtin:` 条目往返一致；
- 数组有未保存修改时，开关写入同一数组，之后保存报冲突；
- 数组无修改时，开关写入后列表更新为新值；
- 列表保存后，资源目录刷新。

**原生界面**：worker 用 `script/gupi-ui-gallery` 临时配置，检查两种作用域下的“资源路径”分组和项目开关。不触碰真实 `~/.pi`。

**检查命令**：`cargo fmt --all -- --check`、`cargo clippy -p gupi --all-targets --locked -- -D warnings`，以及受影响包的测试。


## 实现与验证结果

- 四个资源数组接入 ToolsDraft，按当前文件原样编辑；缺键、空数组、重复项和顺序保持独立语义，不支持的形状只读。每个数组仍是一个冲突叶。
- 项目开关通过项目 controller 写入，写入时重新核对项目目录来源并严格检查目标数组；继承资源和 `autoload: false` 条目不提供开关。开关重读保留脏数组的旧基准（包括随后保存其他页时）；列表保存会刷新同作用域目录，正在读取时的刷新请求会排队。
- 自动检查通过：`cargo fmt --all -- --check`、`cargo check -p gupi --locked`、`cargo clippy -p gupi --all-targets --locked -- -D warnings`、`cargo test -p gupi -p gupi-resources -p gupi-settings --locked`（106 / 47 / 21 项）。新增覆盖原样数组往返、单叶冲突、项目/包开关、只读来源与非法形状拒写、脏数组冲突/干净数组更新；挂载设置视图验证真实 controller 路由及列表保存后的目录刷新。九种语言文案键和参数一致性检查通过。
- macOS 原生试验使用 `script/gupi-ui-gallery --no-build --keep` 的临时配置：两种作用域显示、追加、上移/下移、键盘操作、清空为 `[]`、移除此键、格式不支持只读；全局/项目开关后列表自动更新，新增路径保存后目录更新，项目包资源开关及继承行只读。核对临时 JSON 的作用域、包过滤、重复项顺序和未知字段均符合预期；未修改真实 `~/.pi`。
- 范围未扩展；运行中的会话仍需手动刷新。继承包启停和内置扩展专用开关未加入，内置条目可在 `extensions` 原样编辑。
