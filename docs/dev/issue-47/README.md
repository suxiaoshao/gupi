# #47 项目资源路径、启停过滤与包 delta

状态：Draft，待架构师审查与用户确认。

依据：Pi v1.2.0（本地 `/Users/sushao/Documents/code/pi`，标签 `v1.2.0`），路径相对 `packages/coding-agent/src/`。

## 目标

让用户在 Gupi 里直接编辑决定 Pi 加载哪些资源的 `settings.json` 内容：

- 顶层 `extensions`、`skills`、`prompts`、`themes` 四个字符串数组；
- 资源启停，也就是往这些数组或包条目里写 `+路径` / `-路径`；
- 全局包在项目中的 delta 条目（`autoload: false` 的对象）；
- 内置扩展开关（`+builtin:<name>` / `-builtin:<name>`，从 #49 转来）。

**原则**：与 #49/#50 相同，Gupi 按 JSON 文件原样编辑。条目原样保存，不认识的表达式原样保留，不推断 Pi 实际加载了什么，不为体验做额外的解析与预览。

## Pi 规则（决定写到哪里）

| 规则 | 依据 |
| --- | --- |
| 四个数组**不做全局与项目合并**。项目数组只作用于项目资源：项目自动发现的资源（`.pi/extensions`、`.pi/skills` 等）和项目数组列出的路径；全局数组同理只作用于全局资源 | `core/package-manager.ts` `resolve` 约 943–975 行、`addAutoDiscoveredResources` 约 2419 行 |
| 数组条目：普通路径相对 `.pi/`（或 agent-dir）解析并加入资源；`!glob` 排除；`+路径` 强制启用、`-路径` 强制停用，只做精确匹配；`*`、`?` 是 glob | `applyPatterns` 约 751 行、`isEnabledByOverrides` 约 724 行 |
| **项目不能停用继承的全局独立资源**。唯一例外是内置扩展：项目 `extensions` 中针对 `builtin:<name>` 的 `+`/`-`/`!` 条目优先于全局 | `resolve` 约 977–990 行 |
| 内置扩展：`llama.cpp`、`codemode`、`tool-search`、`mcp`，默认启用 | `extensions/index.ts:8-13` |
| 包条目为对象时是过滤器：某类型数组缺省为全部加载，`[]` 为全部停用，否则按模式过滤 | `collectPackageResources` 约 2220 行、`applyPackageFilter` 约 2293 行 |
| 项目里 `autoload: false` 的对象，若全局有同身份的包，就是全局包的 delta：只调整列出资源的启停，本身不安装；两条都保留 | `dedupePackages` 约 1748 行、`findAutoloadDeltaBase` 约 1356 行、`applyPackageDeltaFilter` |
| 项目未信任时 Pi 不加载项目设置。Gupi 仍可写文件，沿用 D1 的“未加载（项目未信任）”标记 | 现有 D1 规则 |

## 范围与决定

### 1. 资源路径数组：原样列表编辑

- 放在 Pi 设置“工具与环境”页的新分组“资源路径”，四个字段各一行，全局和项目作用域都可编辑。
- 复用 Pi 配置页的 Form、作用域、锁、重读与按叶冲突机制，与 `defaultTools` 一样用可换行的条目标签：
  - 末尾“添加”打开内联输入，原样追加一条字符串；
  - 标签带删除 ×；
  - **提供上移、下移**（放进标签菜单）。这四个数组里普通路径的顺序决定同名资源的先后，与 `defaultTools` 不同，顺序有意义。
- 不校验、不解析、不预览匹配结果；空字符串之外的任何内容都原样写入。
- 项目作用域显示的是项目文件里的数组，不显示继承的全局数组：两者不合并，“继承”在这里没有意义。

### 2. 资源启停开关

已有全局开关的写法不变（`pi_resources::set_enabled`：去掉同一路径的旧 `+`/`-` 条目，再追加一条）。本次只把开关扩展到项目作用域：

| 行 | 项目作用域的开关 | 写入位置 |
| --- | --- | --- |
| 本项目资源（自动发现或项目数组列出） | 提供 | 项目对应数组 |
| 项目包内的资源 | 提供 | 项目包条目（字符串先改为对象，与全局写法相同） |
| 继承的全局包内的资源 | 提供 | 项目 `packages` 中该包的 delta 对象；不存在时新建 `{source, autoload: false, <类型>: [...]}` |
| 继承的全局独立资源 | **不提供**，保持只读 | Pi 不允许项目覆盖 |

- 开关状态沿用现有扫描结果（D3 已有的“已停用”判定和 `Catalog::inherited_enabled`），不新增推断。
- 已有 delta 行的菜单增加“移除项目过滤”：删除这条 delta 对象。D2 中“delta 只读、不允许移除”的限制随之取消；同身份安装覆盖仍不允许。
- 不提供包过滤数组的原样编辑器：开关已覆盖 delta 编辑，其他已有模式原样保留。需要任意 glob 的用户仍可手改文件。

### 3. 内置扩展开关

- 包页“已安装”视图新增“内置扩展”组，四行，每行一个开关。
- 全局作用域：开关读写全局 `extensions` 中的 `+builtin:<name>` / `-builtin:<name>`；没有条目即为启用。
- 项目作用域：项目 `extensions` 有对应条目时以它为准，否则显示全局状态并标“继承自全局”；切换会写入项目条目。行菜单“恢复继承”删除项目条目。
- 写入方式与资源开关一致：先去掉同名的旧 `+`/`-` 条目再追加。`!` 模式不动。

### 不做

- 扩展、主题代码编辑；
- 资源路径的文件选择器、存在性检查、glob 预览；
- 包过滤数组的原样编辑器；
- 祖先目录 `.agents/skills`、AGENTS 文件、trust.json 管理；
- 保存后让正在运行的会话重新加载：与现有全局开关一致，按现有规则在新会话或重载后生效。

## 所有权与实施顺序

1. `gupi-resources`：
   - `set_enabled` 支持项目根和“写入全局包的项目 delta”；
   - 新增删除 delta 条目、读写内置扩展条目的函数，沿用 `write_settings` 的锁与原子写入。
2. `src/features/settings/pi_config`：新增四个列表字段（`Field`）与“资源路径”分组，复用 `ToolsDraft` 的列表模式，补上移/下移菜单。
3. `src/features/settings/resources`：
   - 项目作用域按上表显示开关；
   - delta 行菜单；
   - 包页“内置扩展”组。
4. 九种语言文案。
5. 资源页的开关与 Pi 配置页的列表会写同一个数组，靠现有的重读与按叶冲突处理：
   - 开关写入后，Pi 配置页重新读取；
   - Pi 配置页有未保存草稿时按冲突提示。

## 验证

- `gupi-resources` 单元测试：
  - 项目资源开关写入项目数组；
  - 全局包资源在项目中新建或更新 delta；
  - 字符串包条目改为对象；
  - 移除 delta 只删除那一条；
  - 内置扩展条目在两个作用域的写入与恢复继承；
  - 未知条目与未知字段原样保留。
- Pi 配置页：四个数组的追加、删除、移动及保存往返；与开关写入同一数组时的冲突。
- worker 用 `script/gupi-ui-gallery` 临时配置检查两个作用域下的“资源路径”分组、项目开关、delta 菜单和内置扩展组。不触碰真实 `~/.pi`。
- `cargo fmt`、`cargo clippy -p gupi`、受影响包的测试。
