# Pi 设置页面美化

状态：Done。实现及必要验证已完成。

依据：
- GPUI Kit 设计规范（`.agents/skills/gpui-kit-design-guides`）；
- 2026-10-15 在 `25398c3` 下用 gallery 临时配置截取的“对话、网络、工具与环境”三页截图，包括默认窗口、宽窗口和项目作用域。

范围：三个 Pi 配置页里每个字段的布局与控件。字段、存储、保存与继承语义都不变，不改 gpui revision。

## 共同原则

1. **一行一个设置，控件紧凑。** 列表和映射不再展开成“每项好几行加通栏按钮”。只有内容本身需要多行时才多行，例如有好几项的映射。
2. **统一的右侧结构：控件 + `⋯`。**
   - 去掉固定宽度的来源栏，来源改为标签后的弱化小字，例如 `默认思考等级 · 全局`。默认值不标注；有未保存修改时追加“· 未保存”。
   - 文本、数字、选择器统一用一档宽度（rem 辅助方法），右缘与 `⋯` 对齐到同一条竖线。
3. **添加操作放在标题行右侧，用小按钮或下拉菜单。** 不用通栏按钮。
4. **行级操作放进行尾的 `⋯` 或删除图标。** 不要居中的大号文字按钮，也不显示禁用状态的占位按钮。
5. **说明只写一次。** 组内共用的说明放到组说明里；字段说明尽量一行。
6. **组的顺序：常用在前，高级在后。**

## 按模型映射（思考等级、压缩参数）

```text
按模型思考等级 · 全局                                    [添加模型 ▾]  ⋯
切换到该模型时使用；显式等级和模型范围的后缀优先。
┌──────────────────────────────────────────────────────────────────────┐
│ openai/gpt-5.4                     [高      ▾]   项目            🗑   │
│ anthropic/claude-sonnet-4-6  不可用 [中      ▾]   全局             ⋯   │
└──────────────────────────────────────────────────────────────────────┘

按模型压缩参数                                           [添加模型 ▾]  ⋯
┌──────────────────────────────────────────────────────────────────────┐
│ 模型                          预留 token        保留近期 token          │
│ openai/gpt-5.4               [24576] 项目      [20000] 全局       ⋯   │
└──────────────────────────────────────────────────────────────────────┘
```

- 标题行与普通行使用同样的结构；“添加模型”是可搜索的选择器形态的小按钮。
- 列表放在细边框容器里（主题的 `group_box` 和 `border`），左右与标签对齐，不另外缩进。
- 模型名单行显示，超长截断，悬停显示全名。当前不可用时，在模型名后加弱化的“不可用”。
- 本作用域的行在行尾显示删除图标（带提示文字和可访问名称）。继承来的行显示 `⋯`，菜单里是“设为项目值”。
- 压缩参数的两个输入框各自显示来源，继承来的值用弱化文字。单格的“恢复继承”放在行的 `⋯` 里。
- 模型列表读取失败或读取中时，只在组说明下显示一行“无法读取模型列表 · 重试”（小号 ghost 按钮），两张表共用；读取完成前“添加模型”禁用。
- 宽窗口下，列表容器的最大宽度与普通行的控件区对齐，不随窗口无限拉长。

## 实施

1. 共享行结构：来源后缀、宽度档、`⋯` 栏位、组顺序。这一步会顺带改到首批的对话页和网络页。
2. 按模型映射的列表组件，模型范围也改用它。
3. 默认工具的标签式条目框和添加菜单；npm 命令改为单个输入框。
   - shell 引号的拆分与拼接需要一个小依赖，例如 `shell-words`，按 AGENTS.md 写完整版本号。
   - 测试覆盖：任意 argv（包括空串、空格、引号）往返一致。
4. 合并思考预算、精简说明，补齐九种语言文案。
5. worker 在同样的窗口尺寸、两种主题和项目作用域下重新截图对比，检查以下几项，我审查后交给用户试用：
   - 右缘和 `⋯` 的竖线对齐；
   - 键盘焦点顺序，包括添加菜单、标签删除和行的 `⋯` 菜单；
   - 长模型名截断。

## 实现与验证结果

- 普通行改为来源后缀、20 rem 控件区和固定行尾菜单；内容最大宽度为 56 rem。模型映射与模型范围使用有边框的紧凑列表，模型范围的排序和删除收进行尾菜单，表头选择器有独立尺寸容器，避免 Select 外层占满父布局；预算合为一行，保留逐项来源与搜索关键词，整行共用一个菜单。
- 默认工具改为可换行 chips、已知工具菜单和内联自定义输入；删除继承条目时将键盘焦点移到稳定的添加入口。npm 使用固定版本 `shell-words =1.1.1`，草稿为 `Slot<Vec<String>>`；无效引号保留为 Invalid，等价引号写法保留原始存储及继承。存储层、锁与叶冲突语义未改。
- `cargo fmt --all -- --check`、`cargo test -p gupi -p gupi-resources -p gupi-settings --locked`（103 / 45 / 21 项）、`cargo clippy -p gupi --all-targets --locked -- -D warnings` 均通过；调试构建通过。新回归覆盖预算独立对账、chips 追加/删除顺序、npm 特殊 argv 往返和真实绑定的无效输入；九种语言键集合一致且没有重复键。
- macOS 临时 gallery 验证了默认/宽窗口、浅色/深色、全局/项目作用域；长模型名截断后不挤出控件，项目缓存预热使用本地化值，继承行提供“设为项目值”，超时关闭显示“已关闭”。默认 2× 截图中普通行及区块标题的菜单图形均位于 x=1855–1872，控件右边框位于 x=1822–1823；宽窗口也检查了共同对齐竖线。
- 原生键盘验证：Shift+Tab/Enter 打开添加菜单、自定义条目 Enter 追加、首个继承 chip 删除后继续 Enter 打开添加菜单；压缩输入框 Tab/Enter 打开行菜单，Escape/Tab 后输入进入下一行。模型范围输入框也可用 Tab/Enter 打开只含适用排序命令的菜单。无效 npm 保存被拒绝，放弃后临时文件的 argv 和工具数组保持原样。共保留 61 张截图（1920×1482 与 3456×1998），包括 Gupi 通用/外观对照和交互状态；未触碰真实 `~/.pi`。
