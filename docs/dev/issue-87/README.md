# 对话导航条

## 目标与边界

在长对话的左侧留白中提供用户消息刻度、短预览和定位。参考上限为本机 Codex 桌面版；数据只来自 Pi 已提供、Gupi 当前正在展示的会话内容。导航只改变阅读位置，不发送消息、不执行历史分叉、不改变 Pi 当前分支。

导航条是当前对话的索引，不是历史树、查找结果列表或按正文高度缩小的 minimap。用户消息与下一条用户消息之间的显示内容构成一个导航区间；工具调用、思考、Shell 记录和压缩记录不另增刻度。

本方案不加入书签、输出产物目录或音频效果。Codex **确实有**本地书签，不能把省略理由写成参考产品没有；本轮采用无持久化的定位工具，不增加另一份会话标记存储。若用户要求书签，应单独确认本地 UI 标记的保存范围，不能向 Pi 会话文件自行追加记录。

## Gupi 中的界面

```text
对话区域（已扣除停靠历史面板占用）
┌─────────────────────────────────────────┐
│            当前对话正文                  │
│  ─         用户消息                      │
│  ━ ──────→ 问题一行 / 回答至多三行       │
│  ━         助手回答、工具过程             │
│  ─                                      │
│            ……                           │
├─────────────────────────────────────────┤
│               原有输入框                 │
└─────────────────────────────────────────┘
```

导航条附着于消息视口，不覆盖标题栏、查找栏、历史预览横幅、输入框和回到底部按钮。保留当前正文居中及最大宽度；按**最终对话视口与正文列**计算左侧余量，达到 3rem 才显示。使用现有间距体系，条带宽 2.25rem、左侧留出 0.75rem；不足时隐藏，不改变外层分隔比例或历史面板布局。工作区最大化/自动单区隐藏对话时一起隐藏。窗口变宽后按当前阅读位置恢复。

### 刻度长度与状态

**长度不表示内容量。** Codex 的 `floating-navigation-rail-17bd6c59412b.css:1`（`Marker` / `MarkerLine`）将线条容器设为 26px，默认 `scaleX(.2308)`，视觉长度约 6px；线厚为间距单位的 0.5（默认 2px），从左端伸缩。它没有读取用户文本字数、回答字数、token 数或区间高度。`floating-navigation-rail-25bbb08441b3.js:1` 的 `p` 接收交互/书签/层级参数；对话 rail 的调用只传 `bookmarked` 与 `neighborDistance`，没有传 `hierarchyLevel`。通用组件的层级长度和可选音频可视化都不是消息长短编码，本轮不采用。

| 状态 | Codex 形状与强调 | Gupi 对应设计 |
| --- | --- | --- |
| 普通 | 约 6px 短线，description 色、0.4 opacity | 所有用户消息使用同一短线，主题 `muted_foreground` 的低强调表现 |
| 当前视口内 | 长度不变，text 色、0.6 opacity | 主题 `foreground`，比普通项明显；当前区间可有多项 |
| 悬停 / focus-visible / 拖扫目标 | 26px 全长，text 色、完全不透明 | 同一个长线状态，加清晰的键盘焦点指示 |
| 距悬停/拖扫目标 1 / 2 / 3 项 | progress 为 .7 / .4 / .2，对应约 20 / 14 / 10px | 保留相邻三级渐变长度，帮助定位密集刻度；不表示回答重要性或长度 |
| 正在指向其它项 | 非目标的当前项退回普通强调 | 交互目标优先，但可见区间数据不改写 |

参考 CSS 的伸缩过渡为 160ms；拖扫及减少动态效果模式取消过渡。Gupi 用主题 motion 能力表达短促伸缩，不复制 CSS 曲线或加入弹簧系统。尺寸用 rem 表达：短线约 0.375rem、全长 1.625rem、厚 0.125rem，沿用 2.25rem 宽、0.625rem 高的刻度命中行。它是局部密集导航尺度，不改变正文或普通按钮；命中区域不随短线缩小，焦点指示不被裁切。

不推荐按用户消息或回答长度改变线条：两者都超出参考行为，而且会把“内容多少”与“当前指向哪里”混在同一个长度通道。按参考上限原则，本方案直接采用固定基线 + 交互伸缩，无需用户在问题长度/回答长度之间选择。

列表高度限制在消息视口的 70% 与 40rem 中较小者，使用虚拟列表，保持固定密度。滚轮在导航条内滚动刻度列表，在正文内仍滚动正文；跟随当前区间只做必要的最小滚动，用户正在悬停/拖扫时不与其争抢导航条位置。

### 预览卡片

Codex 结构见 `thread-user-message-navigation-rail-768952921547.js:1` 的 `$e`，表面见 `floating-navigation-rail-25bbb08441b3.js:1` 的 `m`，回答样式见 `thread-user-message-navigation-rail-9057905bb670.css:1`。顺序为：问题行（可带 heartbeat 图标及书签按钮）→ 有内容才显示的回答 → 有内容才显示的输出产物行。Gupi 保留前两层；不添加图标栏、时间、轮号标题、操作区、分隔线或产物行。

```text
刻度条          预览卡片（左边紧邻刻度按钮右边，垂直居中）
   ─            ╭──────────────────────────────╮
   ───          │ 问题或附件名称，单行省略…     │  medium / 前景
   ━━━━━ ────── │ 回答的现有内容，最多三行。   │  normal / 次要前景
   ───          │ 可以保留轻量 Markdown，      │
   ─            │ 超出可见部分在这里截断…     │
                ╰──────────────────────────────╯
```

| 部分 | Codex 源码值 | Gupi / Kit 映射 |
| --- | --- | --- |
| 表面 | `bg-surface-elevated-secondary`、`ring-border`、`rounded-xl`、`shadow-xl-spread`，无箭头 | 复用 Kit Popover/HoverCard 的主题表面：`popover` 背景、`popover_foreground` 文本、`border`、主题圆角和 popover elevation；不用硬编码颜色或另造强阴影，不强行照抄 rounded-xl 数字 |
| 宽度与边距 | `w-80`，最大 `100vw - 1rem`；`p-2` | 20rem，最大为可用窗口宽度减 1rem，四边 `p_2()`；由公共 popup 定位约束，不参与正文布局 |
| 问题 | `text-sm leading-5 font-medium`，`min-w-0 flex-1 truncate`；内部有图标时 `gap-1.5` | 平台 UI 字体、`text_sm()`、medium、`popover_foreground`；一行尾部省略，全文通过实际消息阅读。本轮没有书签/heartbeat，不保留空图标槽 |
| 回答 | `mt-1 line-clamp-3`，small Markdown；CSS 使用 description 色，行高为 small 字号 + 8px | 问题下 `mt_1()`；`text_sm()`、正常字重、`muted_foreground`，采用 Kit 小正文行高。最多三行；长词/路径换行后仍受三行限制 |
| 高度与裁切 | 外层 `overflow-hidden`；普通回答三行 clamp；含表格时取消 Web line-clamp、另限三倍行高。未见此卡自身固定总高度 | 随实际内容自然高度：内边距 + 一行问题 + 可选间隔/三行回答；不固定空回答高度。窗口高度不足时由可用高度裁切，卡片不滚动；表格/代码不得突破回答区域 |

回答是已有内容的短预览，不是生成摘要。保留轻量文本层级，链接/代码呈现不提供独立操作，图片只用已有 alt/名称，不加载图片或外部资源；沿用 Codex 的 restricted 预览边界。Markdown 的大标题、代码块、表格不能恢复成正文尺寸，截断处不增加“展开/复制/继续”等按钮。卡片没有可聚焦操作，也不成为第二个阅读器。

**内容状态：** 没有回答时只显示问题，不放占位的三行空白；运行中已有可显示回答时随现有会话内容更新同一个卡片，尚无回答时仍只显示问题，不加本轮专用 spinner、思考摘要或进度。附件消息复用正文展示的名称/类型；混合文本附件仍以问题文本为主，不在卡片内增加附件画廊。无法形成可读标题时使用本地化“无文本内容”，不展示原始协议数据。Codex 另有远端预览 loading 骨架和 unavailable 文案（`$e`），Gupi 从已显示 rows 投影，不移植这套远端加载状态。

**定位：** Codex 使用当前刻度按钮作为 `positioningElement`，`side:right`、`align:center`、`sideOffset:0`，不跟随鼠标坐标。Gupi 同样以整行按钮右边和垂直中点为锚；优先右侧，公共 popup 在窗口边缘做必要偏移/翻转。滚动、缩放后按当前按钮重新定位；按钮被虚拟化移走、导航隐藏或会话切换时关闭，不能停留在旧坐标。卡片在正常浮层层级，不越过模态窗口。

**出现与消失：** Codex 通用 tooltip `M2/W6t`（`app-shared-60f4bb85435f.js:195` 的 `M2`、`:324` 的 `W6t`）在 `delayOpen:true` 时选择 250ms，随后允许同一 `skipDelayKey` 的交接策略缩短延迟；焦点和点击可立即打开。150ms 仍只是 rail 的预览数据预取。非交互预览默认 pointer-leave / blur / Escape / window-blur 关闭；带书签的交互预览才有跨入卡片的容错路径。

Gupi 首次悬停采用 250ms；已打开时跨刻度更新同一卡片，不闪烁重建。键盘聚焦刻度立即显示同样的卡片，焦点仍留在按钮；离开导航、Escape、窗口失焦及目标失效关闭。无书签的卡片不可操作、不接收焦点；不加入 HoverCard 默认 300ms 的离开保留来模拟参考中有书签的交互卡。指针与焦点同时存在时，最新明确指向决定预览项，离开后不意外恢复已关闭预览。拖扫复用卡片，不额外等待。定时器只负责本地显隐，切换目标取消旧的待开任务，不请求 Pi。

Kit 0.8 HoverCard 只有悬停封装，不能直接满足受控焦点和上述显隐规则；复用其公共 Popup 定位及主题表面，显隐由导航组件一个 owner 协调，避免叠加两套计时器。此处是具体导航交互，不抽象为新的通用浮层系统。

## 交互与无障碍

点击刻度定位对应用户消息起点，不改变输入框草稿、运行状态、历史分支或查找条件。复用 `MessageScrollerState::scroll_to_item`；Kit 0.8 此接口是即时定位，第一版不另造平滑滚动器。指针按住跨刻度时按当前命中项连续定位，重复命中同一项不重复跳转；释放、取消、失焦或切会话结束拖扫。

悬停和焦点预览采用上节统一显隐规则；不为了模仿 Codex 的预取延迟加入异步摘要任务。Escape 关闭预览/结束拖扫，不修改阅读位置，也不吞掉更高优先级弹窗的 Escape。

沿用 Alt+↑ / Alt+↓ 的前后用户消息定位，边界不循环。当前位于某个回答内部时，“上一条”先回到该区间用户消息；已经在其开头才到前一条。下一条到后一个用户消息。快捷键作用域限当前对话阅读区域及导航条，不抢输入编辑、源码、查找输入、菜单和对话框的按键。导航条因窄窗隐藏时，阅读区域快捷键仍可用。无需专有全局快捷键或新设置页。

刻度使用语义 Button，Tab/Shift+Tab、Enter/Space 激活遵循组件；虚拟列表不通过遍历全部未渲染按钮实现长距离导航，前后动作负责跨虚拟区间。无障碍名称包含“跳到第 N 条用户消息”和简短问题，当前位置有可读取的状态及可见焦点，不只依赖颜色。预览是辅助说明，不独立夺取焦点；隐藏导航条不保留不可见的焦点目标。新增文案维护全部九种语言。实际屏幕阅读器支持以实现时原生检查为准。

## 数据与状态归属

`SessionView.rows` 是导航数据唯一来源，继续通过 `messages::project(session, preview)` 使用 Pi 已提供的历史/实时内容。每个用户行的稳定消息 ID 是刻度 ID；区间结束是下一个用户行之前，未渲染行也可按 `row_positions` 找到索引。投影不按 agent run 数量猜轮次，不独立解析会话文件，也不要求完整 DOM 或全部行同时渲染。

新增 `home/messages/navigator.rs`，拥有消息导航的投影、界面与临时交互。每个 SessionView 保留自己的导航视图/句柄；输入必须来自同一个会话 key、同一个当前预览路径。Home 只组合和路由动作，不让导航内部读取全局 current 后改写另一会话状态。切会话关闭悬停和拖扫，显示目标会话原有 scroller 的位置；切历史路径重新投影并清除已不存在的目标。

正文滚动的唯一所有者仍是 `MessageScrollerState`。导航条只持有自己的刻度列表滚动状态、悬停/焦点/拖扫目标和有界的当前帧测量；不保存第二份正文滚动位置，不新增 state.toml 字段或后台任务。

公开 API 核对：`gpui-component-0.8.0/src/message_scroller.rs:73` 的 `logical_scroll_top` 提供顶部行/行内偏移，`:147` 的 `scroll_to_item` 可跳未渲染行；`list_state` 私有，没有公开 visible-range 或平滑跳行接口。Kit 没有现成 conversation minimap。复用 GPUI 虚拟列表与 Kit Button、主题、浮层定位；不要用 Slider 的百分比代替轮次索引。

多刻度高亮采用现有行渲染边界的轻量测量：仅收集本帧已绘制行与消息视口的交集，映射到用户区间；结合 `logical_scroll_top` 识别横跨整屏的长回答。过绘行必须排除，不缓存全会话像素高度。当前区间集合变化时才通知导航视图，不逐帧让 Home 自我刷新。消息尺寸因流式内容、展开、主题或窗口宽度变化后，以新布局测量为准。尾随滚动返回 item_count 哨兵时等待布局结果，不把哨兵当成真实行。

Kit `HoverCard` 的受控焦点限制及采用的公共 Popup 组合见“预览卡片”。实现不访问私有状态、不升级依赖，鼠标与键盘共用同一份预览内容和显隐 owner。

## 与现有能力的关系

- **历史面板**仍负责会话树、分支和历史路径选择。导航只索引当前已显示路径；历史预览中点击不会“继续此处”、fork 或修改 Pi leaf。历史浮层打开时遵从现有遮挡和焦点规则，不在其上方留下可点击刻度。
- **查找**仍负责文字命中及其展开/定位。查找导致正文滚动后导航高亮自然更新；导航点击不清空查询、不冒充查找命中。
- **虚拟滚动**继续使用既有 row splice/锚点保持。导航不 reset scroller，不改变工具展开状态；实时追加只更新索引/片段，用户停留旧位置时不抢回底部。
- **临时窗口**可用相同只读投影和显示条件，无独立持久化。无用户消息、少于四项、加载/失败页面不显示条带；Shell-only 会话没有虚构用户刻度。

## 删改范围与必要验证

实现主要落在 `home/messages/navigator.rs`、`home/messages.rs` 的行投影/视口组合，以及 `home.rs` 的 SessionView 生命周期。只在需要时接入现有 actions/keybindings 和九语言资源；不改 Pi RPC、会话持久化、历史写入、工作区几何或依赖。既有历史导航、查找与回到底部入口保留。

验证集中证明正式产品契约：稳定消息身份下的跳转/可见区间与虚拟滚动一致；切会话和历史路径不串状态；运行中阅读旧位置不被抢走。复用已有组件夹具，只对新增逻辑在最低有效层补必要验证，不为测量工具、样式常量或每个边界另列测试。实施后一次有代表性的原生检查确认长对话定位、悬停/键盘、窄窗隐藏及历史面板共存，区分自动检查与原生证据。

## 与议题描述的差异

“每轮”具体定义为用户消息区间，不是每次 agent 运行；没有按主题或日期分组。“回答摘要”是已存在回答的短预览，不调用模型生成摘要。书签在 Codex 存在且可做成本地 UI 能力，但本轮建议删去可选项以保持零持久化的定位范围。点击先采用 Kit 公开接口即时跳转；不把 Web smooth 行为当作已具备能力。

本文是设计阶段的源码结论，尚未实现或完成原生验收。需用户确认的收敛点是本轮省略书签，以及采用即时跳转；其余行为按上述参考范围实施。
