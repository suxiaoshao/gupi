# 查看本轮 agent 的文件改动（[Gupi #33](https://github.com/suxiaoshao/gupi/issues/33)）

状态：已实现按文件合成净差异的改动卡片，完成受影响检查与 macOS 原生试用。

## 目标与范围

在每次回复下方汇总这一轮里 agent 通过编辑工具改过的文件，并用 GPUI Kit 的只读差异组件查看改动。

分两个提交交付：

1. **依赖升级**：GPUI Kit 升级到 0.7.3 及配套依赖，处理破坏性变更，评估能否用官方组件替换自写实现。
2. **改动查看**：回复下方平铺的改动卡片，以及工具详情改用差异组件。

不做：bash 等非编辑工具造成的改动、工作目录快照或文件系统重建、回滚和提交操作。

## 依据

- Pi（`2688aba7d`）不提供文件基线或整轮净改动，也没有快照或检查点接口。`edit` 工具结果的 `details.patch` 是标准补丁（`details.diff` 仅供展示）；`write` 工具结果没有 `details`，只有参数中的路径和新内容，无法得知原内容或是否新建。Gupi 事后也无法补回 `write` 的基线。`edit` 与 `write` 都在写盘完成后才检查取消，取消或出错的结果仍可能对应一次实际写入。
- 扩展通过 `ctx.executeTool` 发起的嵌套调用不会作为独立工具调用出现在会话中，父调用结果只保留有限的状态与参数记录，不含补丁（`core/extensions/types.ts`、`nested-tool-calls.ts`）。
- 参考产品：
  - Zed 的原生 agent 由各编辑工具写入变更日志，文件首次被 agent 修改时记录基线，用户的中途编辑并入基线；改动按整个对话累计，直到用户保留或撤销。每次工具调用另有内联差异。外部 agent 在工具调用中自带原文与新文。
  - ChatGPT 桌面应用（Codex）：解包其前端可见，每个文件改动条目（`fileChange`）自带补丁，整轮差异由 Codex 后台推送（`turn/diff/updated`），前端只按轮保存显示；随附的 Codex 程序中也有该通知。后台如何计算未在本地核对。
  - 两者的整轮净差异都由上游提供基线；Pi 没有对应契约。Pi 的 `edit` 补丁由 `createTwoFilesPatch` 生成，带 4 行上下文，基于去 BOM、统一为 LF 的文本；Gupi 按顺序合成同一文件的补丁得到净差异，`write` 之后的内容完整已知。
- 实现前，Gupi 保存工具参数与结果，持久化结果替换实时输出，当前会话与历史会话使用同一投影（`crates/gupi-conversation-ui/src/home/messages/activity.rs`）。配对仅在单个 Run 内进行：工具调用与其结果之间插入用户消息时，两者落在不同 Run，结果一侧成为缺少参数的孤立条目；工具详情按 ID 查找时取第一个匹配，可能选中不完整的一半（`.../messages/details.rs`）。工具详情已优先显示 `edit` 的 `details.patch`，回退到旧的 `details.diff`，并显示 `write` 的内容（`.../messages/tool_details.rs`）。本次由会话分支级 `ToolIndex` 统一配对。
- 界面中的一组回复（Run）按用户消息、压缩和分支摘要切分；中途插话会产生多段，它不是 Pi 的稳定轮次标识（`.../home/messages.rs`）。
- GPUI Kit 0.7.3 的只读差异组件：`DiffFile::parse(patch)` 解析补丁，`DiffState` 由所有者持有，渲染时构建 `Diff`，需要有界视口；`DiffFile::unchanged(path, content)` 可中性展示整份内容。组件负责渲染、选择与虚拟化，不合并多次补丁；同一 `DiffState` 内按文件路径标识，重复路径以第一个为准，选择、导航和复制都会落到第一个文件上。

- 可见变化：文本视图的默认排版调整（段落间距 1rem → 0.75rem，标题随正文字号缩放），Markdown 回复的观感会略有不同。

## 二、改动查看

### 范围与入口

- 以界面中一次可见回复为一轮；遇到中途插话或压缩不跨段合并。
- 先在整个当前会话分支内按工具调用 ID 配对调用与结果，再把操作归到调用所在的 Run；结果落在后续 Run 时不重复计入，也不因中间插入了用户消息而视为缺少参数。工具详情使用同一配对。
- 只统计顶层 `edit` / `write`。扩展嵌套调用没有补丁记录，本次不纳入。
- 列表含义是“本轮记录到的编辑操作”，不是磁盘改动的完整清单，文案不暗示整体或当前文件差异。
- 改动直接平铺在回复下方，位于折叠的过程区之外，不使用对话框，参照 Codex 的改动卡片。

### 改动卡片

- 卡片头：差异图标、“已编辑 N 个文件”与净 `+a −b`；文件行目录弱化、文件名强调（过长截断，提示给出完整路径），带“写入”“错误”文字标记，含义不只靠颜色。默认显示前 3 个文件，其余收在“再显示 N 个文件”，展开后可“收起文件”。点击文件行在行下方原地展开，多个文件可同时展开。
- 不提供撤销、“查看变更”侧栏或悬停预览。
- 每个可合并文件展开后只显示一个有界的统一差异视图（Unified），组件自行滚动，卡片不加外层滚动条。
- 无 write 时，按记录顺序合成 edit 补丁，文件与卡片显示合成结果的净 `+a −b`。有 write 时，以最后一次成功 write 的完整内容为起点，严格应用其后 edit，最终内容中性显示并标“写入”，不推断原文件或显示行数。
- 合成或应用失败时，仅该文件回退为现有逐次操作视图，并提示“无法合并，按操作显示”；回退继续每批最多三个视图和上一批导航。回退文件不提供净汇总，逐次视图仍可显示各次补丁行数。
- 卡片净统计只累加可合成的纯 edit 文件；tooltip 明示这是记录补丁的净改动，排除 write 与无法合并的文件，不代表工作区完整差异。没有可计数文件时隐藏统计。失败但带补丁的 edit 保留错误标记并参与合成。
- 合成后净变化为零（全部抵消）的文件不列出，也不计入文件数；本轮所有文件都抵消时不显示卡片。

### 内容

- 沿用所选 session branch 的 toolCallId 配对、调用所属 Run、顺序与字面路径归组；每个可见 Run 独立合成，不跨 Run、分支或路径别名取基线，不读磁盘、不增加 Pi 扩展。工具详情保持逐次操作。
- 纯 edit 合成使用稀疏原始行/未知区间与新增行的映射，按前序改动换算后续 hunk 的位置。后续 context/删除行凡与已知当前内容相交，都须精确匹配；不得搜索相似位置、使用 fuzz 或填造未知行。校验 hunk 范围、计数、顺序、零长度插入锚点及算术溢出，重叠区只计一次；修改后还原、插入后删除应抵消为净结果。
- 四行 context 只能发现与已知片段矛盾的链；不相交的外部改动无法完整检测。合成结果仅表示记录操作在一致性假设下的净补丁，不声称文件实际未被其他来源修改。
- 存在 write 时，仅最后一次成功 write 及其后 edit 构成有效链；更早的 edit、旧式或坏补丁均已被覆盖，不导致回退。最后 write 后缺失实际补丁、旧式 details.diff 或不可解析补丁不能跳过，回退该文件。失败/取消且无补丁仍按原规则不列入；返回实际补丁的失败 edit 参与链。
- Pi 的 edit patch 针对去 BOM、统一为 LF 的文本生成。write 后应用须按该协议建立匹配文本并严格校验，保存 BOM 与 Pi 检测出的换行风格；有 edit 后按 Pi 的规则恢复全文件换行（混合换行不保证逐行保留），不能将 LF 补丁直接套到原始 CRLF 字符串；不引入尾空白、引号等模糊归一化。通用补丁记录的 CR、无末尾换行标记及所属 old/new 侧必须无损保存，不能用 lines()/trim() 破坏；无法可靠解释时回退。
- 参数路径决定归组，patch old/new 头须按相同字面规则指向该文件，允许已证明的 cwd 内绝对/相对别名。不能把真实 rename 强行改名后合成；多文件、二进制、冲突或不支持的元数据补丁回退，不静默只取首文件。输出头正确转义路径，保留有效行号与可知 context，未知区间只作为 hunk 间隙。

### 工具详情

现有工具详情对话框中的 `edit` 补丁改用同一个差异视图；对话中的工具标记保持紧凑。

### 交互

- 文件行、“再显示/收起”都可用键盘聚焦，Enter / Space 切换，并向辅助功能暴露完整路径与展开状态；文案本地化，计数使用单复数规则。
- 展开或收起后，被操作的文件行保持可见；收起时焦点若在被隐藏的内容中，回到该文件行或“再显示”按钮。净零文件消失时，仅当焦点属于该文件才移到下一行（末行时取剩余末行）；卡片消失则回到输入框，其余情况不抢焦点。
- 回复进行中卡片原地更新，已展开文件的净差异随新操作原地更新，结果不变时保留滚动与选择；新文件按顺序加入。用户向上翻看时保持当前阅读位置，停在底部时沿用现有跟随行为。
- 卡片不是模态阅读器：后台扩展请求等原有焦点转移行为不因卡片展开而改变。

### 归属

- `gupi-conversation-ui` 的非 GPUI 投影负责合成。官方 Diff 仍只用于显示；0.7.3 的 DiffFile 未公开 hunk/源行读取接口，不从显示对象倒推补丁。合成层需要保留行号、边界、换行和路径的补丁表示，将成功结果序列化为标准 unified patch 后交给官方解析器。
- 同步时按文件的有序操作身份与共享载荷修订缓存成功或失败结果；仅重算发生变化的文件，不在 render 或普通文本增量中重算，不深拷贝不变的工具结果。长行、极大稀疏行号不得触发按行号分配或无界二次复制；受控资源限制触发逐次回退。
- SessionView 按 `(Run, path)` 持有合成 Diff/最终内容状态，工具调用 ID 用于持久化 Run 更名时迁移；回退保留逐次 ID 状态。操作集合虽变化而规范化显示结果未变时，复用实体且不调用 set_files；切换合成/回退视图须处理旧焦点回到文件行，不能留下隐藏内容焦点。沿用会话切换保留、分支替换/预览变化清空及现有阅读锚点规则。

## 验证

- 依赖升级提交：`cargo fmt --all -- --check`；`gupi` 及受影响 crate 的 `cargo check`、`cargo test`、`cargo clippy --all-targets -- -D warnings`（`--locked`），包括 `xtask`、`gupi-updates` 的 Objective-C 构建，以及需要 `bundled` 特性的 `gupi-update-helper`（普通全目标检查不会启用该特性）；确认 `Cargo.lock` 中只有一套 GPUI 运行时；推送后由 CI 取得 Windows / Linux 结果。原生试用：Markdown 排版、文本选择/复制/查找、输入框自动增高与右键菜单焦点、设置页焦点环、托盘、截图多屏与临时窗口。Windows 安装包降级行为属于发行验证，不在本次本地验证范围。
- 改动查看提交的自动测试：
  - 调用与结果之间插入用户消息时，`edit` 与 `write` 在实时、持久化、重新加载后都归到调用所在 Run 且不重复；调用确实缺失（压缩）时的孤立结果。
  - 同一文件多次操作时，选中和复制第二次 `edit` 的内容正确。
  - 路径归组：相对与绝对别名、Windows 盘符路径、含空格路径；可解析的孤立 `edit` 与孤立 `write`；补丁解析失败回退为纯文本。
  - 取消/出错且无补丁的调用不列出；成功的 `write` 中性展示。
- 改动卡片的挂载测试：两个文件同时展开且操作较多（含“再显示”操作与文件）、滚出虚拟视口再回来、向上翻看时与跟随底部时的实时增长、持久化后展开状态与焦点保留、分支替换清空、收起时焦点在子内容中的回退、`write`/失败/无法计数混合时的合计、窄窗口与长行、复制路由。保留原有文本与工具参数增量的缓存回归。
- 原生试用：真实会话中的改动卡片（多文件、展开/收起、再显示、进行中更新、键盘、窄窗口）、工具详情，以及历史会话；在卡片展开、回复持续更新时观察流畅度。
- 净差异合成：
  - 正式合成代码：不相交与重叠 hunk、行号因多次增删前后移动、context 交叠/新插入行被再修改或删除、同位置连续插入、空文件/删空/首尾边界、完整抵消、重复行；错误行号/计数/重叠 hunk、可观测外部修改不匹配均回退。
  - 与完整文本参考结果对照：对已知文本生成多次合法补丁，合成结果应用于原文应等于依序应用的结果，净统计来自合成补丁；固定随机种子的多 hunk 序列、相反修改及重复文本覆盖算法边界，不用生产合成器自身生成预期值。
  - write、空 write、多个 write、write 后多 edit、write 前坏补丁被覆盖、write 后坏补丁回退、失败但有补丁；LF/CRLF/单 CR、BOM、混合换行、双方独立的无末尾换行标记、Unicode、尾空白；使用已安装 Pi 的实际生成格式固定样本。
  - 参数/头的相对绝对别名、Windows 盘符与 UNC、空格/制表符/引号路径、不同路径 rename 与多文件补丁拒绝；严格行号应用不能移动到其他重复片段。
  - 缓存与挂载：只重算变化文件，失败缓存、不变净结果不 set_files，单文件一个实体，Run 迁移/会话切换、合成与回退切换及焦点、读取锚点、混合净统计与 write/回退排除、净零文件不列出；工具详情仍逐次。
  - 在长会话和大 write 后多次 edit 场景测量同步成本，覆盖补丁数量与载荷规模、稀疏大行号及资源回退；保留文本/toolcall_delta 不遍历历史大载荷的性能回归。原生用非 debug gallery 观察已展开文件随多次 edit 更新同一净视图及失败后回退；既有验证不能直接视为合成版本已通过。

## 实现

- `messages/tools.rs` 在所选会话分支上配对顶层调用与结果，保留首次调用归属和顺序；持久化结果优先。过程区和工具详情共用该索引。
- `messages/composition.rs` 严格解析补丁并维护稀疏原始行映射，生成可交给官方 Diff 解析的净补丁；最后 write 后使用完整行向量严格应用 edit，按 Pi 的 BOM/换行协议恢复内容。路径、hunk、EOF 和已知内容不一致时逐文件回退，不访问磁盘。
- 合成有界：输入补丁/内容 8 MiB、100,000 行、2,048 个补丁及 8,000,000 工作量上限；write 链累计遍历内容上限 64 MiB。触及上限使用原有逐次视图，不按稀疏行号分配完整文件。
- `messages/edited_files.rs` 按路径归组，并以有序操作身份、共享载荷与 cwd 缓存合成成功、失败或净零结果；仅重算变化文件。纯 edit 净统计来自合成补丁，write/回退不计；净零文件及空卡片不列出。规范化显示结果不变时复用共享载荷。
- 会话工具修订号、不可变工具载荷与 `Rc` 身份沿用性能修复：文本与思考增量不重建工具索引；工具参数增量复用未变化的历史与实时载荷。历史与实时合并保留实时修订，避免错误复用。
- `messages/changes.rs` 在回复下方渲染卡片；SessionView 持有展开、焦点和 `(Run, path)` 合成视图实体。默认三个文件，可同时展开；每个合成文件一个 Unified 视图，write 最终内容中性显示；回退文件显示说明并保留每批三个操作与前后导航。有界 Diff 自行滚动，卡片无外层滚动条。工具详情继续逐次操作。
- 显示结果不变不调用 `set_files`；变化时在同一实体上更新。虚拟卸载保留状态，Run 持久化更名按调用 ID 迁移。会话切换保留，分支替换或预览变化清空。合成/回退切换、净零文件消失只在隐藏内容拥有焦点时回到文件行、剩余行或输入框。
- 卡片预绘制记录可见行几何，通过 List 自动滚动保持披露行可见及向上阅读锚点；主动披露先暂停底部追尾，正常底部更新仍跟随。保留批准的自动滚动行为，GPUI 的 debug 限制见下文。
- 文案覆盖九种语言，净统计 tooltip 明示排除 write/回退及完整工作区差异；回退中的逐次统计另用单次补丁说明。未增加持久化字段、磁盘差异或撤销功能。
