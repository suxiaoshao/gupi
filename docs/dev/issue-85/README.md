# 标题栏分支与 `@` 文件补全

状态：已实现，已完成下述范围的自动化与原生验证。对应 [Gupi #85](https://github.com/suxiaoshao/gupi/issues/85)。本页记录当前设计、实现与实际验证；改动尚未提交。

## 决策

标题栏显示当前会话 cwd 所属仓库的 Git 分支；`@` 文件引用采用 Pi 1.3 TUI 的路径搜索、排序和目录续查语义，保留现有操作面板与资源 token。项目名继续在侧边栏显示。

遵循 [Gupi 与 Pi 的职责边界](../../gui-boundary.md)：Git 信息是桌面展示所需的只读本地数据，不经过 Pi `bash`，不产生会话消息。补全只编辑草稿，发送、扩展处理和会话写入仍由 Pi 负责。不增加 `fd`、Git 库或新的 capability crate，不修改 `/` 命令行为。

## 标题栏分支

- 会话标题旁显示低强调的分支图标和名称，使用现有标题栏字体、间距和主题语义色，不新增彩色状态徽章或项目名。
- attached HEAD 显示实际分支名；detached HEAD 显示 Git 返回的短提交号；尚无提交的仓库仍可显示真实 symbolic HEAD 分支名。
- 非仓库、无当前 cwd、首次加载或查询失败时不显示分支值，不回退到 `main`，不保留另一会话的分支。查询状态在模型中区分，不把失败当成“非仓库”缓存。
- 长分支名截断并提供完整名称 tooltip；窄窗口不能挤出既有标题栏动作或破坏拖动区域。分支是只读信息，不添加 checkout 菜单；可访问名称表达“Git 分支”或 detached 提交状态，新增文案覆盖所有 locale。
- 选中会话/cwd 改变立即查询；窗口恢复活动时刷新。窗口活动期间每 5 秒刷新当前 cwd，查询串行合并；失去活动、隐藏或销毁后停止刷新任务。这样外部 checkout 不依赖 Pi 事件，也不需要常驻全项目 watcher。单个 Git 命令超时为 5 秒，丢弃查询会回收其子进程。

## 所有权与 Git 读取边界

### 可复用的只读查询

在 `gupi-resources::git` 放置无 GPUI、无会话依赖的系统 Git 读取模块。它负责仓库定位、进程执行和结果解析；`gupi-conversation-ui` 负责刷新任务与界面投影。沿用现有依赖方向，不把 Git 信息放进 Pi 会话内容或持久化设置。

对外首先提供“按 cwd 解析仓库”和“读取 HEAD”两个语义操作。仓库描述包含真实工作树根、Git 目录以及必要的 common Git 目录信息，支持 cwd 为子目录及 `.git` 为文件的 linked worktree。HEAD 结果区分分支与 detached 提交；非仓库与执行错误分别返回。类型通过构造器/只读访问器暴露，具体命令组合留在模块内部。

共享的进程执行部分保持私有：直接以参数数组启动系统 `git`，使用明确 cwd，禁止 shell 字符串拼接；后台执行，关闭 stdin 交互，处理超时、取消、退出状态和 stderr，回收子进程。命令只使用必要的只读子命令，不允许调用者传入任意 Git 操作。仓库与路径参数不从展示字符串反向解析；仅去除协议换行，不破坏合法路径空格。

后续 #86 在同一模块扩展语义化的 status/diff 读取，复用仓库定位和进程生命周期；由 diff 查询自行定义输出与大小处理，并关闭 external diff/textconv 等非必要外部执行。#85 不提前实现 diff、stage、commit、checkout，也不创建尚无消费者的通用 Git 服务接口。

### UI 数据流

`当前会话 cwd → 仓库/HEAD 后台查询 → 当前查询结果 → 标题栏`。

Home 保留一个当前仓库展示状态及其任务，不在 `render` 启动 I/O，也不在 Session 中复制分支字段。任务携带 cwd 与请求代次，完成时核对当前目标；切换 cwd 清空旧投影，过期结果不回写。相同目标的刷新不并发叠加。临时窗口按自身当前会话 cwd 查询，生命周期随窗口结束。

首次界面只有未知状态，读到真实值后才展示；不先渲染推测分支再修补。#86 的工作区来源可复用这一 UI 所有者的仓库描述和刷新入口，分支与 diff 各自保存查询结果，避免为了显示分支读取整个 diff。

## `@` 补全语义

参考 Pi 1.3 的 `pi-tui/dist/autocomplete.js`：前缀识别与插入（7–121、294–381）、目录解析（410–443）、候选评分与搜索（584–675）；`pi-coding-agent/dist/modes/interactive/interactive-mode.js:465–543` 将 session cwd 交给默认 provider。这里对齐用户看到的结果和交互，不把 Pi 的 `fd` 进程实现作为依赖。

### 查询与排序

继续使用 Gupi 的 walker，在后台按查询搜索，不在打开面板时同步扫描或在渲染中遍历文件。候选是文件和目录，以真实路径为身份、相对当前搜索根的路径为展示；支持符号链接并防止循环。

| 匹配（忽略大小写） | 分值 |
| --- | --- |
| basename 完全相同 | 100 |
| basename 前缀 | 80 |
| basename 包含 | 50 |
| 完整候选路径包含 | 30 |
| 无匹配 | 排除 |

非空查询只取最高匹配分，匹配目录再加 10；空查询全部为 1，不加目录分。同分依次按层级浅、路径短、名称排序，返回最多 20 项。不是多词 AND，也不是字符子序列匹配：`abc` 不因字母顺序匹配 `a_b_c.rs`。

包含隐藏文件和目录，始终排除 `.git` 及其内容；遵守适用的 Git/ignore 规则，补齐 `.fdignore` 的候选过滤兼容。Pi 的 `fd` 还有 regex/smart-case 预过滤，不能只比较最终分值就宣称等价；用有大小写、元字符和路径分隔符的对照用例确定可见候选，walker 内实现必要过滤，不新增命令依赖。名称同分的 Unicode 排序也用对照用例核实。

Pi 使用浅层与递归两个有界候选池（各最多 100）去重后排序；Gupi 可保留 walker，但不能先截取任意字典序 20 项再评分，或让深层扫描挤掉明显的浅层匹配。搜索应可取消、有界并优先覆盖浅层。大目录下候选集合及排名与 Pi 的代表用例对照；不要求复制文件系统遍历顺序造成的偶然差异。

查询默认从 session cwd 开始。若最后一个 `/` 前的目录存在，进入该目录并用剩余部分搜索；支持 `src/`、`../`、`~/`、绝对路径及平台路径分隔符，保留用户的路径表达。目录不存在时按 Pi 规则回到 cwd 搜索完整查询，不自动换成其他目录。

### 识别与接受

- 从当前逻辑行光标前识别 `@`；支持空白、括号等包装符及中文标点边界，支持 `@"带空格的路径"` 和未闭合引号。普通正文中的 `@` 不任意触发。
- `/` 和 `@` 仍打开现有 CommandPalette。面板持有查询、候选、选择和任务；40ms debounce 后查询，取消旧任务，并以会话绑定、查询代次和 cwd 防止旧结果覆盖新输入。浅层与递归候选池各最多 100 项，去重、评分后最多展示 20 项；总遍历另以 100,000 项或 2 秒约束，保留已取得的候选。
- Enter、Tab、鼠标选择文件：替换原 `@` 前缀范围，插入现有资源 token 和尾随空格，保留光标后的文本、避免重复闭合引号，然后关闭面板并恢复输入焦点；不提交消息。
- 选择目录：面板保持打开，查询进入该目录并继续搜索，路径以 `/` 结尾；加载完成后默认选中第一项，Enter/Tab 可直接继续。文件查询的页脚始终为“填入消息”（加载或空结果时禁用），不显示“发送”。此时不写草稿、不插目录 token、不加空格。Escape 关闭面板，恢复原草稿与焦点。
- token 保留真实路径、显示标签、安全引号转义和原子撤销行为，不照搬 Pi 对嵌入引号的简单包装。每个面板独立持有打开时的完整 InputContent、选区/引用范围和会话 key/binding，文件选择通过延迟回调显式传递该上下文。普通命令面板后续切换到 `@` 也捕获自己的新上下文。完成前核对完整草稿与会话，失效时不替换不相关的新草稿；不使用当前选区兜底，也不借用已关闭面板的范围。
- 面板明确区分加载、无结果与读取失败，取消不报错。此次不增加普通正文 Tab 路径补全，不改变文件导航树的读取规则。
