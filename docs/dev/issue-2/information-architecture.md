# 设置页面与导航讨论

状态：已采用 B3，首批已实现。本文保留区域方案的比较与取舍；当前界面以 [页面设计](page-design.md) 为准，范围以 [首批实施方案](implementation.md) 为准。

用户关切是 Pi 设置数量较多，需要与 Gupi 自身设置清楚区分，并判断应新建页面还是沿用现有页面。

## 当前源码事实

- 当前设置是主窗口中的 `StartupScreen::Settings`，不是独立设置窗口。`src/features/startup.rs` 已有返回按钮和“设置”标题所在的页面栏。
- `src/features/settings/layout.rs` 使用一个 `Settings`，包含通用、外观、通知、快捷键、Pi、包、Skills、模板和关于。
- 当前 Pi 页管理可执行文件路径与探测状态；路径保存到 Gupi 配置，不属于 Pi `settings.json`。
- `gpui-component` 0.7.1 的 `Settings` 支持页面和有标题的组。多个有标题的组可显示为侧栏子项，点击后滚动到该组；这仍是同一长页，而非独立子页面。
- 设置搜索、选中页状态由组件按 ID 持有。当前没有侧栏分区标题、侧栏头部插槽或隐藏侧栏 API；`SettingPage::title_suffix` 可容纳页标题同行的控件。
- 现有资源实现只支持全局资源；为其展示项目选择器会产生错误承诺。

以上来自静态源码核对，尚未验证拟议布局的实际尺寸、焦点和滚动行为。

## 方案比较

| 方案 | 优点 | 代价 | 讨论结论 |
| --- | --- | --- | --- |
| A：扩展现有 Pi 页，以组组织全部字段 | 复用最多，组导航与搜索现成 | 形成长表单；资源仍与 Gupi 偏好平级，归属不清 | 保留备选，不作为目标推荐 |
| B2：同一侧栏分 Gupi / Pi 两段，Pi 各类别独立成页 | 统一搜索，所有分类可见 | 侧栏可能约 15 项；真正分段需上游组件 API 和依赖更新 | 重视统一搜索时的备选 |
| B3：同一设置页面切换 Gupi / Pi 区域 | 归属明确，侧栏较短，入口统一，可复用现有组件 | 搜索限定当前区域；需要处理跨区域导航和状态保留 | 协调者与设计师共同推荐，待用户确认 |
| C：独立 Pi 设置入口与页面 | Pi 有完整独立空间，项目入口直接 | 两套入口、搜索与返回路径；资源需要迁移归属 | 需要独立目的地时的备选 |
| C 的独立窗口变体 | 可与会话并排打开 | 新增窗口生命周期及入口，改变现有设置使用方式 | 未认定有必要，保留选择 |

“新页面”和“新窗口”是不同决策。B3 复用现有设置页面外壳，但新增 Pi 的分类页面；并不等于把全部字段塞进旧 Pi 页。

上图是早期分类容量草案，不表示本期实现清单。后续筛选推荐收缩为真正有字段的页面，不默认创建工具或隐私页；当前分类提案以 [逐页设计](page-design.md) 为准，字段依据见 [筛选文档](field-selection.md)。

- 将区域切换放在现有页面栏，与标题同行，不新增一行工具栏。标准分段式 `TabBar` 是组件候选，尚未运行验证。
- 当前 API 下可为两个区域使用不同 ID 的 `Settings`，每次渲染当前区域。分类选择与搜索可按区域持有；组件卸载后状态保留行为仍应在实现时核对。
- 真正放在侧栏搜索框上方需要上游插槽；不通过复制整个组件或布局偏移模拟。
- 区域内搜索匹配名称、说明和 JSON 字段关键词；不承诺跨区域结果数量或自动跨区域查找，当前组件没有公开对应搜索状态。
- 包市场搜索继续是包页内的独立搜索，不与设置字段搜索混同。
- 原有跨页跳转需要携带区域和页面身份。侧栏宽度是否跨区域共享属于后续常规实现选择，不另列产品问题。

“连接”用于当前可执行文件与探测信息。它与 Pi 使用相关，但值由 Gupi 保存；放在 Pi 区域便于发现，放在 Gupi 区域则更符合存储归属，两者仍待选择，不用解释性横幅掩盖命名问题。

## 项目作用域与资源边界

项目覆盖是本次任务核心，不以“先只做全局”作为默认方案。

推荐在 Pi 配置页标题同行提供 `全局 / 项目名称` 选择，作用域在这些配置页之间共享。从会话或项目菜单进入时携带准确 `cwd`，直接打开 Pi 配置。项目集合和是否提供“选择文件夹…”仍需结合真实入口需求确定。

现有包、Skills、模板继续使用唯一的全局编辑器，不默认扩展项目资源管理：

- **R1，推荐：** 放在 Pi 区域，页标题同行显示静态“全局”，不提供项目选择器。返回普通配置页时恢复先前选定的项目作用域。
- **R2，备选：** 资源保留独立位置，由 Pi 配置提供跳转。边界更强，但 Pi 相关内容会分散。

项目配置页中的全局专用字段，如代理、缓存预热和信任默认策略：

- **G1，推荐：** 显示当前全局值，以普通文本和“在全局中编辑”按钮呈现；跳转至全局对应页/组。避免禁用控件被误认为故障。
- **G2，备选：** 项目页隐藏这些字段。界面更短，但项目作用域搜索不到它们。

未信任项目是允许编辑但显示未生效状态，还是只读，仍待确认；不得通过编辑入口默认授予信任。格式错误则显示可恢复错误与打开配置文件操作，不把它当成空配置。

## 继承与保存交互

继承值保持正常可编辑样式。用简短来源文字区分默认、全局、项目，恢复继承删除字段。不要用灰色控件制造禁用感，也不要给每个字段加彩色标签或说明横幅。

布尔值有一个未定问题：当继承值已经是 `true` 时，用户可能想显式固定为 `true`。普通开关无法直接表达该操作。应比较“设为项目值”的行操作或明确继承控件；不把来回切换两次作为正常操作路径。

`enabledModels` 是整体替换数组；`defaultTools` 支持继承上的增减，不能复用普通数组替换编辑器。工具专用编辑器是否进入本期尚未决定，不在此确定清单、替换模式等详细行为。

| 保存方案 | 优点 | 需处理的问题 |
| --- | --- | --- |
| 按字段提交，设计师倾向 | 布尔/枚举操作直接，无额外保存区；小范围定点写入 | 数字/文本需草稿和明确提交时机，继承操作可能连续写入 |
| 按页显式保存，协调者保留为有效备选 | 可一起检查多个参数和项目覆盖，失败时草稿集中保留 | 切页/区域/作用域需处理未保存内容；保存/还原操作应优先评估现有页标题空间 |

两种方案均应保留保存失败的用户草稿，明确区分草稿与磁盘已保存值。不要静默回退并丢弃输入。Pi 路径目前独立采用草稿与显式保存，是否调整不随其他字段自动决定。

保存到文件和影响当前会话是不同契约。必须按入选字段核对启动、恢复会话、运行中读取和 RPC 持久化副作用，不能统一承诺“立即生效”或“只对新会话生效”。仅在已验证且影响使用时给出简短字段说明。

## 已采用的决定

1. 页面结构采用 B3：同一设置页面中的 Gupi / Pi 区域，切换控件位于现有页面栏。
2. 资源边界采用 R1：包、Skills、模板留在 Pi 区域，标题行标注“全局”，不加入项目资源编辑。
3. 全局专用字段采用 G1：项目作用域下显示全局值与“在全局中编辑”。
4. 提交方式为按页保存；布尔继承的显式覆盖通过字段菜单“设为项目值”表达。
5. 连接页放在 Pi 区域；未信任项目可以编辑和保存原始配置，标题行显示未信任状态并提供“信任项目…”。
