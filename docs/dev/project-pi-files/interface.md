# 项目 Pi 文件：界面设计

状态：Draft。用户已认可“共享设置界面 + 项目上下文入口”的方向，并要求编写开发文档；实现尚未开始。工作总览见 [README](README.md)，文件读写、冲突与锁的契约见[数据与持久化](data-and-persistence.md)，本文不重复。

本文用三种标记区分结论的来源：

- **已采纳**：用户认可的界面方向；
- **源码确认**：依据 Pi 1.1.0 研究快照或当前 Gupi 源码，出处列在文末；
- **设计推荐**：常规设计选择，实现时可按需调整，不需要用户另行批准。

后续 Packages 作用域与标题栏入口以 [D2 界面](d2-interface.md) 为准；本文保留 D1 文本资源契约。

## 范围

项目 Pi 文件指项目目录 `.pi/` 下的文件。本工作分两个里程碑：

| 里程碑 | 内容 | 状态 |
| --- | --- | --- |
| D1 文本资源 | `.pi/SYSTEM.md`、`.pi/APPEND_SYSTEM.md`、`.pi/skills/`、`.pi/prompts/`，以及首批已有的项目 `settings.json` 字段 | 本文主要对象 |
| D2 项目包 | `.pi/settings.json` 中的 `packages` 声明及项目包安装 | 同一工作的下一里程碑；**包页面目前没有项目模式**。修改 `package_action`（区分 cwd 与 agent-dir、`--local`）留到 D2 |

**仍属本工作、但尚未设计**：

- `.pi/extensions/`、`.pi/themes/`；
- `settings.json` 中 `skills`、`prompts`、`extensions`、`themes` 路径数组的编辑；
- 在项目中停用全局资源（写项目 `settings.json` 过滤项）。

**不属于本工作**：

- `.pi/mcp.json`，归独立的 MCP 工作；
- `.pi/` 之外的 AGENTS/CLAUDE 指令文件，以及祖先目录中的 `.agents/skills`；
- 全局 `trust.json` 的列表、撤销和拒绝管理。项目信任只是 Pi 加载这些文件的前提。

## 编辑界面与入口（已采纳）

**编辑界面**：项目文件在现有“设置 › Pi”中编辑，不新增会话内面板或单独的项目页面。理由如下：

- `.pi/` 属于目录，作用于该目录下现有和将来的所有对话；
- 它与全局配置是同一个分层模型。

**入口**保持现有两处，文案均为“项目 Pi 设置…”：

- 对话标题栏 `⋯` 菜单的第二项。会话的 `cwd` 未知时禁用。
- 首页项目行的右键菜单。

两处都打开设置，切到 Pi 区域，并把作用域设为该项目。

- 返回按钮回到原对话。
- 标题栏右侧、文件面板按钮之前提供 FolderCog 项目设置入口；名称包含项目文件夹，明确是项目作用域。有 cwd 的非临时对话显示，新建对话无需先发送消息。详见 [D2 界面](d2-interface.md)。

**没有活动对话时**：在作用域菜单中选择项目，或用“选择项目文件夹…”。

## 作用域选择器

**一个区域共享的作用域（已采纳）**：Pi 区域只有一个当前作用域，所有支持项目的页面共用它。

- 在任一页切换作用域，其余页面随之切换。
- 不允许各页停留在不同作用域。

**菜单内容**（方向已采纳，以下排序为设计推荐）：

1. 全局。
2. 当前活动对话所在的项目（若有），排在项目第一位。
3. 本次运行中打开或选择过的其他项目。
4. 分隔线，然后是“选择项目文件夹…”。

**显示方式**：

- 项目以文件夹名显示，悬停提示完整路径。
- 两个项目同名时，在名称后附加上级路径加以区分。
- 菜单与页面标题不使用对话标题。

**默认值**：从设置入口直接进入时为全局（已采纳）。只有明确的上下文入口（对话 `⋯` 菜单、项目行菜单）才切换到对应项目。

**选择项目文件夹…**：

- 打开系统文件夹选择器。
- 所选目录作为一个作用域加入菜单并切换过去。
- 不会创建 `.pi/`，也不会授予信任。

**列表来源**：D1 使用本次运行内的列表，包括打开过的项目和选择过的文件夹，不跨运行保存。列出会话目录（catalog）中的全部已知项目、跨运行保存最近项目，都是以后可选的增强，不阻碍 D1 就绪。

**切换作用域时有未保存修改**：沿用首批的“保存 Pi 设置？”确认，选项为取消、放弃、保存。

## 各页面的作用域

| 页面 | 作用域 |
| --- | --- |
| 连接 | 不显示作用域，编辑 Gupi 自身配置 |
| 对话、网络 | 全局 / 项目，首批已实现 |
| Skills、模板 | D1：全局 / 项目 |
| 包 | 保持标题行的静态“全局”，直到 D2。项目作用域下进入包页时同样显示“全局”，**不得**伪装成项目模式 |

包页不另加固定说明行，标题行的“全局”即可表明范围。只有实际出现歧义时，才考虑加上下文帮助。

## 项目作用域下的资源页

### 列表组成

项目作用域下，Skills 与模板页分两组：

| 组 | 来源 | 可执行的操作 |
| --- | --- | --- |
| 本项目 | `<cwd>/.pi/skills/`、`<cwd>/.pi/prompts/` 中的文件 | 新建、编辑、删除、查看、在 Finder 中显示 |
| 继承 | Gupi 已扫描的全局来源（个人目录与全局包） | 只读查看；“在全局中编辑”先经过离开保护，再把区域作用域切到全局，并定位到同一页 |

继承组只展示已扫描的全局来源。它不是当前会话有效资源的完整列表：CLI 参数、扩展注册的资源和祖先 `.agents/skills` 都不在其中。

继承组不显示开关和删除操作：这些操作改动的是全局配置，在项目作用域中出现会误导范围。在项目中停用全局资源留待后续设计。

模板页顶部的“系统提示词”组改为显示项目文件：

- `.pi/SYSTEM.md`：替换系统提示词；
- `.pi/APPEND_SYSTEM.md`：追加到系统提示词。

每项显示状态“项目文件”或“使用全局”。

### 来源与覆盖标签（源码确认的规则）

**Skill 与模板**：

- 按优先级排序，同名项以先出现者为准，后出现者被 Pi 记为 collision。
- 名称来源：
  - Skill 取 frontmatter 的 `name`，缺省时取所在目录名；
  - 模板取文件名去掉 `.md`。
- 优先级从高到低：
  1. 项目 `settings.json` 路径项；
  2. 项目自动发现，包括 `.pi/skills|prompts`，以及祖先目录中的 `.agents/skills`；
  3. 全局 `settings.json` 路径项；
  4. 全局自动发现；
  5. 包资源。
- 只有已启用的条目参与比较：已停用的高优先级条目不会遮蔽低优先级条目。
- 项目不受信任时，Pi 不发现 `.pi/` 中的 skills、prompts、extensions、themes。

**SYSTEM / APPEND**：

- 项目受信任且项目文件存在时，使用项目文件，否则使用全局文件。
- 两级的 `APPEND_SYSTEM.md` 不会拼接。

**界面据此显示**来源和已知的同名关系，不显示“生效 / 未生效”：

| 情况 | 本项目条目 | 同名继承条目 |
| --- | --- | --- |
| 项目已信任；项目条目与全局条目均已启用；两者名称都能按上述规则确定且相同 | “与全局同名 · 项目优先” | “与项目同名 · 项目优先” |
| 项目未信任 | “未加载（项目未信任）” | 只显示来源，不对其是否被 Pi 使用作任何说明 |
| 任一方未启用、名称无法确定（例如 frontmatter 无法解析），或无同名条目 | 只显示来源 | 只显示来源 |

继承条目在未信任时也不能写成“Pi 仍使用”：CLI 参数、扩展和过滤项都可能改变它，Gupi 无法得知。

**限制**：

- `.pi/` 外的祖先 `.agents/skills` 与项目条目同级，但不在本工作范围内，Gupi 也不扫描它们。
- 因此界面**不得**断言某个资源在当前会话中一定生效或不生效，只说明配置中的同名关系。
- 标签只依据磁盘上的配置推断，不代表运行中的会话已经重新加载。

## 文件操作语义

| 操作 | 行为 |
| --- | --- |
| 新建 Skill / 模板 | 沿用现有流程：输入名称 → 在 `.pi/skills/<名称>/SKILL.md` 或 `.pi/prompts/<名称>.md` 打开新建编辑器。保存时创建缺失的父目录，包括 `.pi/`；目标已存在则不覆盖 |
| 编辑 | 沿用现有编辑器对话框：保存立即写入该文件，不经过页面级“保存” |
| 删除 | 只作用于明确选中的本项目条目。只删除文件：Skill 条目的路径是 `SKILL.md`（根目录下的单文件 Skill 是该 `.md` 文件），删除时把这个文件移入系统废纸篓，不删除所在文件夹及其支持文件。确认框显示条目名称和将被删除的文件路径。同名全局条目的文件不受影响，它重新成为候选，但不保证在当前会话中生效 |
| 编辑项目 SYSTEM / APPEND | 文件不存在时打开空白编辑器，保存即创建项目文件 |
| 使用全局（SYSTEM / APPEND） | 删除项目文件（移入废纸篓），恢复回退到全局文件的发现规则；不保证当前会话立即使用 |

文件操作的**源码确认**现状：

- 现有编辑器保存时整体原子替换，**不比较**打开时的内容基线；
- 新建用不覆盖方式写入；
- 删除用 `trash`。

**计划**（契约见[数据与持久化](data-and-persistence.md)）：

- 编辑器记录打开时的内容基线，保存前重读比较。文件已被删除或外部修改时不覆盖，保留修改，并提供“重新读取”和“取消”。这只能发现已经发生的变化，不保证与其他编辑器严格互斥。
- 保存目标绑定打开时的文件与作用域，不随之后的作用域切换移动。

**外部路径（推荐边界）**：

- 解析后位于本项目 `.pi/` 之外的条目，在项目页只读，并显示实际目标路径；
- 这包括外部路径和指向 `.pi/` 外的符号链接；
- 目的是避免通过项目页无意修改全局或其他项目；
- 现有 `Resource.editable` 标志不足以作此判断：它只表示条目来自个人目录而非包，不检查解析后的实际路径。写入前必须按解析后的路径重新校验归属，不能只比较路径字符串前缀；
- 本方案不承诺抵御恶意的文件系统竞争。

**空内容与不存在不同**：保留现有能力，空白内容可以保存。

- 保存空白的项目文件会留下一个存在的空文件。按发现规则，项目受信任时 Pi 选中这个文件，不再回退到全局文件。
- 按源码阅读，Pi 读取后的处理如下（未经运行验证）：
  - 空的 `SYSTEM.md` 内容为空字符串，系统提示词组装时视为未提供自定义内容，因此使用 Pi 内置的默认提示词，**不是**全局 `SYSTEM.md`；
  - 空的 `APPEND_SYSTEM.md` 不追加任何内容，全局 `APPEND_SYSTEM.md` 同样不会被使用。
- 以上发现规则只在未通过 CLI 指定系统提示词时适用；CLI 指定的来源优先于文件发现。
- 因此“使用全局”必须是单独的显式操作，界面不能把“清空内容”当作恢复继承。

**项目作用域下 D1 不提供的操作**：

- 本项目条目的启用开关：会写项目 `settings.json` 过滤项；
- “注册 Skill”：会写路径数组。

## 未保存修改与离开

- **文本编辑器**：保存方式不变，仍是模态对话框，在对话框内保存单个文件。
  - 关闭时若有修改，先确认是否放弃。
  - 编辑内容不并入 Pi 设置的页面草稿。
- **对话、网络页的字段草稿**：沿用首批的“保存 / 放弃 / 取消”确认。
- **统一离开保护**：资源编辑器修改与字段草稿使用同一个离开保护。适用的操作：
  - 切换作用域；
  - “在全局中编辑”；
  - 切回 Gupi 区域；
  - 离开设置；
  - 从菜单或快捷键进入另一个项目的设置。

  模态对话框挡住了大部分点击路径，但应用级的菜单和快捷键动作仍须经过这个保护。统一的只是“保存 / 放弃 / 取消”的确认；每个文件分别保存、分别报告失败，不承诺跨文件全部成功或全部不写。
- **区域内切换侧栏页面**：仍由 `Settings` 组件处理、无法拦截；字段草稿按字段保留，与首批相同。

## 信任

项目未信任时，标题行显示“未信任”和“信任项目…”，与首批相同。

- 可以新建和编辑项目文件。页面说明 Pi 在项目受信任前不会加载它们。
- 编辑、保存或删除文件都不授予信任。
- 信任对话框的内容与写入规则不变：只为当前规范化目录写入 `true`。
- 信任记录无法读取时显示错误，不推断为已信任。

## 路径标识与错误

**项目标识**：

- 作用域以规范化后的绝对目录为键。来自会话、项目行和文件夹选择器的同一目录合并为一项。
- 切换项目后，旧项目晚到的读取或保存结果不显示在新项目页面上（契约见数据文档）。
- 目录必须存在且是文件夹。
- Pi 只读取 `cwd` 下的 `.pi/`，不会向上查找（源码确认，`projectBaseDir = join(cwd, ".pi")`）。因此选择项目的子文件夹，得到的是另一个作用域。

**错误状态**，资源页在列表上方显示一行状态，与首批字段页一致：

| 状态 | 处理 |
| --- | --- |
| 项目目录不存在或已移走 | 显示路径与“目录不存在”，禁止写入，提供“选择项目文件夹…” |
| `.pi/` 不存在 | 正常状态：本项目组为空；首次新建时创建 |
| `.pi`、`skills` 或 `prompts` 不是目录 | 显示错误，禁止新建，不尝试修复 |
| 读取失败（权限等） | 显示错误和“重新读取”；不显示为空列表 |
| 单个文件无法解析 | 沿用现有资源警告行 |
| 保存或删除失败 | 编辑器内显示错误，修改保留 |

## 文案约束

- 不把项目文件称为“本对话的设置”。
- 保存只说明文件已保存，不承诺立即生效，也不承诺新对话或重新连接后一定使用每一项设置：恢复的模型或思考等级、CLI 参数等都可能优先。与[数据与持久化](data-and-persistence.md)一致。
- 按“来源”“项目优先”“未加载”“使用全局”建立一组固定词汇，菜单、标签和对话框统一使用。

## 键盘路径

Tab 顺序：作用域菜单 → 信任操作 → 页面工具栏（搜索、新建）→ 本项目条目 → 继承条目。

- “选择项目文件夹…”可用键盘从作用域菜单打开。
- 编辑器对话框沿用 Escape 关闭及“放弃修改”确认，焦点回到触发按钮。

## UI 验收（有界）

以下是验证计划，不是已通过的结果；验证由协调者执行。D1 交付试用前，在真实窗口中确认：

1. 从对话 `⋯` 菜单和项目行右键菜单进入，作用域都是该项目；返回后回到原对话。
2. 切换作用域后，对话、网络、Skills、模板四页显示同一作用域；包页标题行仍显示“全局”。
3. “选择项目文件夹…”能选择没有对话的文件夹，不创建 `.pi/`，也不改变信任状态。
4. 在项目中新建、编辑、删除一个 Skill 和一个模板：文件位于 `<cwd>/.pi/` 下，全局目录不变。
5. 项目 `SYSTEM.md` 的创建与“使用全局”：前者产生项目文件，后者移除它，全局文件不变。
6. 同名的项目条目与全局条目显示“项目优先”的同名关系；未信任时显示“未加载”，不标为已覆盖。
7. 继承条目没有开关和删除操作，“在全局中编辑”切到全局并定位到同一页。
8. 读取错误不显示为空列表；编辑器有修改时，关闭、切换作用域或离开设置都会询问。
9. 解析后指向 `.pi/` 之外的条目（外部路径或符号链接）在项目页只读，并显示实际路径。

完整的全量验收按用户要求另行安排。
