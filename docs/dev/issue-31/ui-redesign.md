# 会话与源码工作区 UI/UX 改造方案

状态：已实现。本文记录当前设计、实现和必要验证。

## 目标与当前问题

主要任务是浏览项目源码，并在保留代码上下文时阅读、输入会话。当前文件正文 Dialog 会挡住会话；右侧栏同时承担导航与正文入口，存在重复标题、工具栏分层混乱、完整路径争夺视觉注意及底部“预览”入口冗余的问题。

改造采用 **会话与源码并排的工作区**。源码是常驻内容区，右侧栏仅承担文件与历史导航。会话可以变窄，但保持正文可读和输入可用。允许修改主窗口布局、面板结构与交互；正文已移至工作区。

不新增编辑、保存、多文件标签、Git 操作、目录监听、模型能力或语言依赖。继续使用只读 Editor、现有文件读取边界和按需目录加载。

## 确定的布局

```text
宽窗口，有文件打开
┌────────────────────────────────────────────────────────────────────┐
│                         窗口标题栏                                  │
├──────────┬──────────────────┬─────────────────────┬────────────────┤
│ 会话导航 │ 会话正文         │ 文件名  路径  只读   │ 历史 │ 文件  × │
│          │                  │ 重读 / 换行 / ⋯ / × │ 项目名  刷新 ⋯ │
│          │                  ├─────────────────────┼────────────────┤
│          │                  │ 行号与源码正文      │ ▾ crates       │
│          │                  │                     │   ▾ ui         │
│          │                  │ 独立滚动            │     files.rs   │
│          ├──────────────────┤                     │   Cargo.toml   │
│          │ 会话输入框       │                     │                │
└──────────┴──────────────────┴─────────────────────┴────────────────┘
           可拖动边界         可拖动边界            可拖动边界
```

区域顺序为：**会话导航 → 会话正文与输入 → 源码 → 文件/历史导航**。文件树与其打开的源码相邻；没有打开文件时不占源码区域，会话恢复使用剩余空间。每个对话拥有一个独立源码槽，新文件替换该对话的旧文件；同文件保留阅读位置、换行与查找，重读需显式操作；隐藏导航或切到历史不关闭源码。

会话输入框在宽窗口中属于会话列，不横跨源码底部。会话导航的显隐由用户控制，不因打开文件自动关闭。

### 宽度与响应式行为

工作区尺寸和侧栏偏好按 rem 计算，分隔线及拖拽命中区域沿用组件能力。表中的数字是起始设计比例，实施时以实际组件和窗口校验为准。

| 区域 | 最小值 | 默认及空间分配 |
| --- | --- | --- |
| 左侧会话导航 | 10rem，上限 30rem | 默认 14rem；显示宽度再按当前可用空间约束 |
| 会话内容 | 24rem | 工作区宽度的 40%，按正文/源码最小值夹取 |
| 源码内容 | 30rem | 占工作区剩余宽度 |
| 右侧导航 | 15rem，上限 32.5rem | 默认 20rem；空间不足时临时压缩 |

令 `M` 为扣除可见左栏后的宽度，`N` 为右导航实际宽度，`W` 为会话与源码工作区宽度，`Nmin = 15rem`。实际计算须计入分隔线占用。可用空间不足以满足最小值时，最小值降到当前可用最大值；显示和拖拽调用相同的几何边界函数，不在保存或加载阶段二次夹取。

- 文件打开且导航可见，`M ≥ 54rem + Nmin`：导航停靠，`N = clamp(已保存导航 rem × 当前 rem, Nmin, min(32.5rem, M − 54rem))`。会话、源码达到各自最小值后，导航才放弃宽度；不覆写保存值。
- 文件打开且 `54rem ≤ M < 54rem + Nmin`：会话与源码并排，导航按需以覆盖面板打开。选择文件后覆盖面板关闭。
- 文件打开且 `M < 54rem`：工作区变为单正文槽，提供“会话 / 当前文件”切换，输入框留在槽底部。导航按需以覆盖面板打开。
- 没有打开文件：会话最低 24rem，导航最低 `Nmin`，按相同最小值策略决定停靠或覆盖，不沿用固定 1100px 阈值；历史在部分较窄窗口继续停靠是本次改造的明确变化。
- 导航隐藏时不给它保留宽度；会话与源码是否并排由可用工作区宽度决定。

并排时，`会话宽度 = clamp(比例 × W, 24rem, W − 30rem)`，源码取余量。原始比例不受窗口临时夹取影响。各分区分别滚动，不让整窗滚动。

```text
窄窗口，当前正在看源码
┌──────────┬──────────────────────────────────┐
│ 会话导航 │ 会话（回复状态） │ 当前文件  ×    │
│          ├──────────────────────────────────┤
│          │ 源码，或保留状态的会话正文       │
│          │                                  │
│          ├──────────────────────────────────┤
│          │ 发消息到当前会话的输入框         │
└──────────┴──────────────────────────────────┘
```

窄窗口打开文件自动显示源码槽；发送消息不自动切走源码。会话切换项显示正在回复状态，并有对应可访问名称，让用户知道回复在哪。点击历史条目会激活会话槽。会话草稿、选择、阅读位置及已有更新行为保留，不借本次改造做通用消息滚动重构。

## 视觉层次

右侧栏使用与左侧相同的主题 sidebar 表面；会话与源码使用内容 background。区域边界只画一条细线，不靠堆叠卡片、阴影或强调色分层。覆盖导航才使用覆盖层表面与阴影。

右侧栏严格分为三个层级：

1. 一个真正的“历史 / 文件”页签栏及共同关闭按钮。用组件的选中状态，不用两个普通 ghost 按钮假扮页签。
2. 一个当前页签的工具栏。文件：项目名、刷新、更多菜单；完整项目路径放入提示及“复制路径”。历史：列表/树切换与“视图”菜单；菜单保留内容程度、分支范围的原语义和勾选状态。
3. 内容列表。删除重复“会话历史”标题、常驻两行完整根路径和文件底部的路径/预览按钮。

窄窗口切换项标为“会话 / 源码”，避免重复文件名；输入区域有独立上分隔线和会话归属文字，源码显示时收起非关键会话通知；扩展 widget 在输入框上方或下方正常显示，不因源码模式隐藏，空间不足时由用户扩大窗口。源码标题行与导航页签栏对齐高度和基线，起始高度约 2.5rem。文件名使用正文小号中等字重，目录路径使用次要色并允许截断，完整路径可查看。“只读”为中性文字及锁图标。重读、换行、更多与关闭在固定尾部区域，换行启用状态持续可见；更多菜单提供复制路径和在文件树定位。

树行的实际总高度起始约 1.75rem，包含组件内部 padding，避免在 ListItem 外再叠加行高。每级缩进 1rem，箭头和图标有固定槽位；标题、工具栏、列表及状态行共享对齐线。选择行使用组件选中填充和焦点状态；当前打开文件另有中等字重及固定尾部标记，不能只靠颜色区分打开与选中。

使用主题语义颜色、组件密度及 rem 间距；中文和长翻译不能撑坏工具栏。目录加载和失败沿用正式列表反馈；空目录展开后没有子项，不添加提示行。源码加载/不支持/超限反馈放在正文内；长行降级和重读失败保留旧快照采用简短行内说明。

## 打开、焦点与键盘

- 单击普通文件即打开快照；在停靠树中保持树焦点，方便继续浏览。上下箭头仅移动选择，不逐项读正文。目录单击与左右箭头保留展开/收起语义。
- Enter 打开文件，立即聚焦源码容器；读取完成后，仅当仍是最新打开请求且容器仍有焦点时，才进入 Editor。之后用户移到输入框，异步结果不得抢焦点。
- 从覆盖导航打开文件后关闭覆盖层。鼠标打开只聚焦源码容器；键盘打开遵循上述 Enter 规则。加载、错误容器也需拥有可见焦点路径。
- 源码容器中的 Enter 可进入正文，Tab 沿用控件间焦点导航；查找由焦点控件自己处理：普通与扩展多行输入框查找草稿，源码 Editor 使用内置查找，会话消息区域拥有其局部 Ctrl/Cmd-F；导航、加载及错误区域不转接查找。无窗口级 Find 兜底，也不依据单槽可见内容选择目标。显式“查找会话”命令按其名称显示会话并打开会话查找；切换正文后聚焦可见区域，命令面板“显示会话”提供键盘返回入口。覆盖导航打开时聚焦其当前导航内容，确保键盘操作和 Escape 可用；停靠面板的鼠标操作沿用正常点击与 Tab 行为。关闭导航不恢复历史焦点，也不强制聚焦输入框；只有当前聚焦控件移除时才回退到有效祖先或主窗口容器。明确的键盘命令仍聚焦其目标。停靠列表内 Escape 沿用现有停止回复命令，本次未改变。空历史、加载和错误提示区域复用现有历史焦点句柄，避免键盘打开后聚焦隐藏的列表。覆盖层使用独立 Escape 命令，适用于内容及工具栏；菜单优先关闭，下一次 Escape 再关闭导航。源码容器与工具栏的 Escape 返回会话输入框或停靠文件列表，不触发停止回复。
- Editor 内 Escape 先关闭查找，再返回有效目标。返回目标为当前停靠且激活的文件树中的打开行；若文件父目录收起，返回最近可见父目录。树隐藏、覆盖、历史激活或单槽模式时返回会话输入框。
- Escape 不关闭常驻源码，不暗中打开导航、切换页签或切换正文槽。覆盖导航里的 Escape 关闭覆盖层，焦点按上述失焦兜底规则处理。
- 关闭文件通过标题栏 × 或命令面板“关闭文件”。释放文本/解析/读取任务；单槽模式返回会话。只有焦点原在源码内时才转移到返回目标，不能抢走正在输入的焦点；命令面板记录其打开前区域。
- 命令面板保留“项目文件”，补充当前文件可用的“关闭文件”“聚焦源码”和“显示会话”。不新增全局快捷键或“提及文件”功能。

## 状态所有权与本地偏好

HomeView 组合会话、源码及导航可见性/布局；每个 SessionView 独立持有文件导航、源码 Entity、事件订阅及正文切换状态。文件导航 Entity 的根目录固定为该对话 cwd，拥有目录缓存、展开、选择、滚动与目录任务；源码 retained Entity 拥有当前路径、只读 Editor、快照与读取任务。正文挂载在工作区，与导航显隐独立，移除文件正文 Dialog 生命周期。

切换对话使用各自保留的文件树与源码实例，即使 cwd 相同也不共享。新对话从未展开、未选择且位于顶部的文件树开始；切回已有对话保留展开、选择、滚动、源码快照与正文切换状态。不在切换时重置根目录、同步缓存或刷新文件树。隐藏对话的既有读取任务仍只更新其所属实例，事件订阅按对话归属处理。关闭文件、移除所属对话或关闭窗口时释放相应源码；移除对话同时释放文件树与订阅。保留视图不改变 Pi 内容，也不持久化到磁盘；文件树定位复用按需子目录读取。

新增分栏偏好由 `gupi-settings` 拥有，单独保存会话/源码比例，默认 0.4，只接受有限且在 `(0, 1)` 内的值。该比例独立保存，不增加旧版本降级兼容逻辑。缺失、无法读取或无效的新偏好使用默认值，不阻止主窗口布局加载。临时窗口没有此分栏，不读取或写入该偏好。

松开鼠标或按 Escape 都结束拖拽，保留并保存当前尺寸或比例；未变化时不写入。窗口缩放、面板切换等非主动结束会中断拖拽，不保存，并在当前帧恢复拖拽前的原始源码比例（包括未设置状态）。比例只在用户主动结束拖拽时保存；窗口缩放、自动夹取、导航临时收窄及模式切换不写回用户偏好。窗口位置和尺寸继续用平台坐标；侧栏使用 `sidebar_width_rem` / `navigator_width_rem`，只验证有限正数。旧像素字段不迁移，旧布局文件读取失败后使用默认值，窗口位置和侧栏宽度重置一次，不影响应用启动。默认 14rem / 20rem 在 16px 字号下为 224px / 320px。

符号链接跟随目标，与 Pi 对齐；目录链接可展开，文件链接只读预览，目标可在 cwd 外。显示、身份、定位与语言识别仍使用链接的原始路径；链接图标、目标提示和不可用状态单独保留。读取不是 cwd 沙箱，循环链接仅逐层按需展开。文件读取仍限 1MiB、20,000 行、严格 UTF-8/BOM 和普通文件；单行超过 16KiB 使用纯文本。现有 tree-sitter 及其高亮限制保持，由原设计文档记录。

## 实施与验证

源码已从 Dialog 移至 retained 工作区 Entity；导航、分栏、单槽、覆盖层及独立偏好已接入。历史原有列表/树、分支范围与内容程度保持。新增命令和九种语言文案同步维护。

- Nix 开发环境的受影响测试：92 个 conversation-ui、21 个 settings 测试通过，覆盖读取边界、旧目录请求、语言映射、正式只读 Editor 与复制、分栏约束、侧栏切换与失焦兜底、输入框焦点保持、空历史的列表/树模式、消息/草稿/源码的局部查找、字号约束与重开一致性、拖拽完成后的真实落盘、布局中断的首帧比例恢复、链接目录与文件的导航/预览、失效及特殊目标、项目外目标和已有会话回归。
- `cargo check -p gupi --locked`、`cargo clippy -p gupi --all-targets --locked -- -D warnings`、开发构建与格式检查通过。
- macOS 原生离线 UI gallery 已观察到并排源码与会话草稿、只读粘贴拒绝、源码查找打开/关闭、隐藏导航保留源码、半屏单槽、导航覆盖及明暗主题。最终键盘复验确认 Enter 进入正文、源码查找、两次 Escape 依次关闭查找与返回输入框、命令面板切换会话及关闭文件；覆盖导航中的菜单与导航按 Escape 分层关闭；刷新按钮上 Escape 关闭覆盖层，停靠导航保持打开，源码工具栏上 Escape 返回输入框。[宽窗口截图](images/workspace-wide.png) 与 [窄窗口截图](images/workspace-narrow.png) 使用离线 fixture。

当前视觉细节：深色主题切换项对比和覆盖层边缘较弱；源码视图中的警告/错误通知固定展开，通知清理沿用全部清理语义。

拖拽保存测试在 conversation-ui 单元测试的独立应用上下文中配置临时布局目录，不修改进程环境变量或用户偏好；根包测试中的 HomeView 读取正常配置目录（不写入，源码比例只在打开源码时生效），运行整套验证时由外部指定临时配置目录。

拖拽修正的 macOS 原生启动通过；默认字号下，右侧导航拖到最小宽度并关闭重开，宽度保持。Escape 保存、字号边界和中断恢复由正式 HomeView 的 UI integration tests 验证。

符号链接的目录展开、文件事件、失效链接不激活和读取边界已通过正式组件与文件系统测试；本轮原生界面复验因自动化无法取得窗口（cgWindowNotFound）未完成。

本次局部查找的 macOS 原生复验通过：输入框 Cmd-F 自动聚焦其查询框、匹配草稿且不改正文，Escape 返回草稿；点击会话消息区域后 Cmd-F 打开会话正文查找。使用离线扩展 fixture，没有模型请求。

焦点精简已通过正式 HomeView 的 UI integration tests；该轮原生复验因 macOS 显示链接创建失败、自动化无法取得窗口而未完成。

实际验证使用临时配置、项目和会话，没有模型请求。覆盖导航和源码的 Escape 先于停止回复命令，依据为 GPUI 0.7.1 的上下文深度排序及命令消费逻辑；本轮未用流式回复验证，也未复测临时窗口。Windows/Linux 原生体验、非默认字号缩放、30rem 源码下长文件名/目录、15rem 历史覆盖栏、真实流式模型回复（包括 Escape 后继续流式输出）及大目录性能未验证。现有 Nix 编译器目标提示和 `block 0.1.6` future-incompatibility 提示仍存在。
