# 临时会话预热

状态：设计已确认，待实施前测量。对应 #102。

## 结果

在设置的“临时对话”组提供“预热临时会话”开关，默认关闭。开启后，整个临时窗口共享一个后台待命会话，不按模板分别预热。任何真正需要新建临时会话的入口都先尝试接管它：模板任务快捷键、临时窗口内新建会话，以及普通唤起首次需要会话时。待命未就绪、失效或不可用时，沿用当前冷启动流程，不等待待命进程补齐准备。

已有会话的普通唤起继续复用；“新建”原有的未发送草稿复用优先级不变，仅在需要创建独立会话时取用待命项。模板已有进行中或待输入任务时仍显示该任务，不消耗待命项。预热只减少进程启动和核心快照准备的等待，不承诺消除模板设置、输入捕获或模型响应时间。

## 当前流程与测量依据

普通唤起经 `src/app/temporary.rs` 复用应用持有的临时会话。隐藏 600 秒只回收窗口，不关闭会话或 Pi；首次创建仍需启动 Pi。模板任务的真正新建分支在 `src/app/shortcuts.rs` 读取输入和模板后调用 `new_draft(None)`，进入 `begin_preparation`，每 30ms 检查本地会话状态和错误，等待上限 30 秒；并非每次轮询都发送 `get_state`。连接流程负责取得并应用 `get_state` / `get_entries`，模板准备随后读取 `get_commands`、应用指定的模型和思考级别、再读最终状态并 `complete_preparation`。有输入时继续 `send_draft`。

#102 既有真实 HOME 测量中，Pi 1.4.0 加完整扩展、重复 cwd 的新进程首次状态中位数约 2 秒，完整样本最长约 8 秒；排除 CommandCode 0.3.0 后约 0.5 秒。独立剖析确认该扩展 factory 同步等待远端模型目录约 4 秒。辅助 RPC 在 entries 后约 5–8ms 完成，不代表整个 Gupi 模板准备耗时。这些数据继承工具环境代理，尚未验证 Finder 启动的网络路径，也不是原生快捷键全程测量。纯净进程约 120 MiB 的旧测量不用于本功能的设置说明。

## 设置与代价

开关放在 `src/features/settings/layout.rs` 的 `settings-temporary-storage` 分组，与“清理已释放临时对话”同组，不另建设置页。复用现有设置字段、Kit 开关、帮助文字和持久化方式；新增布尔配置缺省为关闭，旧配置文件兼容。开关与说明沿用组件主题、键盘和无障碍行为，九语言同步，不添加自绘控件、确认弹窗或常驻进度界面。

- 名称：**预热临时会话** / **Prewarm temporary conversations**。
- 说明：**后台常驻一个 Pi 进程，实测约 N MB 内存（随扩展变化），以加快新建临时会话。会提前执行扩展初始化、认证和网络请求。**
- 英文：**Keep one Pi process ready in the background to start new temporary conversations faster. It uses about N MB of memory in measurements, depending on extensions, and runs extension initialization, authentication, and network requests in advance.**

N 必须来自实施第一步中完整扩展环境的待命进程 RSS 实测，按 MB 换算并合理取整，测量环境和范围保存在本文件；不是内存上限或每台机器的保证。不在产品中动态监测内存，也不以纯净环境数字或未经测量的占位值交付说明。空闲 CPU 同时测量，用于核对常驻代价。

打开开关即后台准备，无需先使用模板快捷键；应用启动读取到已开启配置时也准备，不显示或抢焦点打开临时窗口。关闭开关或退出应用时丢弃待命项；已接管的正常会话不因关闭开关而被关闭。删除全部模板快捷键不关闭此功能，因为普通临时新建仍使用它。

## 所有权与生命周期

### 一个内部会话，复用既有连接

`ConversationState` 持有唯一待命会话身份及其 `Session`，继续使用现有 Pi runtime、binding、读取任务和临时 cwd。`Temporary` 与现有配置观察接点负责启停策略；各入口调用同一接管接点。不建连接池、第二套进程管理或按模板缓存。

将现有 `insert_draft` 的创建能力拆出不改变 `selected`、可返回创建结果的接点。后台创建不能调用 `new_draft` 后再恢复选择，也不能发出前台选择通知。每个待命项有自己的新临时目录，连接仍使用 `--no-session`；接管保留该 cwd，不移植到另一个 cwd，也不复用已进行过对话的进程。

内部待命身份必须同时从普通 `new_or_reuse` 的候选、临时导航的全量与增量投影、未读/托盘汇总和面向用户的会话通知中排除。后台失败只记录日志；扩展产生交互请求或对话内容的待命项不适合接管，丢弃并回退。原始 `sessions` 仍保留内部项用于资源所有权、退出和临时目录保护，不能将公共遍历整体改为只包含可见会话。

临时模式现有 `file` / `save_changes` 已整体排除草稿落盘，待命项遵守相同规则；不为它增加 `DraftFile` 字段。只持久化开关，不持久化待命 key、连接或预热状态。

### 原子接管与补充

接管前完成下述资源检查。进入单次 owner update 后，重新确认开关、待命身份及 binding 仍有效，并确认核心状态和历史快照已应用、连接正常、会话空闲且无正文、待处理输入或扩展交互。RPC Ready 本身不等于可以接管，也不要求额外等待所有辅助目录读取。唯一待命身份在这次更新中被消耗，转为普通选中会话并发出正常通知；模板入口在同次更新中进入 `begin_preparation`，避免其他入口抢走或重复接管。

模板继续使用本次触发读取的模板定义，沿用 `get_commands`、指定模型/思考级别、最终 `get_state`、`complete_preparation` 和原发送流程；输入捕获仍发生在窗口抢焦点之前。待命阶段不提前应用某个模板的设置。正常连接在完整快照后自动调用 `refresh_auxiliary`，其中的命令、模型等读取无需禁止，也不复制一条“精简连接”路径。

待命被用掉后，在当前会话准备完成时补一个：普通新建以核心快照就绪为界，模板任务以 `complete_preparation` 完成为界，不等待一轮模型回答结束。未就绪的待命项不阻塞前台冷启动；槽位仍被它占用时不再补充。失效回退也先完成当前冷启动准备，再补充。并发入口只能消费一次，后续入口按各自原流程冷启动，补充操作始终幂等。

预热报错或超时后记录日志并丢弃，不自动循环重试。之后重新开启开关，或下一次前台新建准备完成时，才再次尝试补充。当前准备失败不触发重试循环。

### 资源新鲜度的有限检查

待命开始前记录预热开始时间、实际启动路径和本次检查涉及的已知文件存在状态。接管前在后台读取文件元数据，与预热开始时间比较；任一相关文件修改时间较新，或启动路径/存在状态发生变化、必要元数据无法确认，就丢弃待命并走原冷启动。异步检查返回后仍需核对 owner 和 binding，不能接管已经被关闭或替换的项。不解析配置内容，不输出认证文件内容。

检查范围为：

- 模板任务本次实际使用的模板文件；普通新建无模板时不额外扫描所有 prompt。模板必须在接管前完成读取与元数据检查。
- 临时会话实际使用的 Pi agent 配置目录中，现有路径能力可定位的 `settings.json`、`models.json`、`auth.json`、`mcp.json`，以及该临时 cwd 的 `.pi/settings.json` 等现有作用域配置路径。缺省允许不存在的文件，持续不存在不算失效；原有文件消失或新文件出现须回退。普通项目 cwd 的配置不拿来替代临时 cwd 配置。
- 本次实际启动的 Pi 可执行文件路径及其解析目标。应用已知的 Pi 启动路径变化直接令待命失效；同路径文件以修改时间检查。

认证或扩展自行改写上述文件也按相同规则处理，不根据内容猜测“无影响”。若无法可靠确认某项就走冷启动，不为命中率降低检查。主题、语言、模板快捷键标题或按键等不改变 Pi 资源的设置，不使待命失效。

这不是完整的资源一致性保证：不递归监控扩展、技能、其他模板、包依赖、脚本所启动的整个安装目录、环境变量、远端目录或扩展自有配置；不识别保留/回拨修改时间的替换，也不保证文件系统时间精度、系统时钟调整和检查后再次写入的竞态。参数模板由 Pi 已加载的资源展开，`get_commands` 并不重载文件；本次模板的修改时间检查降低旧模板风险，但不能宣称接管与任意时刻的冷启动完全等价。需要强制重新加载时可关闭再开启预热。此处不新增 watcher、内容哈希缓存、Pi reload/展开协议或应用侧模板解释器。

### 最小内部丢弃接点

现有 `close` 只关进程、不移除 Session/cwd，且不能覆盖启动中取消；不直接用它表示丢弃。内部接点先使待命不可再接管，递增 binding 并取消目录准备/读取等任务，再复用 `delete_temporary` 的进程关闭、确认退出、受限临时目录回收、移除会话步骤。不能沿用会拒绝启动中状态的用户删除守卫。

目录创建的异步工作必须纳入完成/清理顺序，迟到结果不能启动 Pi 或留下失去所有权的目录。关闭中仍保留目录保护；不能确认退出时不删除目录，也不把该项恢复为可接管状态，记录错误并沿用现有退出/清理处理。开关反复变化不能使旧任务重建待命或叠加补充进程。

退出接入现有 `Temporary::drain` 与 `PiState::close_all`，不另建退出框架。现有“清理已释放临时对话”继续保护仍被会话和关闭任务持有的目录；窗口隐藏 600 秒的回收策略不改变。

## 范围与取舍

本轮不做连接期间编辑。它可能改善首次普通唤起或无输入模板的体感，但不能缩短自动发送模板等待 Pi 的时间，并会改变现有 `can_edit_draft` / preparing 的交互契约。保留 Load before render 的真实就绪约束，不伪造可发送状态、不自动排队输入，未命中时继续显示现有连接/准备状态。

本轮不发布 CommandCode 上游反馈，因为 issue 要求另行授权，而非项目禁止向 Pi 生态报告问题。Gupi 不跳过 provider、不缓存远端模型目录、不修改用户 Pi 配置。预热属于 Gupi 的连接生命周期职责；不以未经证实的参考产品预热机制作为事实依据，不给 Pi 补功能，也不为 Kit 添加绕行。

## 实现顺序

1. **先做基线与资源测量，不改产品行为。** 使用真实 HOME、完整扩展与 Gupi 桥接扩展，核对 Finder 启动环境和网络路径。分开记录普通首次创建与已有进程复用、模板上次结束后的真正新建与正在准备/待输入的复用、临时窗口内真正新建；模板再区分有输入自动发送和无输入等待编辑。记录窗口出现、核心快照应用、模板准备完成、自动发送被 Pi 接受等阶段，解释“可编辑/可发送”终点，不以空输入按钮状态或模型首 token 混代。加测同配置的待命进程 RSS、空闲 CPU 和采样时段；记录代表样本及波动，给出设置说明的 N。临时计时和探针用完删除，不保留常驻埋点。若基线与现有瓶颈判断冲突，先报告事实。
2. **接入设置与单一 owner。** 增加默认关闭的配置和九语言开关说明，复用当前设置组；建立非选中创建、内部身份排除及最小丢弃接点，保持临时会话不持久化。
3. **接入所有新建入口。** 共用后台元数据检查及原子接管，分别衔接普通连接和模板 preparation；未命中冷启动。启用立即准备，当前准备完成后补充，关闭与退出丢弃。
4. **验证并记录实际效果。** 比较命中、未就绪/失效回退和关闭状态下的原生耗时，确认补充未拖慢当前准备，更新 N 与测量结果。只执行与本次生命周期和设置变更相关的门禁与原生检查。

## 必要验证

这是连接生命周期和资源所有权变更，需要按 AGENTS.md 选择能防止实际产品失败的回归覆盖：隐藏项不能被导航、通知或普通复用泄漏；多入口不能重复接管；资源变化不能命中已知过期待命；关闭/取消后不能有迟到进程或目录失去所有权。优先扩展已有正式入口测试，不另建模拟连接框架或逐字段夹具断言。模板设置、独立 cwd 和临时不落盘继续沿用现有契约。

原生验证聚焦设置开关和三类新建入口的可见结果、命中与回退时间；设置说明须在实际窗口可读、可键盘操作，数字与完整环境测量一致。不扩大为全量 UI 验收，测量、测试和原生结果分别记录，不以其中一种替代另一种。
