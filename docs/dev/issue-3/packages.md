# 包页：已安装、浏览与详情体验

归属 [#3](https://github.com/suxiaoshao/gupi/issues/3)。目录来源、元数据字段与网络行为见 [catalog.md](catalog.md)；设置外壳与命名（S-3）见 [settings.md](settings.md)；实施切分见 [implementation.md](implementation.md)；总览见 [README.md](README.md)。

**状态：方案已确认并已实现，待试用；实施与验证记录见 [implementation.md](implementation.md#实施记录)；试用反馈的布局修正见 [implementation.md](implementation.md#试用反馈修正2026-10-08)。2026-10-08 用户同意本轮全部采用方案，并指定由 designer 开发。** 标记含义同 [settings.md](settings.md#阅读约定)。

## 用户已确认的约束（Issue #3 与本轮反馈）

- 提供包搜索、浏览和详情：可取得的来源、版本、说明，以及包内扩展 / Skill / 模板 / 主题。
- 安装、更新、移除复用现有 Pi 包管理流程。
- 所有资源类型共用一个市场，不分别建立 Skill、模板、主题市场。
- 先确定真实目录 / 注册源与元数据；不把 GitHub 搜索结果当作官方市场；不自建插件运行时。
- 自动更新、榜单、账号体系默认不纳入。
- 实施前确定资源来源、搜索 / 分页与详情元数据、已安装状态匹配和失败反馈；区分“已安装”与“当前会话已加载”。
- 参考 Zed 扩展界面。

## 核对基线

Gupi `a90a12a`、`gpui-component` 0.7.1；Zed `c770f3b182bc98fff2ec79484ab3d936a6a2f493`；Pi 文档读取本机 `@earendil-works/pi-coding-agent` 1.0.4 的 `docs/packages.md`。

## 源码事实

### Gupi 当前“插件”页

- 页面头部：标题“已安装的包” + “安装包”按钮；点击后在页内展开来源输入框（帮助：`npm:name`、Git URL 或绝对本地路径）与“安装 / 取消”（`src/features/settings/resources/packages.rs`）。Pi 未就绪时禁用并提示先配置 Pi。
- 每个包一行：来源、版本（有则显示）、按类型计数、展开按钮、位置 / 更新 / 移除图标。计数来自**本地已发现资源**（`src/features/settings/resources.rs:554` `io_counts`），只显示大于 0 的类型。
- 展开后按类型列出包内资源，每项有位置按钮与**启停 Switch**（`packages.rs` `render_package_resource`）。不属于任何包的扩展列在“独立扩展”下。
- 移除有确认对话框：“从个人 Pi 设置中移除此包？本地包来源目录会保留。”
- 操作经 `gupi_resources::pi_resources::package_action`（`crates/gupi-resources/src/pi_resources.rs:248`）运行 `pi install|update|remove <source> --no-approve`，`update` 附加 `--extension`，以最近一次资源扫描的根目录作为 `PI_CODING_AGENT_DIR` 与工作目录（`crates/gupi-resources/src/resources.rs:144`；该根来自 `pi_resources.rs:97` `agent_dir()`，即当前个人 Pi agent 目录，与会话目录发现共用环境解析），并非单独隔离的目录；失败返回 Pi 的 stderr/stdout（截断 4000 字符）。
- 成功提示：“已完成对“X”的操作。请手动重新加载现有会话。”——已体现“已安装 ≠ 当前会话已加载”。
- Gupi 当前不发起任何目录 / 注册源网络请求；README 写明“不提供包市场”。

### Pi 已有能力

- 命令：`install` / `remove` / `update` / `list` / `config`；**没有搜索命令**（`pi --help`）。
- 发现约定：npm 关键字 `pi-package` 使包可被 [Pi package gallery](https://pi.dev/packages) 收录；`pi.image` / `pi.video` 为图库预览；`pi` 清单可声明 `extensions / skills / prompts / themes`；无清单时按约定目录发现。
- 包身份：npm 按包名，Git 按去掉 ref 的仓库 URL，本地按解析后的绝对路径。
- 包来源由 Pi 解析，Gupi 不额外解释版本选择器或更新规则。

### P-1 浏览入口

- **采用**“已安装 \| 浏览”：已安装完全本地、立即可用；浏览是唯一产生网络请求的区域，边界清楚。代价：同一包在两个视图都会出现，需要一致的状态标记。
- **备选 A**（Zed，`extensions_ui.rs:290`）：一个列表，已安装与远程合并。代价：远程失败、分页与本地项混排时状态复杂；未声明内容的包在类型筛选下难以诚实处理。
- **备选 B**（独立窗口 / 主窗口页面，Zed 扩展页即工作区 Item）：浏览空间大。代价：改变入口结构，与 S-2 备选 B 联动。

### P-2 详情呈现面

- **采用**主从布局：左侧结果列表，右侧详情；窄窗口时详情占满并提供返回。理由：浏览中频繁比较，保留列表上下文；GPUI Kit 设计指南的 master–detail 外壳。代价：需要处理最小宽度。
- **备选 A**（Zed 卡片）：实现最少；代价：声明内容、来源、安装输出放不下。
- **备选 B**（Sheet）：不改页面布局；代价：遮挡列表，比较不便。

### P-5 更新呈现

- 源码事实：现有已安装页对每个包都提供“更新”（`pi update --extension <source>`），来源解析和更新行为由 Pi 处理。
- **采用**：所有已安装包保留“更新”。界面展示已安装版本、最新发布版本和完整来源，不显示固定版本或更新限制说明，也不根据版本差异显示“有更新”。
- **备选 A**（固定来源隐藏“更新”）：避免“点了没变化”的误解。代价：去掉 Pi 的协调入口，改变现有行为，需要用户确认。
- **备选 B**（Zed，`extension_card.rs:357` 版本不同即显示“更新”）：发现更新最直观。代价：对固定来源与 Git 来源给出错误承诺。

## 状态模型

| 视图 | 状态 | 呈现 |
| --- | --- | --- |
| 浏览 | Pi 未就绪 | 说明 + “打开 Pi 设置”按钮；可浏览，安装禁用（已确认） |
| 浏览 | 加载中 | 搜索框内加载指示；清除上次结果 |
| 浏览 | 无结果 | “没有匹配“X”的包” |
| 浏览 | 网络失败 | 原因 + “重试”；不影响已安装 |
| 详情 | 未安装 / 已安装 / 已配置但文件缺失 | 主按钮：安装 / 更新、移除为普通按钮，展示已安装版本和来源 / 说明缺失路径，更新与移除沿用现有操作 |
| 详情 | 操作中 | 按钮显示进行中，禁用重复操作 |
| 详情 | 失败 | 内联显示 Pi 输出 + 重试 |
| 详情 | 成功 | 状态改为已安装，提示“重新加载或新建会话后生效” |

已安装匹配以本地配置与扫描为依据，按 Pi 的包身份规则；Git、本地路径安装不按名称与 npm 结果合并。现有扫描会包含“已配置但路径缺失”的包，出现在目录中不等于安装完整。清单数组可含目录、glob 与排除项，其长度不是资源数量；资源数量只来自安装后的本地扫描，“未知”不显示为 0。
