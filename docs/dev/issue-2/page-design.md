# Pi 设置页面设计

状态：首批已实现，等待协调者验证后交付试用。范围与契约以 [首批实施方案](implementation.md) 为准，区域方向见 [设置页面与导航讨论](information-architecture.md)，字段取舍见 [字段筛选](field-selection.md)。本文记录当前界面设计。

## 导航

设置页面栏中，“设置”标题后是 `Gupi | Pi` 分段控件。两个区域各用一个 `Settings` 实例，选中页和侧栏搜索按区域分别保存，搜索只覆盖当前区域。

```text
← 设置    [ Gupi | Pi ]

Gupi 区域：通用 · 外观 · 通知 · 键盘快捷键 · 关于
Pi 区域：  连接 · 对话 · 网络 · 包 · Skills · 模板
```

- **连接**：原 Pi 页，保存 Gupi 自己的 Pi 可执行文件配置。不显示作用域，也不写入 Pi `settings.json`。
- **对话**：默认模型、上下文、消息队列、图片四组。
- **网络**：代理、重试两组。
- **包、Skills、模板**：沿用现有全局资源编辑器，标题行显示静态的“全局”，不提供作用域选择。

关于页“打开 Pi 设置”跳到 Pi 区域的连接页。资源页内部的跳转沿用原有行为，并带上目标区域。

## 标题行

对话页和网络页的标题行从前到后依次是：

1. **作用域菜单**：`全局 ▾` 或 `<项目名> ▾`。
   - 菜单列出全局和本次会话中打开过的项目。
   - 提示显示当前作用域的目标文件路径。
2. **信任状态**：仅在项目作用域、且项目未被信任或无法读取信任记录时，显示“未信任”和“信任项目…”。
3. **放弃 / 保存**：仅在本页有草稿时出现。“保存”是本页的 primary 操作。
4. **`⋯` 菜单**：打开 settings.json（文件存在时可用）、重新读取。

文件操作放在 `⋯` 菜单里，窄宽度时标题行不会因此换行。

## 字段行

字段行沿用 `SettingItem` 的左标签、右控件结构。控件后有一列固定宽度的来源文字，再后面是 `⋯` 字段菜单。

| 类型 | 控件 |
| --- | --- |
| 布尔 | `Checkbox`（按页保存，不使用暗示立即生效的 Switch） |
| 选项 | outline 下拉按钮 + 带勾选的菜单 |
| 数字 | 小号 `Input`；非负整数，非法文字在字段下提示 |
| 代理 | 小号 `Input`；清空表示不设置 |
| 默认模型 | 可搜索的 `Select` |

来源文字为 `默认`、`全局` 或 `项目`，有草稿时追加“· 未保存”。继承值保持正常可编辑样式，不变灰。

字段菜单提供：

- **撤销更改**：有草稿时。
- **设为项目值 / 设为全局值**：当前作用域尚未设置时，把当前有效值显式写入当前作用域；即使与继承值相同也保留为覆盖。
- **使用全局值 / 使用默认值**：当前作用域已设置时，保存后删除该叶字段，恢复继承。

在 Enter 或失焦时，输入只更新页面草稿，不会触发整页保存。输入与当前显示值相同不产生草稿。

| 组 | 字段 | 说明 |

| 重试 | 最大重试次数 | — |
| 重试 | 初始延迟、最大延迟（毫秒） | — |

**默认模型选择器**

- 模型列表来自专用的 `--no-session` Pi 实例：不发送 prompt，不借用用户正在进行的会话。
- 全局作用域的实例在空临时目录中启动；项目作用域在项目目录中启动，由 Pi 按自身规则决定信任。
- 读到列表后关闭该实例。
- 存储的模型不在列表中时，选择器以 `provider/id` 作为占位，并提示“此模型当前不可用”。
- 读取失败时显示原因，并提供“重试”。

**思考等级选项**

- 已知所选模型时，按 Pi 1.1.0 `getSupportedThinkingLevels` 从模型元数据计算：
  - 非推理模型只提供“关闭”；
  - `thinkingLevelMap` 中为 `null` 的等级不提供；
  - `xhigh` 和 `max` 需要有映射条目。
- 已存储但不受支持的等级作为额外选项保留并选中，标注“所选模型不支持”，不会自动改写。
- 模型未知时列出全部等级。

**项目作用域中的代理（G1）**：显示全局值文本和“在全局中编辑”按钮，不显示禁用的控件。

## 状态与错误

页面在字段组之前显示一行状态，以下状态互斥：

| 状态 | 处理 |
| --- | --- |
| Pi 正在检查 | 显示检查中 |
| Pi 不可用 | 提示去“连接”页检查 |
| Pi 低于 1.1.0 或版本无法识别 | 只显示要求和当前版本，不提供编辑 |
| 文件读取中 | 显示读取中 |
| 文件无法读取或解析 | 显示错误和“重新读取”；不当作空配置，也不覆盖文件 |
| 保存冲突 | 显示冲突说明；冲突字段下注明“读取后文件中的值已被修改”；草稿保留 |
| 文件被其他进程锁定 | 提示稍后重试；草稿保留 |
| 存在非法输入 | 拒绝保存并提示修正 |

## 离开保护

存在 Pi 草稿时，下列操作先询问“保存 Pi 设置？”，提供取消、放弃、保存：

- 切换作用域；
- 从 Pi 区域切回 Gupi 区域；
- 离开设置（返回按钮或“显示主窗口”）。

选择“保存”时保存全部草稿，成功后才继续原操作；失败时停留并保留草稿。

Pi 区域内的侧栏页面切换由 `Settings` 组件内部处理，应用无法拦截。因此草稿按字段保存在 Pi 设置状态中，切页不会丢失；返回原页后仍可保存或放弃。

## 项目入口与信任

**入口**：首页项目行的右键菜单，以及会话菜单中的“项目 Pi 设置…”。它会打开设置，切到 Pi 区域的对话页，并把作用域设为该项目的实际 `cwd`。

**信任确认**：“信任项目…”打开确认对话框。

- 标题为“信任‘<文件夹名>’？”，正文给出完整路径，并说明 Pi 将加载项目设置和资源、安装项目包、执行项目扩展，上级文件夹不受影响。
- 只有选择“信任项目”才写入；只写当前规范化目录的 `true`。目录不存在、是相对路径或不是文件夹时拒绝写入。
- 保存项目设置不会授予信任。

**信任状态的判断**：

- 只依据磁盘记录（最近祖先的明确决定，以及全局 `defaultProjectTrust` 是否为 `always`）。
- 记录无法读取时显示错误，不显示为已采用。
- 运行中的 Pi 实例与扩展的 `project_trust` 回答无法从这里确认，界面不推断。

## 键盘路径

1. 用“设置”快捷键或菜单进入设置。
2. Tab 顺序：返回按钮 → Gupi / Pi 分段控件 → 侧栏搜索框 → 侧栏页面 → 页标题行（作用域、信任、放弃 / 保存、`⋯`）→ 各字段控件 → 来源文字后的字段菜单。
3. 数字和代理输入：Enter 只结束输入，不保存页面。
4. 菜单和对话框沿用组件的 Escape 关闭与焦点返回行为。
