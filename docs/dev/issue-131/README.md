# #131 普通输入框上箭头召回

状态：已确认，行为跟 Pi 一样。核对基线：Gupi main `315a6b0`；本地 Pi `36be9c612`（1.4.0）。

## Pi 行为

普通输入框通过 `home/input_history.rs` 接入发送历史；`home/shell.rs` 的历史属于独立 Shell 输入，不合并。

依据 Pi `packages/tui/src/components/editor.ts:428,456,926`，普通输入采用以下规则：

- **Up**：位于第一视觉行，且编辑器为空、正在浏览历史或光标列为 0 时，召回更旧记录。位于第一视觉行但不满足该条件时，先移到行首；其他视觉行照常向上移动。这里“空”指真正空输入，不把仅有空格的草稿当空输入。
- **Down**：正在浏览历史且位于最后视觉行时，转到较新记录；否则在最后视觉行移到行尾，其他视觉行照常向下移动。视觉行包含软换行，不能替换为“正文开头/末尾”判断。
- 首次进入历史浏览时保留原草稿和光标，并保留撤销入口；向下越过最新记录恢复原草稿。召回更旧记录时光标置于开头，较新记录置于末尾。编辑召回内容后退出浏览；超出历史边界不循环。
- 入历史的文本先 trim，忽略空结果，连续相同项去重，最多保留最近 100 条。Pi TUI 在提交入口记录展开前文本，部分路径早于 `prompt()` 完成（`interactive-mode.ts:3313–3353`），历史不是“执行成功记录”；Gupi 同样不等待模型成功或 `data.disposition` 才记录已提交输入。
- 恢复会话时从当前上下文的 user 文本回填（`interactive-mode.ts:3939,4200`），不另存一份正文历史。模板文本在恢复后可能已经展开，与 Pi 一致。

## Gupi 接入

普通输入历史按会话隔离，浏览位置归该会话输入视图；利用已有会话消息初始化，临时会话只留内存。调用 Kit 公开 action 与输入状态，补全、IME 等输入组件已有的方向键处理优先，不截获全局按键或自算软换行几何。实现时若公开 API 不能表达上述视觉行条件，报告能力缺口，不悄悄缩减为仅空输入或按字节端点判断。

只召回可编辑文本，不重建旧图片或引用卡片；文件/技能文字沿用现有投影规则，当前未发送附件保留。浏览前的草稿保存完整 InputContent 与光标，返回时保留原 token；不修改 Pi 会话树，不自动发送。

必要验证复用真实输入框回归，覆盖 Pi 的首末视觉行规则、软换行、非空草稿召回与返回、100 条连续去重及会话恢复。无待确认产品选择；不新增历史搜索或持久化格式。

## 实现与验证

`Session.input_history` 从首次成功加载的当前路径 user 消息初始化，在提交入口记录展开前文本；浏览位置、完整 `InputContent` 草稿与光标只属于对应 `SessionView`。公开 `display_map` 提供视觉行边界；上下键动作只绑定普通 Composer 的 Input，组合输入与非空选区交回 Kit。召回使用可撤销的 `replace_all`，返回草稿恢复 token；召回斜杠文本不会打开命令面板。
