# D2 项目包与标题栏入口：界面设计

状态：已实现。实现与验证记录见 [D2 实现记录](d2-implementation.md)。Pi 的包命令、存储和身份规则见 [D2 Pi 契约调研](d2-packages.md)，本文不重复。D1 的作用域、信任和离开保护见[界面设计](interface.md)。

本文用三种标记区分结论的来源：

- **已采纳**：用户已确认的方向；
- **源码确认**：出处见 d2-packages.md，或列在本文；
- **设计推荐**：常规设计选择，实现时可按需调整。

项目信任的覆盖策略已由用户选定：保留 Pi 的扩展信任判定，命令不传 `--approve`，也不传 `--no-approve`。详见下文“信任”。

## 范围

| 内容 | 状态 |
| --- | --- |
| 包页跟随共享作用域；项目作用域下列出本项目包、过滤全局包的条目和继承的全局包 | 本文主要对象 |
| 项目作用域下从“浏览”或来源安装、移除本项目包 | 本文主要对象 |

| 包内资源在项目中的启停 | 不提供，只读显示 |

## 标题栏入口（已采纳）

| 项 | 规格 |
| --- | --- |
| 位置 | 对话标题栏右侧，**紧挨在文件面板按钮之前**：导出、刷新、项目 Pi 设置、文件 |
| 图标 | `IconName::FolderCog`（Lucide `folder-cog`，已在 gpui-kit-assets 图标目录中），与相邻按钮相同的 `chrome::button` 安静样式 |
| 悬停提示与无障碍名称 | “项目 Pi 设置 — <文件夹名>”，使用会话 `cwd` 的文件夹名，**不**使用对话标题；不加快捷键说明 |
| 动作 | 派发现有的 `ShowProjectPiSettings(cwd)`，复用已有的延迟进入、离开保护和规范化项目作用域；不新增设置界面 |
| 显示条件 | 有当前会话，`info().cwd` 非空，且不是临时对话。**不依赖** `has_actions`：新建对话还没有会话文件或实例时，`⋯` 菜单不显示，但它已有 `cwd`，按钮照常显示 |
| 不满足条件时 | 隐藏，不显示禁用状态。`⋯` 菜单中的“项目 Pi 设置…”保持现有行为 |

按钮只是现有入口的快捷方式。它不代表对话级设置，也不承诺修改会立即生效。

## 包页的作用域

- 包页加入共享作用域：标题行用 D1 的作用域菜单和信任状态，取代静态的“全局”。
- 全局作用域下，包页的行为和现在完全一致。
- “已安装”和“浏览”两个视图都跟随当前作用域。

## 项目作用域下的“已安装”列表

列表按“本项目”和“继承自全局”两组显示，与 D1 资源页一致。

| 行 | 来源 | 标记 | 可用操作 |
| --- | --- | --- | --- |
| 本项目包 | 项目 `settings.json` 中的完整条目，安装在 `.pi/npm`、`.pi/git`，或为 local 路径 | 同一身份的全局包存在时：“替换全局包” | 查看、在 Finder 中显示、移除… |
| 过滤全局包的条目 | 项目中 `autoload: false` 的对象条目 | “过滤全局包 <名称>” | 只读：查看、在 Finder 中显示；**不提供**移除，也不能被安装覆盖 |
| 继承的全局包 | 全局 `settings.json` | 被替换时：“被项目替换”；被过滤时：“在此项目中被过滤” | 只读：查看、在 Finder 中显示、在全局中编辑 |

**为什么过滤条目只读（源码确认）**：

- `remove <来源> -l` 按身份匹配，会删掉用户的过滤条目。
- 对同一身份执行 `install -l` 时，`addSourceToSettings` 只改写来源，保留 `autoload: false`。结果新安装只起过滤作用，不会作为项目包加载。

因此，项目中存在同一身份的过滤条目时：

- 该条目不提供移除；
- 该身份的项目安装被阻止，原因写在按钮旁，例如“此项目已有该包的过滤设置”。

**包内资源**：

- 项目作用域下展开任何包时，其中的资源只读显示，不出现开关（开关会写过滤项）。
- 全局作用域下的开关保持现状。

**列表的数据来源**：列表只读取文件，不启动 Pi 或 npm。项目包按 `.pi` 映射安装位置，不使用 npm 全局目录回退。

## 安装目标

- **按钮写明目标**：
  - 项目作用域下，“浏览”中的安装按钮，以及来源输入框下方的安装按钮，都写成“安装到项目 <文件夹名>”。
  - 用来展开来源输入框的按钮仍是“从来源安装…”，不写目标。
  - 全局作用域保持原有文案。
- **不另加确认框**：沿用现有的直接安装流程。写明目标的按钮和现有的包信任说明已经足够，不额外增加安全确认步骤。
- **同一身份已在全局安装（已采纳）**：允许安装到项目，这在 Pi 中是合法的项目替换。安装后，两行分别显示“替换全局包”和“被项目替换”的关系标记。
- **全局包不受影响**：项目安装与移除只改动项目设置和项目存储，全局设置和全局安装都不变。按钮与提示不能暗示会影响全局。

## 不提供项目更新

- 项目作用域下不显示“更新”，版本信息只读显示。
- 原因：Pi 的 `update` 没有项目作用域，会同时更新全局中同一身份的包。“先移除再安装”不是原子操作，安装失败时会丢失原有的包。
- 重新执行 `install -l` 能否作为仅限项目的更新，见 d2-packages.md 中的待核实项。核实前不在界面中提供。

## 信任

- **状态与入口**：沿用 D1 的信任状态和“信任项目…”操作。项目未信任时，安装和移除不可用，并说明原因：需要先信任此项目。
- **不隐式信任**：空项目、新选择的文件夹都不会被视为已信任；安装、移除和浏览都不会授予信任。
- **Gupi 的前置检查（已采纳）**：
  - 每次执行项目包命令前，重新读取已保存的信任：最近祖先的明确记录，以及 `defaultProjectTrust`。不使用页面上缓存的状态。
  - 读取结果不是“信任”时，不执行命令，界面显示需要先信任此项目。
- **Pi 的最终判定（已采纳）**：
  - 前置检查通过后，`install -l` 和 `remove -l` 既不带 `--approve`，也不带 `--no-approve`，由 Pi 按自己的规则判定。
  - Pi 会先加载全局扩展处理 `project_trust`。扩展可以拒绝，也可以让 Pi 记住决定并写入 `trust.json`，这是上游行为，不是 Gupi 写入的。
- **Pi 拒绝时**：命令失败，通知中显示 Pi 的输出。界面不把 Gupi 的前置检查结果当作 Pi 的最终结论，执行后重新读取信任状态和列表。
- **执行全局扩展**：项目包命令会运行用户的全局扩展代码。这与在终端执行同一条 Pi 命令一致；界面不另加说明。

## 操作生命周期与切换作用域

改变作用域的途径不止作用域菜单，还有对话或项目行的上下文入口、标题栏按钮、直接进入设置时重置为全局，以及“在全局中编辑”。只禁用作用域菜单不够。本节记录必须保持的不变量，不规定实现机制：可以统一拦截所有改变作用域的途径，也可以按目标保留进行中的任务。

**必须保持的不变量**：

1. **不因作用域改变而中止**：进行中的包操作不会因任何途径改变作用域而被取消或丢弃。它的进程和结果归属于开始时固定的目标，即作用域和规范化的 `cwd`。
2. **结果只归原目标**：操作完成后，只更新原目标的状态，并重新读取原目标的列表。进度、错误行和列表刷新不能出现在当前显示的其他作用域页面上。
3. **完成通知照常显示**：通知写明目标文件夹，例如“已在 <文件夹> 中安装 <包>”。它不属于错误作用域的反馈，即使当前显示的是其他作用域也照常显示。
4. **回到原目标时状态准确**：用户回到原目标时，看到的是正在进行的状态，或操作结束后的实际状态。
5. **不重复执行**：同一目标上已有操作进行时，不能对该目标再发起包操作。不同目标之间能否并行，由实现决定，前提是遵守不变量 1–4。

**其他**：

- 离开设置不会取消操作，操作完成后照常通知。
- 不提供取消，现有全局包操作也没有取消。
- 没有进行中的操作时，切换作用域后旧目标的读取结果被丢弃，与 D1 相同。

## 错误状态

| 状态 | 处理 |
| --- | --- |
| 项目 `settings.json` 无法读取或解析 | 显示错误和“重新读取”，不提供安装或移除，不把它当作没有包 |
| 本项目包已声明但未安装 | 行内标“未安装”，可以移除 |
| Pi 不可用或版本不足 | 沿用现有包页提示，指向“连接”页 |
| 命令失败 | 通知中给出 Pi 的输出，注明项目文件夹；完成后重新读取原目标的实际状态 |

## 文案

- 固定词汇：
  - “本项目”“继承自全局”；
  - “替换全局包”“被项目替换”；
  - “过滤全局包”“在此项目中被过滤”；
  - “安装到项目 <文件夹>”。
- 不写“本对话”，也不承诺立即生效。
- 安装或移除完成后，提示只如实说明已安装、已移除或已保存，以及目标文件夹；不承诺已有会话刷新后一定使用所有资源。

## 键盘路径

**包页**：作用域菜单 → 信任操作 → 已安装 / 浏览切换 → 搜索与“从来源安装…” → 本项目包 → 继承的包。

**标题栏按钮**：与相邻按钮一样，可通过 Tab 聚焦，用 Enter 或空格触发。

## UI 验收（有界，由协调者执行）

1. 项目对话中，标题栏按钮位于文件按钮之前，悬停提示是项目文件夹名。按下后打开项目作用域的 Pi 设置；新建对话尚未发送消息时同样可用；临时对话中不显示。
2. 包页切到项目作用域后，本项目、过滤和继承三类行的标记和可用操作都符合上表。
3. 使用 local 来源：
   - 安装到项目后，`.pi/settings.json` 增加条目，全局设置不变；
   - 移除后只删除项目条目。
4. 存在过滤条目时：没有移除操作，同一身份的安装被阻止，并说明原因。
5. 项目未信任时：安装和移除不可用，说明需要信任，并提供“信任项目…”。
6. 在项目 A 中开始安装，随后通过作用域菜单或上下文入口切到 B 或全局：
   - 安装不中断；
   - B 或全局的页面上不出现 A 的进度和错误；
   - 完成通知写明 A；
   - 回到 A 时显示实际结果。
7. 全局作用域下，包页的行为与 D1 之前一致。

网络安装（npm、git）的验证按 D2 范围另行安排。
