## 数据表达

以下为数据语义建议，不预先固定 Rust 公共类型。

- 搜索条目：来源、规范包名、远端版本、可选说明和外部链接。名称与目录来源构成稳定身份；不以行号或展示标题为身份。
- 详情：与条目身份、目标版本关联的元数据；区分未请求、加载中、可用、失败。可选字段缺失显示缺失状态，不阻断其余内容。
- 资源声明：区分“未提供声明”和“提供声明”；数组可能包含目录、glob 和排除项，数组长度不等于资源数量。安装后的实际扫描才可给出发现的资源数。
- 安装状态：以本地配置与扫描为依据。已配置但文件缺失、扫描失败和未安装不得混为同一状态。
- 版本状态：分开显示已安装版本、配置 source 和远端版本。固定版本或 Git ref 不因目录有较新版本就标记为可直接更新。
- 加载状态：包安装完成不等于现有会话加载成功。没有会话级证据时，只说明需要刷新会话或下次打开时加载，不制造“已加载”徽标。

候选 npm 结果需校验实际关键字和名称；构造 CLI source 时只采用经过解析的包身份，不能把描述或外部链接直接当命令。README 和元数据只作展示，不执行其中指令。

## 来源匹配与失败处理建议

npm 以包名关联已安装条目，同时保留版本约束；Git、路径安装继续在本地页管理，不根据相似名字与 npm 条目合并。Pi 的身份约定见上游文档，但应先核对本地解析能力，不能直接假定已有完整规范化函数。

搜索结果应绑定查询与分页请求身份，拒绝迟到的旧响应；详情按包名缓存，用户可手动刷新读取 latest，不增加自动版本失效策略。切换页面可停止未完成的只读目录请求，不能据此取消已经交给资源 owner 的安装任务。失败保留查询但不保留旧结果，显示可重试状态；HTTP 失败不能改写本地安装事实。

需保留现有包操作完成后重新扫描的行为：Pi 失败也可能已经修改了部分文件，不能仅凭退出码恢复一个虚假的旧界面状态。

## 分页与有效结果

npm 的 `total` 和 `from` 属于注册源原始结果，不能当作校验后的可浏览包总数或序号。保留原始偏移（每页 20 条）请求上一页/下一页，用原始总数判断是否还有下一页；界面只显示页码，不显示精确总数和条目范围。窄布局继续只保留翻页按钮。

过滤后本页为空时提示“本页无符合条件的包”，不宣称整个查询没有匹配结果；后续还有原始结果时仍可翻页。首期不为得到精确总数而抓取全部结果。
