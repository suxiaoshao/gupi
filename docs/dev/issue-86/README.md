# Diff 阅读器与工作区改动

状态：已实现，原生验证范围与限制见文末。对应 [Gupi #86](https://github.com/suxiaoshao/gupi/issues/86)。本页记录当前设计、实现与实际验证。

## 决策

扩展现有右侧工作区 Changes 视图，复用文件导航与 GPUI Kit `Diff`，让用户读清修改、定位文件并在外部编辑器继续工作。增加实际 Git 工作区来源，与 Pi 每轮工具记录共用阅读器，始终标明来源。

全程只读。不提供 stage/unstage/revert、commit/push/PR、评论、worktree 管理或终端；不经 Pi `bash` 获取 Git 数据，不写 Pi 会话。遵循 [职责边界](../../gui-boundary.md) 与 GPUI Kit Coding/Design Guides，不升级依赖或另写 diff 绘制器。

## 入口与来源

保留现有回复卡片打开指定轮次 Changes 标签的入口；在工作区 launcher 增加“工作区改动”，打开当前会话 cwd 所属仓库的独立 Changes 标签。同一会话内复用该工作区标签，既有轮次标签继续独立保留。

| 来源 | 含义与展示 |
| --- | --- |
| 本轮改动 | Pi edit/write 工具记录，保留轮次标题、时间与已有操作回退；只反映记录的修改，不声称是仓库状态 |
| 工作区改动 · 未暂存 | index 与工作树之间的差异 |
| 工作区改动 · 已暂存 | HEAD 与 index 之间的差异；无提交仓库按 Git 的空基线语义处理 |
| 工作区改动 · 未跟踪 | 未被跟踪且未忽略的路径；可读文本按新增内容展示，明确标为未跟踪 |

工作区标签用来源选择控件切换后三类，标题/工具栏持续显示来源。一个文件同时有 staged 和 unstaged 修改时属于两份不同差异，身份包含来源，不能合并或共享选区。切换来源先显示相应加载状态，不把上一来源的正文暂当新来源。非仓库、Git 不可用和查询错误分别提示，不回退成 Pi 轮次记录。

## 阅读与操作

- 复用虚拟文件 navigator：状态文字/图标、路径、增删数，重命名显示旧路径到新路径。未知或不适用的统计显示不可用，不伪造 `+0/-0`。搜索过滤路径，选择即跳转；上一/下一文件按当前过滤集合移动，边界禁用，不循环。过滤后若原选择消失，明确选择首个实际结果；无结果显示空态。
- 保留一次阅读一个文件的布局，避免为大仓库同时构造所有正文。当前文件工具栏有上一/下一、阅读方式、换行及更多操作；不增加另一套侧栏。
- 统一/并排为阅读偏好；正文区域窄时实际采用统一，变宽后恢复偏好。按 diff 内容可用宽度而非整窗宽度判断，工具栏如实显示窄宽生效状态，不改写用户偏好。阈值在真实组件中验证，模式变化不重建不变的源数据。
- 字内差异默认开启，自动换行可切换；沿用 Kit 语法主题、行号、选择、复制和滚动。键盘动作只作用于当前 Changes 区域，不抢占 composer 输入。
- 展开上下文使用 Kit disclosure。“折叠全部/展开全部”作用于当前来源的文件正文；文件头和导航仍可选择。由于正文按需加载，尚未加载文件只记录折叠意图，不因此批量读文件。选中一个已折叠文件时显示明确的展开入口，不暗中取消“折叠全部”。上下文展开与文件折叠是两种独立状态。
- 提供复制路径、复制 patch、复制当前可用版本内容及选区复制，标签明确复制对象；删除文件可复制原版本。无法得到完整内容时，不把片段当完整内容复制。
- “在外部编辑器打开”指向实际存在的工作树文件，通过现有平台打开能力；已删除/历史文件不存在时禁用并解释。原版本、已暂存或历史快照与磁盘可能不同，不能把打开当前文件描述为打开该快照。不新增编辑器安装管理或持久临时文件。
- 二进制显示状态和路径，不进行文本解码；仅改名显示路径变化；删除显示旧侧；未跟踪文本显示新增侧。冲突、子模块/特殊文件显示明确的只读状态，不暴露 Kit 冲突解决操作。
- 大文件/超长行/输出超限显示原因与可用的外部打开入口；不静默截断 patch 后交给解析器。加载失败提供局部重试，其他文件仍可读。新增文案覆盖全部 locale；图标、选中态、禁用态、tooltip 和焦点沿用组件及主题 token。

## 所有权与数据流

### 读取层：`gupi-resources::git`

复用 #85 的 `discover`、规范化 `Repository` 和私有系统 Git 进程执行边界，增加语义化的“读取改动清单”和“读取指定来源/文件内容”接口。接口返回路径、状态、可用统计与正文结果，不引用 GPUI、`DiffState` 或 Pi 会话。按需拆为 `git/changes.rs`，不公开任意命令执行器。

- Git 通过参数数组、指定 cwd、后台任务执行；沿用取消、超时、stdin 关闭、子进程回收及环境隔离。status 使用稳定的 porcelain/NUL 格式；name-status/numstat 采用 NUL 路径协议，正确处理 rename 双路径、空格、Unicode 和换行，不能按空白分割路径。文件路径参数使用 literal pathspec，避免 `[`、`*`、前导 `-` 改变查询含义。
- 差异读取明确禁用 external diff 与 textconv（`--no-ext-diff --no-textconv`），禁用颜色/pager；不运行用户 diff driver，不刷新或写 index，不读取 ignore 之外的未跟踪全集。未暂存/已暂存分别读取正确的左右版本，已暂存右侧绝不能用当前磁盘内容代替。
- 清单先于正文；大清单、numstat 和正文读取都有明确的容量/时间边界。超过边界返回“部分清单/过大/不可用”状态，UI 显示限制；不能将有限结果宣称全部，也不能先把无界输出收进内存再判断大小。具体容量按代表仓库和 Kit 实测确定，并作为读取策略集中定义。
- 未跟踪文件按需读取，遵守相同大小/编码判断；符号链接按链接对象展示，不跟随链接读取仓库外目标；删除不尝试读取缺失的工作树文件。保留路径身份与展示文本的区别。
- 工作树不是事务快照：清单和正文携带读取代次，正文读取时核对选定条目的源标识/版本；文件变化或消失时作废该条目并刷新，不将不同版本的 metadata、统计和正文拼成一份确定快照。对读取期间再次变化给出可重试状态，不无限追赶修改。

### UI 层：Changes 标签

`来源 → 真实文件清单 → 选定文件的真实正文 → 阅读模型 → Kit DiffState`。

Changes 标签拥有来源、查询任务/代次、清单、选中文件、过滤词和阅读偏好。仓库描述由工作区来源持有，按当前 cwd 调用 resources 发现；不依赖标题栏缓存 HEAD，也不为 diff 重复实现 Git 子进程。关闭标签/窗口、切换目标后取消任务，旧结果必须核对标签、来源、路径和代次后才可回写。

Pi 轮次适配器继续消费 `EditedFiles`/`ToolIndex`，保留当前历史路径的 in-scope 判断及无法合成净改动时的逐操作回退。工作区适配器消费 Git 返回值；两者转换成阅读器所需的文件描述/正文类型，不给 `EditedFile` 塞入伪造的 Pi operation ID。来源相关信息留在适配器，共用导航、布局和 DiffBlock。

首次打开没有伪造文件、统计、空 patch 或默认版本：清单成功前是加载态；文件正文成功前是该文件的加载态；仅成功的空清单显示“没有改动”。同一来源刷新可保留明确标为刷新中的旧快照，失败时标记未更新；换来源/cwd不能借用旧快照。

打开工作区标签、用户刷新、窗口恢复活动时读取；仅可见工作区来源做合并的低频刷新，隐藏/关闭停止。可以用现有 Pi 状态变化触发刷新，但 Git 才是工作区事实来源。正文按源版本缓存并限制保留量；不变正文保留组件实体、滚动和选区，变化后明确失效。列表与工具栏从同一已应用的结果计算，不依靠额外重绘修正选择或启用状态。

### Kit Diff 接入

已核对锁定的 Kit 0.8：`DiffState::set_mode`、`set_inline_unit`、`set_context_lines`、`expand_unchanged`/`collapse_unchanged`、`set_file_collapsed`，以及 `Diff::soft_wrap`、文件头组合接口可复用。现有 `DiffBlock::render_reader` 隐藏组件文件头，需要由工作区文件头提供折叠/展开入口并调用状态接口，不能只改一个布尔值而不影响正文。

Kit 只能展开已提供的源行。Git 单文件正文可按需取得受限的完整上下文，再由 Kit 折叠；若使用局部 patch，扩展读取成功前保持加载状态，不能把不存在的上下文画成空行。Pi 记录仅含局部 patch 时标明“记录仅包含这些上下文”，不读取当前磁盘补成过去版本。全文不可用时禁用对应的全文展开/复制操作，保留真实片段和已有回退。

- 阅读与所有权回归：来源切换/过期结果、加载与真实空态、过滤后的稳定选择和前后文件、窄宽统一与偏好恢复、word/wrap/context/collapse、不同版本的选区与复制；保留 Pi 净改动与逐操作回退测试，证明不会拿磁盘内容补历史。
- 组件与原生：在真实调度结果帧检查选择及按钮状态，不用额外强制重绘掩盖延迟；鼠标/键盘导航、复制和外部打开，浅/深色、窄区域、长路径与大文件状态。原生受阻时准确记录已验证范围，不用构建或无头测试代替交互验收。
- 完成受影响 resources/UI/root 的格式、检查、针对性测试与 Clippy，构建并必要启动。记录实际结果及平台限制，不将本设计视为已实现或已通过验收。

### 读取与保留策略

- 每个 Git 子进程最多 5 秒；stdout 最多 2 MiB、stderr 最多 64 KiB，读取时即限制并在超限/取消时回收子进程。清单最多 5,000 项；超限显示不可用，不将截断结果交给解析器或宣称完整。
- 单侧文本最多 1 MiB、50,000 行、单行 16 KiB；Pi 工作区正文也使用这套文本限制。Git patch 另受 stdout 上限约束。二进制、特殊文件、冲突和超限正文显示状态；外部打开根据真实工作树文件是否可用独立决定。
- Git 标签最多保留 8 个文件正文；Pi 标签最多保留 16 个文件阅读模型，只为当前文件构造正文，逐操作回退每页 3 项。切换 Git 来源清空上一来源正文，保留各来源阅读偏好；未变源版本保留 DiffState。
- 并排模式最小正文宽度为 48rem，以实际 pane allocator 的 `main_width` 判断；窄时采用统一、扩大后恢复并排偏好。折叠全部为默认意图，单个文件可显式展开，尚未加载正文不会因此批量读取。
- Pi 记录没有完整版本时禁用全文上下文/全文复制；无法合成文件净 patch 时不把任意一条操作当作文件级 patch 复制，保留原有逐操作展示与操作自身的复制入口。外部打开仅打开当前磁盘文件，不补齐历史版本。
