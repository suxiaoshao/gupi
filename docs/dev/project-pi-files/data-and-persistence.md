# 项目文件、来源与保存契约

状态：开发方案。以下“当前”来自源码；“计划/要求”是待实现契约，不表示已经实现。适用范围见 [README](README.md)。

## 目录与对象身份

- `agent-dir` 是 Pi 全局目录；`cwd` 是用户选择的实际项目目录；项目配置根为 `cwd/.pi`。不得把 cwd 自动提升到 Git 根，也不得通过改变 PI_CODING_AGENT_DIR 把项目伪装成全局。
- 现有 `pi_settings::Scope` 可作为作用域基础；资源操作必须持有发起时的目标作用域和文件身份，不在异步完成时从当前 UI 重新获取目标。
- 同一目录的多个对话共享项目文件。项目文件状态由设置/资源能力管理，不在每个会话内复制可写配置。
- 目录选择要求现存目录。规范化路径用于身份去重，界面保留可识别目录名和完整目标路径。不存在 `.pi/` 是正常空状态，选择/查看不创建目录，首次明确创建或保存才建立需要的父目录。

因此，正常启用且可信的 `.pi/` 自有 Skill/Prompt 相对于同名全局资源具有更高优先级，但不能据此宣称该资源在当前会话“一定生效”：CLI 输入、扩展、祖先 `.agents/skills` 和资源过滤可能改变候选集。祖先 `.agents/skills` 虽带项目元数据，却不属于本项目 `.pi/` 编辑范围。

D1 展示配置来源和已知的同名关系，避免伪造完整运行时有效资源列表。未信任时展示原始项目文件并提示未加载；不能把项目同名文件标成已覆盖正在运行的全局资源。

## 当前实现与需要变化的边界

当前 `gupi-resources::pi_resources::Catalog.root`、`scan(root, agents, env)` 和 `ResourceController` 按全局资源设计。`save_text(path, text, create)` 创建用 persist_noclobber，更新用原子替换；当前通用更新并不比较编辑基线。`Resource` 的 editable 标志不能替代执行写入时的目标校验。

计划在既有能力内显式表达：

- 扫描上下文：agent-dir、项目 cwd（若有）、作用域及信任信息。
- 条目来源：项目自有、全局、包或外部路径；声明路径与解析后的实际路径；可写原因。包资源和全局条目不因进入项目页面变为可编辑。
- 加载与操作结果携带上下文身份/代次。切换项目后旧读取可以取消或忽略；旧保存仍只操作原始目标，结果不能发布成新项目的成功反馈。
- UI 只有一个作用域选择的来源；PiConfig 和资源 controller 不各自独立改变项目。现有资源操作完成后仅更新/刷新其所属上下文。

无需引入通用资源平台或复制 Pi 的运行执行器。文件扫描只读文件和元数据，不 import 扩展、不执行引用命令、不启动 Pi 来证明“没有资源”。不完整或无效配置产生明确错误，不能按空配置重写。

## D1 文本读写

1. **只读打开**：项目页允许查看未信任文件，保留来源/未加载提示；不自动授权、安装依赖或执行文件。
2. **创建**：沿用文件名校验；Skill 创建 `skills/<name>/SKILL.md`，模板创建 `prompts/<name>.md`。SYSTEM/APPEND 使用固定名称。写入必须不覆盖现有文件；竞态下发现已存在则保留草稿并报告冲突。
3. **编辑**：草稿绑定打开时的文件与作用域。保存目标不能随全局/项目选择移动。计划记录打开时内容基线，保存前重读；被删除或外部修改时不静默覆盖，保留草稿并允许重新读取/取消。该比较只能检测已经发生的变化，不宣称对任意不协作编辑器具有严格事务互斥。
4. **持久化**：沿用同目录临时文件和原子替换，明确 I/O 错误。写入成功再更新展示值；失败不能清除草稿或显示已保存。
5. **删除**：只作用于明确选中的项目自有对象，确认展示名称/路径。不得把删除 Skill 文本扩大成无提示递归清空其支持文件；当前扫描将 SKILL.md（或根级 Skill .md）作为 Resource.path，删除将该文件移入废纸篓，不删除整个 Skill 目录；D1 保持这一单位并在 UI 上明确。删除项目 SYSTEM/APPEND 后恢复全局同名文件的回退关系，写入空字符串不等于删除。Pi 先选项目文件再读取；system-prompt.ts 的 customPrompt 为空时使用内置提示词分支，不会因此回退读取全局 SYSTEM。空 APPEND 同样不恢复全局 APPEND。保留空文本保存能力，不新增禁止空白的校验。
6. **路径所有权**：D1 推荐对解析后位于项目 `.pi/` 外的路径/符号链接只读；创建时检查父目录，写入时重新校验，避免通过项目页无意修改全局或其他项目。不能只用字符串前缀判断目录归属。严格抗恶意文件系统竞争不在本方案中作保证。
7. **settings 文件**：D1 不改新增资源路径数组/过滤器，现有 settings 叶写入继续走已实现锁与冲突检查。创建目录内默认发现文件不需要擅自登记到全局 settings。

继承来源跳到全局编辑要先保护资源草稿与 Pi 设置草稿。不同编辑器保留现有保存行为，统一的是离开时的“保存/放弃/取消”目标及失效结果隔离，不是强行合并成跨文件事务。多份草稿如涉及多个文件，应分别处理失败，不能承诺全有或全无。

保存只承诺目标文件持久化成功；当前会话是否使用变化由 Pi 重新加载/连接及已有会话参数决定。不得自动重连或用写配置替代 runtime setter。

## D2 包操作设计前提

当前 `package_action` 设置 PI_CODING_AGENT_DIR=root 且 cwd=root，没有 --local，不能直接给它传 `.pi` 作为项目模式。

- 保留真正的全局 agent-dir，独立传项目 cwd；逐个核对 install/update/remove 的本地作用域参数与结果。不可假定一个 `--local` 开关可机械套到全部命令。
- 操作目标是项目 settings 中包声明，安装位置由 Pi 负责。保持 Gupi 管理交互、Pi 负责包安装/加载的边界。
- Pi 文档说明同身份项目包通常替代全局包；`autoload:false` 项目条目可能是过滤 delta，不是独立安装包。npm 按包名、git 按不含 ref 的仓库地址、local 按解析后绝对路径去重。
- 未信任项目的读取/编辑与安装/执行分开；新增安装操作需明确项目目标与信任前提，不得以 --no-approve 当作授予信任。
- 验证安装不会写错全局声明、不会删除全局安装、取消/失败保留正确状态；D2 数据和 UI 方案应在这些契约核对后补齐。

这些是待落实的 D2 条件，不宣称项目安装已可直接开发。MCP 文件、认证和实时连接查询不随包管理加入。
