# 选中文本引用到输入框

当前设计采用 **B：输入框外的引用附件区**。选中后自动弹出工具条加入引用；正文继续使用普通 Textarea，每条引用是一张附件卡片，可附可编辑的评论，发送时才组合成普通文本。本文是改造后的目标契约，不代表附件区已经实现或验收。

## 目标与边界

从对话正文、现有只读源码或差异中选一段，把**当时显示的内容快照**加入当前会话的引用附件，可为每条引用附一段评论，也可在正文中写问题。引用动作不发送消息、不执行工具、不读取磁盘补全。标题明确注明“选中时的内容”，不将快照冒充最新文件。

以 Codex 桌面版 Add to chat / Comment 为能力上限：使用选区浮动工具条、附件呈现、快照语义和每条引用的可编辑评论（对应 Codex 回答批注的 optional comment）；引用原文不可编辑。不做富文本输入框、原文编辑、Codex 的 More details / Ask in side chat / Edit（模型改写文件）、专用 diff 评论编辑器、`:codex-annotation`、出处回跳、批注线程、自动修改文件或 PR 评论同步。不按坐标重新读内容，不监听或检测来源变化；路径、行号和侧别只是来源说明。

Pi 仍只收到现有 `prompt.message` 普通文本及既有图片附件，不增加 RPC 或 Pi 会话元数据。历史使用 Pi 保存的普通用户消息和现有 Markdown 渲染，不重新投影为引用 chip。富文本输入框另行研究，不是本功能的前置条件。

## 入口与公开 API

依据锁定的 `gpui-base` / `gpui-component` **0.8.0**；下列路径相对各 crate 的 `src/`，不是对后续版本的假设。

| 来源 | 可用公开接口 | 取值与限制 |
| --- | --- | --- |
| 对话正文 | `TextViewState::selected_text()`、`selected_source_range()`、`rendered_text()`；`text/state.rs:407–421`。Gupi `home/messages/markdown.rs` 已保留 `Entity<TextViewState>`。 | 取当前这一个 Markdown 正文的选中文本，沿用当前默认 `SelectionFormat::Plain`，不重新解析消息、不用字符串搜索定位重复片段。角色从拥有这段正文的消息取得。`selected_source_range` 只在精确映射存在时可用，本功能不依赖其推算文件行号。 |
| 只读源码 | `EditorState` 是 `InputBaseState<EditorMode>`；公开 `selected_range()`、`selected_text()`、`text()`。见 Base `input/base/state.rs:3344,3996`；组件 `input/editor.rs:109` 的 `context_menu`。 | 对 `home/source.rs::Preview.editor` 的已加载文本取 UTF-8 字节范围和内容；行号按该文本中的逻辑换行计算，一基、末端不包含下一行。保留部分行，不扩成整行。折行显示不改变行号。只读不妨碍选择。 |
| Diff 行号选区 | `DiffState::selected_lines()`、`selected_text(cx)`、`DiffEvent::{SelectionChanged,SelectionEnded}`；`diff/state.rs:79,508,723`。`DiffLineRange` 公开 path、side/start、end_side/end（`diff/document.rs:66–108`）。 | 支持同一文件、同一侧的行号选区；行号为一基闭区间，正文由 Kit 返回，不包含 gutter、`+/-` 或批注。以 Gupi 已加载对象的真实路径和来源作标题，不使用 Git 文本适配器内部的占位文件名。 |

**Diff 的明确限制：**字符拖选可以通过 `selected_text(cx)` 得到文本，但精确源范围/侧别提取位于私有 `diff/selection.rs::selected_source_range`，`DiffState::selection()` 也为 `pub(crate)`；字符选区不能假定同时有可靠 `selected_lines()`。跨旧新侧的行号选区虽然有两个端点，返回正文可能混合两侧且没有符号，不能标成“新侧”或“旧侧”。首版只启用**单侧行号选区**；其他 Diff 选区提示“请从行号选择同一侧的内容”。不按鼠标 X 坐标猜侧别，不匹配文本反推位置，不复制依赖私有实现。若要求所有字符选区都携带精确侧别/行号，需要先有上游公开接口，不能以当前 API 宣称完整支持。

对话首版限一个正文 TextView 内的选区，不将跨消息选择拼为一个虚构角色。源码多光标不组合为连续选区。Diff 的纯文本 fallback、二进制、超限或无法读取状态没有可靠的文件侧别/行号，不提供该入口；仍保留已有复制能力。Pi Changes 和 Git 的正常 DiffBlock 共用入口，出处语义分别来自各自拥有者。

## 入口、捕获与目标绑定

统一操作名为“引用到输入框” / “Quote in composer”与“评论…” / “Comment…”。主入口是**选区浮动工具条**；选区右键菜单保留“引用到输入框”作为备用，命令面板保留键盘入口。不加专用快捷键。

### 浮动工具条

```text
              ┌────────────┬──────────┐
              │ 引用到输入框 │  评论…   │
              └────────────┴──────────┘
      ……被选中的文字被选中的文字……
```

- **出现：**在对话正文 TextView、只读源码 Editor、Diff（单侧行号选区）中，选区结束（指针松开，或键盘 Shift 选择后的 keyup）且选区非空时出现；拖选过程中不出现，没有出现延迟或动画（同 Codex）。
- **消失：**在工具条外按下指针、选区折叠或变化到不支持的来源、Escape、窗口失焦、会话切换、来源组件卸载时立即消失。滚动时跟随选区重新定位；选区离开可见区域时隐藏。
- **定位：**锚点为选区首个可见行矩形的水平中点；工具条底边位于其上方 0.5rem。左右距所在区域可见边界不足 0.5rem 时向内夹紧；上方空间不足时放到选区下方 0.5rem。浮层只在该区域内定位，不覆盖标题栏和输入框之外的窗口 chrome。
- **样式：**容器使用 Kit 弹层背景 `popover`、`border` 1px、`radius_lg`、大阴影；内部为横向分段按钮，`ghost`、`xsmall`，文字 `text_sm`，按钮间以 1px `border` 竖线分隔（同 Codex 的 segmented 工具条）。颜色、圆角、间距全部使用主题 token 与 rem。
- **按钮：**“引用到输入框”添加引用并聚焦输入框末尾；“评论…”添加引用并立即打开该引用卡片的评论编辑。两者都在执行前清除来源选区。
- **禁用：**Diff 字符选区或跨旧新侧选区时，工具条照常出现但两个按钮禁用，tooltip 说明“请从行号选择同一侧的内容”。草稿不可编辑、扩展问答占用输入框或 Shell 模式时同样禁用并给出本地化理由。不退出 Shell、不写扩展问答、不新建或切换会话。

### 捕获与绑定

复用 `home/quote.rs` 的捕获、格式化、来源信息和一次性目标 key/binding。工具条显示时即生成快照（捕获发生在任何按钮、菜单或命令面板接管焦点前）；流式更新不改变这次快照。执行时再次核对目标会话和可编辑状态，失效则取消，不能把引用放到另一会话。一次性载荷执行后释放；成功添加的附件转由会话草稿拥有，不建立全局“最近引用”缓存。

添加后显示该会话的输入区域，必要时通过既有入口从工作区单区前景返回对话；“引用到输入框”聚焦 Textarea 并保留其文字、token、光标和选择；“评论…”打开新卡片的评论编辑。不插入占位字符，不改分隔比例，新卡片滚动到可见位置。引用不修改 Textarea，也不强行提交或清除 IME 组合。

## 会话数据与所有权

每个会话的草稿拥有按添加顺序排列的 `QuoteAttachment`。会话切换只显示对应草稿，不转移或重抓引用。每条附件包含：

| 字段 | 契约 |
| --- | --- |
| `id` | 稳定附件身份，用于呈现、删除和提交快照；不使用数组下标或路径作为唯一身份。 |
| 原文快照 | 捕获时的完整已加载选区，保留换行和缩进，不在发送时取最新内容。 |
| 来源标题 | 添加时按当前界面语言形成的完整标题，包含“选中时的内容”；之后切换语言不改这条引用的标题或正文。 |
| 来源类型 | 对话角色、文件、Git 来源组或 Pi 本轮改动，用于格式化与来源展示。 |
| 路径、行号、侧别 | 文件和 Diff 保存已知真实路径及一基范围；Diff 保存旧/新侧与 Git 来源组。对话无文件路径/行号，不伪造。 |
| 语言 | 来源已有的代码语言信息，可空；只用于围栏展示。 |
| 评论 | 可选，用户可随时编辑；空字符串等同无评论。原文快照不可编辑。 |

路径显示优先相对于捕获会话 cwd，不能相对时使用绝对路径；保留足够来源信息以解释路径，不随当前窗口 cwd 改写。路径中的控制字符使用可区分的显示形式。坐标不是读取凭证，来源删除、移动、会话内容刷新或 diff 消失均不使已添加快照失效。

重复添加保留为不同附件，不去重、不合并、不支持排序。附件增删属于草稿变化，纳入既有 revision、保存与发送生命周期；Popover 开关等展示状态由 UI 拥有，不持久化。

## 附件区、卡片与评论

复用 composer 现有 `AttachmentGroup` / `AttachmentView`（`small`）：引用卡片与图片、文件附件在同一行，按添加顺序排列，超出宽度沿用附件组的横向滚动。每条引用一张卡片（不合并为 Codex 的 “N selections” 单一 pill），因为每条都可单独评论和删除。

```text
┌───────────────────────────┐
│ 先检查请求是否已经取消。  │  原文前 3 行：text_xs、muted_foreground；
│ 然后再提交状态更新。      │  文件/Diff 用等宽字体
│ …                         │
├───────────────────────────┤
│ ❝ 助手回复          💬    │  来源短标题，单行省略；有评论时显示评论图标
└───────────────────────────┘  删除按钮沿用 Attachment 的右上角删除
```

- **短标题：**对话为“你的消息 / 助手回复”；源码为“app.rs · 12–14 行”；Diff 为“app.rs · 旧侧 · 12–14 行”。完整路径与来源在 tooltip 和弹层中可读。
- **打开：**点击卡片或键盘聚焦后 Enter/Space 打开 Kit Popover，锚在卡片上方，最大宽 20rem（不超过可用宽度），最大高 20rem；不依赖悬停。一次只打开一个。

```text
┌─────────────────────────────────────┐
│ src/app.rs · 12–14 行 · 选中时的内容 │  text_xs、muted_foreground
│ ┌─────────────────────────────────┐ │
│ │ if cancelled {                  │ │  原文只读，可选择复制，内容多时
│ │     return;                     │ │  仅此区域滚动；代码等宽，对话为
│ │ }                               │ │  普通文本，不加载 Markdown 资源
│ └─────────────────────────────────┘ │
│ ┌─────────────────────────────────┐ │
│ │ 添加评论（可选）…               │ │  Textarea，自动增高，最多 6 行
│ └─────────────────────────────────┘ │
│ [删除引用]            [取消] [保存]  │  删除：ghost + danger；保存：primary
└─────────────────────────────────────┘
```

- **评论编辑：**⌘↩ / Ctrl+↩ 保存；Escape 取消本次修改并关闭，焦点回到卡片。允许保存空评论（即无评论）。评论编辑框的撤销只作用于其自身文本。
- **删除：**卡片删除按钮与弹层“删除引用”等效；删除后关闭弹层，焦点移到相邻卡片或 Textarea。删除不进入正文撤销栈，误删需重新引用。
- **其它：**正文输入、发送、会话切换不留下指向旧附件的弹层。Popover 开关与评论未保存的编辑态属于 UI，不持久化。

## 发送与格式

所有发送**会话草稿**的路径在同一提交边界取快照，组合“按添加顺序的引用块（每块后紧跟其评论）+ 草稿文本”。普通发送、临时窗口 `send_draft`、运行中的 steer/follow-up 或队列、模板草稿均不能各自拼接或遗漏引用。模板/技能等已有正文处理保持语义，引用在其正文准备完成后追加，不作为模板参数或命令名再次解析。已有图片附件仍走原路径。

非草稿的显式命令输入不隐式挪用当前会话附件；模板或队列只消费它们所属的草稿快照。队列捕获组合后的普通文本，后续编辑或重试不能重复追加引用，也不能把另一份草稿的引用带进去。

只有引用、没有正文时**允许发送**，仍须满足既有连接、模型、草稿可编辑和提交条件；不能继续仅凭 `draft.text().trim().is_empty()` 禁用发送或忽略草稿保存。引用不自动发送，也不绕过 Pi 状态限制。

提交被拒绝或失败时保留正文、图片和引用，可由用户继续编辑或重试。成功指现有发送入口接受该次提交（或既有队列接纳），不是等待模型完整回答；成功后消费该次快照的引用和正文，沿用 revision/身份保护，不清掉提交期间新产生的草稿。模型稍后返回错误是会话内容，不把已经发送的引用自动重新加入草稿。

组合时保留正文原有内容，只补足相邻段之间的空行。无评论的引用不输出评论行。重复引用按原顺序逐条发送。标题注明“选中时的内容” / “Content at selection”；对话使用真实角色与 Markdown 引用块，文件/Diff 使用来源标题和围栏代码块：

````text
助手 — 选中时的内容：
> 先检查请求是否已经取消。
评论：为什么要先检查？

文件 — 选中时的内容：src/app.rs，12–14 行
```rust
if cancelled {
    return;
}
```
评论：这里是否有竞态？

这三处都要改吗？
````

````text
Assistant — Content at selection:
> Check whether the request was cancelled first.
Comment: Why check this first?

File — Content at selection: src/app.rs, lines 12–14
```rust
if cancelled {
    return;
}
```
Comment: Could this race?

Do all three need changes?
````

Diff 标题例如“Git · 已暂存 — 选中时的内容：src/app.rs，旧侧，12–14 行” / “Git · Staged — Content at selection: src/app.rs, original side, lines 12–14”。Pi 使用“本轮改动” / “Turn changes”。Git 来源组和旧/新侧按已加载版本解释，不把 index 或历史内容称为当前磁盘文件。

复用现有角色/来源格式化与 `messages/presentation.rs::code_fence` 避碰规则。每一逻辑引用行加 `> `；代码缩进不 trim，语言未知时省略，代码内容不标成 `diff`。不生成 `@` token、特殊协议标记或自动读文件指令。模型可以凭来源自行用 Pi 工具核对最新文件，但 Gupi 不保证模型会核对，也不替它做变更检查。

## 草稿保存与历史

**已确认：普通会话重启后保留引用卡片和评论。** `DraftFile` 增加可选的引用快照列表，旧文件缺少字段时默认为空；保存原文、评论、稳定身份和来源信息，而不是仅保存路径/坐标。只有引用的草稿也保存。恢复时不访问来源文件、不重算内容；文件已经变化或删除仍展示原快照。现有 A 格式的旧文字草稿保持文字，不尝试识别并转换为附件。

临时会话继续不落盘；仅在其既有会话生命周期内保留引用，不因附件引入新的保存或后台驻留机制。删除附件及成功发送同步普通会话的草稿保存，避免重启恢复已经消费的条目。

Pi 保存的是最终普通文字，历史按现有 Markdown 显示引用块。历史不保存附件 ID、不恢复 chip、不新增引用索引。草稿的结构化附件数据仅服务发送前桌面交互。

## 边界、本地化与无障碍

引用完整的已加载选区，不新增模型 token 限制，不静默截断。源码和 Diff 继续受原有加载上限约束；二进制、超限、读失败、空选区及无可靠 DiffBlock 不提供入口，不改成整篇复制。流式对话只保存捕获时已经显示的部分。不在 render 或鼠标移动时反复序列化大快照；Popover 的显示高度限制不改变发送内容。

九语言 `de/en-US/es/fr/ja/ko/pt-BR/zh-CN/zh-TW` 同步：引用到输入框、评论…、选中时的内容、添加评论（可选）…、保存、取消、删除引用、你的消息、助手回复、旧侧、新侧、评论：、请从行号选择同一侧的内容，以及含“选中时的内容”的完整 Fluent 标题。路径和正文保持原文，不拼翻译碎片。已有附件的来源标题冻结；普通控件文案随界面语言变化。

工具条按钮、卡片、删除按钮和弹层均有明确可访问名称和焦点状态；卡片名称为“引用：{来源短标题}”，有评论时追加“，含评论”；删除名称包含对应来源，不只读“×”。预览按视觉顺序可达，Escape 关闭最上层浮面并恢复焦点；不新增引用快捷键。沿用 Kit Button/Popover/滚动组件及主题的 foreground、muted、border、popover、radius、focus token，使用相对间距，不写死颜色，不加成功 toast。原生选择可访问性仍受来源组件公开能力限制，不宣称新增完整屏幕阅读器选区支持。
